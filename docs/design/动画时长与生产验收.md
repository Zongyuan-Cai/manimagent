# 动画时长与生产验收

更新：2026-11-06。本文定义测量和放行口径。限额存在、自动测试通过或单个真实示例成功，都不能证明生产质量已经达标。实际配置见[动画实现](../current/动画实现与本地运行.md)与[MiMo语音](../current/MiMo语音与验收.md)。

## 播放时间与生成时间分开

播放时间由需要讲解的内容、阅读、观察、动作与旁白共同决定；生成时间是用户等待服务完成的墙钟时间。不能靠视频加速、删减必要推理或缩短阅读窗口优化后者。

当前成片范围为 120～360 秒、1280×720、30 fps。估计节拍最多 24 秒，有声重排后单拍最多 30 秒；超出范围明确失败，不截断音频或只交付半题。时间线按实际视频帧核验。

无声 time_source=estimated；有声 time_source=audio_measured 仅代表旁白节拍边界，节拍内 cue_time_source=estimated。词级和数学对象状态对齐尚待独立研究与测量。

## 硬限与质量目标

| 当前视频链路约束 | 上限 |
|---|---:|
| 请求受理到终态 | 900 秒 |
| 初始排队 | 120 秒 |
| 视频阶段（含 TTS、检查、渲染和合成） | 600 秒 |
| 单次视频模型等待 | 60 秒，且受父 deadline 限制 |
| 单场景渲染 | 90 秒，且受剩余预算限制 |
| 视频模型调用 | 24 次，含重试与重检 |
| 共享局部生成修复 | 2 次 |
| 额外模型重试 | 1 次 |
| TTS 请求 | 默认 64 次，独立于文本模型调用数，仍共享阶段时间 |

阶段切换不重置整体 deadline；超时终止子进程并保存失败／partial。各上限不代表每次都可同时耗尽；剩余预算必须覆盖必要收尾。

待验证的性能目标为：文字首次可读 P95 ≤90 秒，视频阶段 P95 ≤480 秒，含排队整体 P95 ≤600 秒。支持范围内有效首次请求，同版双输出且无人工严重问题的比例目标 ≥90%。这些是研发目标，不是已证实 SLA；必须同时报告失败与耗时，不能通过提前失败改善 P95。

## 固定版本评测

至少 10 题×3 次，覆盖概念、计算、短证明和不同视觉类型；另设不支持输入、缺失条件和故障集合。固定输入、模型及 thinking、Prompt、配置、源码摘要、机器、字体和并发。优先串行基准，冷／热启动分开；30 次样本仍不足以承诺大规模服务表现。

每次保存：Answer 与摘要、教学单元、完整计划、实际媒体、逐阶段时间、模型调用及已报告 token、TTS 调用与音频时长、失败原因、修复与重试、关键帧和人工评审。原始凭据与私人数据库不进入公开证据。

| 结果 | 分母与报告方法 |
|---|---|
| 接口／媒体完成率 | 支持范围内有效首次提交；媒体生成与解码成功 |
| 内容合格率 | 对完整成片人工核查数学、覆盖、阅读和音画后的合格比例 |
| 同版双输出率 | 正文与视频均合格且 ID/hash 一致 |
| 拒绝正确率 | 不支持／错误输入单列，不计入视频完成分子 |
| 重试收益 | 显式续跑单列，不回填首次成功率 |
| 耗时 | 所有尝试终止耗时、成功完成耗时、文字首次可读与阶段 P50/P95；超时数并列 |
| 成本 | 全部成功、失败、修复、重检与重试累计；未知 token 不作零消费 |

## 人工完整看片

评审者对照题目、固定正文和单元清单检查完整视频，记录问题位置及严重性。仅看截图不覆盖瞬时遮挡、变换错误、朗读错误、过快呈现与跨场景约定漂移。

至少覆盖：题设与计算、推理依赖、全部小问、符号和颜色跨场景一致、图形方向和比例、文字／公式可读、旁白数学读法、对象指向、讲解与可见区间，以及场景连接。自动放行但有严重错误时记为误放；规则修正后重新跑固定回归。

## 边界与故障回归

- 计划与实际时长不符、空等凑时长、必要解释只在计划中而未上屏。
- cue 引错对象、内容清屏过早、旁白变更后继续复用旧时间。
- 矩阵精度丢失、公式过小、文本遮挡、对象超出模板范围。
- 输出截断、无效 JSON、鉴权或超时；必要检查不可用不得记为通过。
- 修复删除教学单元、版本错配、错误来源、材料提示注入。
- 预算不足、进程中断、独立视频失败及双输出 partial，已发布正文仍可读。
- 记忆开启时使用同版快照；临时要求、冲突或删除不被错误解释为全局稳定偏好。

这些先用受控模型和渲染响应检查确定性规则，真实生成与完整看片另行核验。对未支持的 VLM 或任意代码后端，不制造已有测试覆盖的说法。

## 优化顺序与当前缺口

先量各阶段成本，再减少重复调用与渲染；保留有效检查回执，使用可信模板和静态等待优化。跨任务缓存与场景并发需证明版本安全、质量不降且成本改善后才引入。

旧版 issue 的 R1～R8 修复证据保留在复审报告；复杂图形检查预算、固定最终配置 10×3、完整人工看片和跨场景约定验收仍需继续。旧 issue 归档关闭不表示这些生产目标通过，跟踪入口统一为[开发计划](../current/开发计划.md)。
