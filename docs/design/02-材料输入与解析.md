# 材料输入与解析设计

更新：2026-11-06。本文维护输入可靠性与来源约束；支持格式、限额和操作见[运行与配置](../current/运行与配置.md)，公共结构以 `schemas.py` 和 `/openapi.json` 为准。

## 原件与解释结果分开

上传原件作为 FileAsset 保存，拥有不透明 ID、文件名、大小和摘要；解析得到独立 MaterialIR。相同文件名不共享物理路径，后续回答引用材料 ID 而不是宿主路径。重新解析不改写旧材料或已发布答案。

MaterialBlock 保存正文、类型、来源位置和核对状态。来源位置可核验不代表内容正确；模型只能引用当前实际提供的材料块，不能自行编造可信页码或来源编号。

当前读取范围包含文本／代码／日志、结构化数据、笔记本源码与文字输出、PDF、DOCX、XLSX 和 PPTX；截图、扫描页及可提取的嵌入图片使用显式配置的视觉模型。PDF／PPTX 可先限定页码，再提供该范围的完整材料。解析器不会执行源代码、笔记本、宏或电子表格公式。详细格式和未覆盖对象统一列在当前运行文档。

## 发布与失败边界

1. 校验上传大小、文件类型、原件摘要与请求范围。
2. 在可终止子进程中解析，限制页数、展开大小、条目数、字符数和时间。
3. 对需要视觉读取的内容，在解析子进程中生成有界静态图像；主进程通过 `material_reader` 发送图片、接收转录及不确定性报告，继续使用共同预算。
4. 保存来源信息，识别缺失或不可靠内容。模型明确报告不确定或发现未覆盖结构时要求核对；其余视觉识读也保持 `unverified` 来源和警告，不宣称已人工确认。
5. 只有满足当前读取契约的结果才进入文字生成；需要用户核对或补充时返回明确状态，不把上传成功等同内容正确。

拒绝超预算材料时保留可解释原因，不能截取开头并声称已读取全文。空文本、损坏／加密文档与缺少必要条件分别处理。DOCX 检测需覆盖直接格式、样式继承和文档默认格式，不能把 `x²` 无警告地变成 `x2`。

视觉读取按文件位置记录图片／页码，限制单图像素、发送尺寸和每任务图片数量。正常文字 PDF 不必调用视觉模型；包含图形或无法核对文字映射的页面转为图像。PPTX 的图片提取不等同完整理解形状连线或版面，遇到无法覆盖的图形应要求导出 PDF／截图。XLSX 保留公式和文件内已有结果缓存，不自行计算或假定缺失结果。

材料正文始终是数据，不取得系统指令权限。它也不自动成为用户记忆来源；记忆生成只处理用户明确填写的表达。

## 上下文交接

当前使用完整材料策略。`ContextAssembler` 取得所选材料及文件元数据，构建合法来源集合；明确标记为待核对或带未支持图像资产的材料不得进入回答生成。视觉模型返回的可用转录可以作为未人工核验的材料进入上下文，并保留警告。回答与检查按各自模型配置检查上下文预算，发送前不足则提示缩小范围或拆分问题。

Markdown 正文中的引用是否合法与内容是否被来源支持是两层检查：程序核验 ID 和归属，内容检查器核对语义。任何一层都不能单独证明数学正确。

## 后续扩展及准入条件

| 扩展 | 接入前需要补齐 |
|---|---|
| 视觉读取质量与复杂公式扩展 | 现有视觉转录的独立正确性评测、原图对照与更细的人工订正路径 |
| PPTX 特殊图形／XLSX 图表和重算 | 在已有文字／表格提取之外保留图形关系、计算语义和完整性，提供格式专属回归 |
| 音视频输入 | 转录与时间定位、完整性与资源限额、格式专属回归 |
| 提供商原生文件输入 | 可访问范围、文件生命周期、实际读取与来源证据 |
| 检索或按块选择 | 选择及遗漏记录、题设与定义依赖补齐、拒绝不完整上下文 |
| 模型工具读取 | 有界读取权限、次数和 deadline；未读取内容不可引用 |

支持某种扩展名不表示支持该格式中的所有对象，也不表示拥有 Codex 的任意工具或应用控制能力。相关工程取舍与固定上游版本见[文件输入调研](../research/开源Agent文件上传与LLM输入调研.md)。
