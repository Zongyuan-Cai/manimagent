# 完整回答与版本设计

更新：2026-11-13。状态：**目标设计，尚未整体实现**。本文定义[固定教学流水线](00-固定教学流水线架构.md)中正文的来源、产物、检查与视频交接。当前 writer 输出 Markdown、来源派生和 API 行为见[能力与接口](../current/能力与接口.md)；下述结构化正文与新增请求解释阶段不能当作已经上线的能力。

## 一份教学内容，多种展示

正文是可独立交付的教学产物，不能为了分镜删减必要推理，也不能依赖 TTS 或渲染器可用才能完成。目标产物 `AnswerDocument` 以有序教学单元保存内容，页面 Markdown 从这些单元生成，不另维护一份可独立修改的摘要版答案。

每个教学单元包含稳定标识、正文内容、来源引用、所依赖单元及必要性。符号、定义、假设和结论保持一致；依赖关系必须能定位到本版内容。单元切分服务于完整性和下游引用，不以单元数量作为质量指标。

`VerifiedAnswer` 是 `AnswerDocument` 通过既定结构、来源和内容检查后形成的版本化产物。它是视频的唯一教学事实源；“通过检查”不等于形式化证明或真实数学质量已经获得完全保证。

## 固定生成路径

| 步骤 | 明确输入 | 输出与边界 |
|---|---|---|
| 任务受理 | 原始要求、材料引用、配置、记忆选项 | 冻结本次配置与已有记忆，保留原始输入 |
| 请求解释 | 本次用户表达、受支持字段与范围 | `RequestIntent` 和 `MemoryProposal[]`；不改写题设，不从材料提取用户属性 |
| 个性化编译 | RequestIntent、冻结记忆、能力定义 | `EffectiveProfile`，本阶段使用其中的 `TeachingSpec` |
| 材料准备 | 原件与选定范围 | 带完整来源定位及未决项的 `SourceBundle` |
| 正文生成 | SourceBundle、原始要求、RequestIntent、TeachingSpec | 结构化 AnswerDocument 候选 |
| 正文检查 | 原始材料、要求、完整候选和检查规则 | 检查凭据；必要项通过才形成 VerifiedAnswer |
| 发布 | VerifiedAnswer 和展示结果 | 独立文字产物；需要视频时显式交接同一版本 |

材料解析与请求解释可以独立执行；正文生成需要两边的有效输入。每个模型阶段只获得本阶段的输入对象，不接收累计聊天记录、提交队列、重试账本或完整记忆库。

当前要求在本次任务直接生效，历史记忆仅提供适用的默认。开启学习时，请求解释产生的合法候选由后台代码提交，不等待 Answer 发布，也不回填当前任务的冻结依据。读取与学习独立控制，具体规则见[用户记忆目标设计](05-长期记忆与个性化.md)。

## 完整性与检查

程序校验单元、来源和依赖引用有效且无环，必要材料与小问有可核对的覆盖关系。模型检查对照原题、当前要求和完整候选，核验计算、假设、推理、限定条件及结论。合法 ID、覆盖标记和生成器自评都不能替代语义检查。

TeachingSpec 可以指导表达顺序、解释程度和例子安排，但不得使检查器降低数学正确性、题设忠实度和必要推理要求。“简洁”不授权省略必要条件；用户自述背景也不证明其已掌握某个知识点。

完整上下文预算不足时，明确要求缩小范围或按领域结构拆分；不能通过静默检索省略原题、删必要证明或总结为另一道题来继续。输出截断、必要内容未知或检查未通过时，候选保留作诊断，不发布为 VerifiedAnswer。

局部修复包含原阶段输入、失败候选与具体错误；受同一父预算控制，产生新的候选并重做相关检查。上游材料有未决问题时应先修正材料，不让 writer 猜测缺失条件。

## 修订与视频交接

| 操作 | 目标行为 |
|---|---|
| 修改正文或教学单元 | 创建新版本并保留来源版本；重新校验依赖、引用和内容 |
| 通过 Markdown 编辑正文 | 将编辑结果显式转换为新 AnswerDocument 候选，重新建立单元关系并检查；不能只改展示副本 |
| 保持原要求的修订或视频续跑 | 继承对应任务冻结的个性化依据，不读取今天的记忆冒充历史 |
| 修改本次教学要求或偏好 | 创建明确的任务修订，重新编译 EffectiveProfile，并从受影响阶段重算 |
| 生成视频 | 只读取指定 VerifiedAnswer 的单元、符号和依赖，不重新调用 writer 解题 |
| 场景读取局部正文 | 同时提供该场景目标单元的必要依赖闭包，不能丢失前提 |
| 动画发现正文问题 | 返回原单元定位；需要改正文时建立新版本，不能只在画面里改答案 |
| 视频失败 | 已发布文字继续有效；双输出任务明确报告部分完成 |

旧视频继续指向旧正文版本，页面不得将迟到响应挂到新正文上。检查凭据绑定实际内容和检查合同；规则变化时重新验证。生成模型和参数作为来源记录，不能仅凭模型名称决定已验证正文是否可复用。

## 验收

- 页面 Markdown、视频教学单元及检查器消费同一版内容，不存在双份答案漂移。
- 必要推理、跨单元依赖和多问共享条件保持完整；截取一个场景时不会遗失前提。
- 当前要求覆盖历史默认，检查器仍保持数学与来源标准。
- 人工修订创建新版本并重检；旧视频、旧异步响应和历史记忆不会被挂接到新版本。
- 文字可以独立交付；视频或语音失败不使正文丢失。
- 请求解释与记忆提交状态分别可核对；正文失败不会抹除已合法提交的用户默认设置。

程序测试验证合同、来源、版本和状态；真实数学正确性、个性化遵循和可读性仍需固定版本的真实模型与人工评测。
