# 动画 Prompt 与检查规范

更新：2026-11-06。本文维护角色职责与回归标准。真正发送的提示词以 `answers/prompts.py`、`video/prompts.py` 和 `memory/service.py` 为准，不在文档复制另一套可漂移的完整 Prompt。

## 共享约束

- 上传材料、用户记忆与模型候选是数据，不得覆盖系统规则或检查要求。
- 题设、公式含义、推理依据、必要条件与结论保持同版；不能为适配模板改题。
- 来源、单元、场景、节拍与对象引用可定位；合法 ID 不替代语义核验。
- 参数、时长、修复次数与 deadline 由服务端决定，模型不能自行放宽。
- 返回具体可执行的错误定位；无法确认的必要项不能假装通过。

## 当前角色

| 角色 | 输入与职责 | 主要禁止行为 |
|---|---|---|
| answer_writer | 完整材料、本次要求、可选记忆快照；输出独立完整 Markdown | 用场景格式限制正文、遗漏条件、把教材当作用户画像 |
| answer_checker | 对照材料与正文核验逻辑、计算、条件和结论 | 只检查文风；接受前文错误被后文自我更正的正文 |
| video_planner | 固定 Answer、教学单元、模板能力与快照；规划完整场景及理由 | 重新解题，按字数机械决定分钟数，跳过小问 |
| scene_generator | 大纲和指定场景；输出屏幕解释、公式、图形状态、旁白与 cue | 输出 Python，伪造实测词时间，为填时长增加无关内容 |
| plan_checker | 固定正文与全部分块；逐单元核对覆盖、数学关系、图形和阅读 | 只读规划自评，以总分覆盖 fail／unknown，给 revise 却不定位场景 |
| memory_extractor | 只读当前明确表达，提出带原文证据的有界候选 | 从题目、答案、沉默或模型复述推断用户长期事实 |

记忆提取的模型连接复用回答配置，调用独立受限；其失败与必要内容检查失败的处理不同，详见[用户记忆](../current/用户记忆与个性化.md)。TTS 合成给定旁白，不参与重写答案。

## 题型重点

| 题型 | 必须核对 |
|---|---|
| 概念 | 定义、适用条件、图形含义和易混量 |
| 计算 | 方法依据、关键代入、单位、结果类型与验证 |
| 证明 | 假设、一般性、依赖链；特殊示意不代替证明 |
| 多问 | 每问目标与共享条件，后问依赖的前问结果 |
| 几何／变换 | 坐标、比例、方向、对应关系和不变量 |
| 分式／矩阵 | 分子分母读法、符号与数值区别、行列对应 |

## 自动检查与人工检查

程序负责 schema、唯一 ID、来源和覆盖、预算、模板边界、媒体解码、时间及版本一致性。计划模型检查语义，不检查实际像素；当前 `visual_model_review=not_run`。关键帧用于复核，不能证明所有变换过程或旁白读法正确。

无声视频必须能从屏幕解释独立理解。配音视频须核查正文、朗读与对象一致，实测节拍长度不证明节拍内精确同步。新增词时间或对象状态规则后须另做对应评测，不能沿用总长检查作为结论。

## 修改 Prompt 后如何验证

固定模型、配置、输入、提示词版本和源码摘要，分别记录结构通过、媒体完成、内容合格、用量和墙钟时间。先运行受控规则回归，再按受影响能力运行真实案例。成功与失败都保存，任何局部修复、重检及显式重试单列成本。

复杂图形统一检查可能在推理 token 上消耗输出预算，导致 JSON 截断。可针对已验证服务选择关闭 thinking 或调整有界输出额度；这只是配置措施，仍需固定样本验证，不能宣称所有复杂题已解决。待办与放行标准见[开发计划](../current/开发计划.md)及[生产验收](动画时长与生产验收.md)。
