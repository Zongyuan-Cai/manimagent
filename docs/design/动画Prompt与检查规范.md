# 阶段 Prompt 与检查规范

更新：2026-11-13。状态：**目标设计，尚未整体实现**。本文维护[固定教学流水线](00-固定教学流水线架构.md)的阶段职责与验收标准，不复制另一套完整 Prompt。当前实际提示词仍在 `answers/prompts.py`、`video/prompts.py`、`memory/service.py` 和 `materials/vision.py`；当前代码结构见[代码架构](../current/代码架构与迁移.md)。

## 定义、组装与传输

目标中，每个业务阶段维护自己的固定规则、明确输入与输出 schema。规则可复用必要公共不变量，但不把所有角色的职责堆进一个系统提示词。能力定义由实际执行模块维护；Prompt、schema 和代码检查使用同一版本的能力说明。

业务层把 `SourceBundle`、指定版本产物、`RequestIntent`、`EffectiveProfile` 的适用字段投影为阶段输入。模型不读取数据库、不决定记忆冲突、不接收不断增长的全局上下文字典或跨阶段聊天历史。记忆使用规则是系统规则，用户事实与偏好是数据。

调用层统一构造最终消息，对同一消息估算预算、记录并发送。初次生成和修复都遵循该过程，详见[LLM 调用设计](01-LLM接入与调用.md)。审计保留阶段、场景、候选、反馈和版本关联；运行时间戳、凭据与重试账本不作为教学输入。

## 固定阶段职责

下表描述目标逻辑阶段，不是当前运行时角色配置清单。

| 阶段 | 输入与产物 | 必须保持的边界 |
|---|---|---|
| 请求解释（新增） | 本次用户原话、支持字段、范围与能力；产出 RequestIntent 和 MemoryProposal[] | 不改写题设，不从教材、答案或历史记忆制造新的用户证据 |
| 材料读取 | 原件片段、来源定位和读取任务；提供 SourceBundle 所需信息 | 保留不确定性，不依据个人偏好改写材料 |
| 正文生成 | SourceBundle、原始要求、RequestIntent、TeachingSpec；产出 AnswerDocument | 独立完整，不为场景删条件或必要推理 |
| 正文检查 | 原题、要求与完整候选；通过后形成 VerifiedAnswer | 不降低数学标准，不仅检查文风或生成器自评 |
| 视频大纲 | VerifiedAnswer、教学参数和视频能力；产出 VideoOutline | 覆盖必要单元，不重新解题，不用字数机械决定时长 |
| 场景生成 | 场景规格、单元依赖闭包、全局符号、VisualSpec；产出 ScenePlan | 使用已支持数学图形与语义色角色，不输出 Python，不伪造实测时间 |
| 整体检查 | VerifiedAnswer、全部场景与检查凭据 | 核对覆盖、数学关系与跨场景一致性，修复必须定位场景或对象 |

目标中的记忆后台没有另一个模型提取角色：请求解释已产生有来源的候选，后台代码决定归并、计数、晋升、失效和提交。当前 `memory_extractor` 属于待替换实现，不能同时保留两条自动提取路径。TTS 合成既定旁白，不参与改写正文。

## 共享约束

- 材料、用户记忆与模型候选不能覆盖系统规则、能力限制或检查要求。
- 题设、定义、符号、推理依据、必要条件与结论保持同版；不能为适配模板改题。
- 来源、单元、场景、节拍和对象可定位；合法引用不替代语义核验。
- 同一任务使用冻结的有效偏好，各阶段只获得适用字段；当前要求优先于历史默认。
- 预算、修复次数和 deadline 由程序控制；候选缺失或超预算时不能删去必要内容继续运行。
- 图形、颜色和时间的可执行参数必须由能力合同和代码落实，不能仅靠重复提醒模型遵守。
- 必要项无法确认时报告具体位置和原因，不用总分或其他通过项抵消。

## 题型与画面重点

| 题型或问题 | 必须核对 |
|---|---|
| 概念 | 定义、适用条件、量词次序、图形含义和易混量 |
| 计算 | 方法依据、关键代入、单位、结果类型与验证 |
| 证明 | 假设、一般性和依赖链；特殊数值示意不代替证明 |
| 多问 | 每问目标、共享条件和前后问依赖 |
| 几何与函数 | 坐标、比例、方向、定义域、连续性含义、点线关系和不变量 |
| 离散数据 | 点集不得无依据连成连续函数；近似或示意的适用范围明确 |
| 分式与矩阵 | 分子分母读法、符号与数值区别、行列对应 |
| 视觉偏好 | 有效 VisualSpec、对象语义角色及实际参数一致，覆盖与未采用原因可核对 |

## 检查的保证边界

程序负责 schema、引用、依赖、可核对覆盖、参数、预算、模板几何、布局、时间、版本与媒体解码。模型检查语义；其结论不能当作形式证明，也不能替代实际像素和完整成片复核。

当前实现的 `visual_model_review=not_run` 仍如实保留，新架构没有自动增加 VLM 检查。关键帧只覆盖采样时刻，不能证明所有变换过程、旁白读法或屏幕可读时间正确。

无声视频须从屏幕内容独立理解；配音视频须核对旁白与正文、对象一致。实测音频长度不证明词级或对象状态精确同步，增加此类能力需要新的合同与评测。

## Prompt 迭代与回归

生成器经验保存在离线评测资料中，流程为“失败证据 → 修改规则、模板或校验器 → 固定案例回归 → 发布新版本”。用户记忆后台不能修改系统提示词，也不能把 renderer 失败沉淀成学生特点。

每轮固定输入、模型配置、规则/schema/能力版本与源码摘要，分别报告结构通过、媒体完成、数学内容合格、偏好实际执行、用量和耗时。成功与失败都保存，格式重试、局部修复和显式续跑单列成本。

真实回归需包含同义与相反偏好、临时覆盖、未支持要求、错误图型、配色执行、必要内容遗漏以及修复失败。不能仅因模型输出了期望字段就声称理解和执行均正确。

修改后先验证确定性合同，再按受影响能力开展真实模型、原生渲染与人工看片。输出预算不足、thinking 配置变化等措施都需固定样本验证，不能据一次成功推断复杂题已解决。优先级与放行口径见[开发计划](../current/开发计划.md)及[生产验收](动画时长与生产验收.md)。
