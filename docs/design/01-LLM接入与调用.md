# LLM 接入与调用设计

更新：2026-11-13。状态：**目标设计，尚未整体实现**。本文落实[固定教学流水线架构](00-固定教学流水线架构.md)中的模型调用边界，允许重写现有内部结构。当前配置、协议和已实现角色仍以[模型界面配置](../current/LLM界面配置.md)、[能力与接口](../current/能力与接口.md)及源码为准。

## 固定阶段调用

模型执行固定流水线中明确指定的任务，不自行选择下一阶段、发现工具或修改运行规则。每个阶段持有自己的提示词、类型化输入和输出 schema；调用层不决定教学内容，也不查询最新用户记忆。

请求解释是新增的固定前置阶段：一次生成 `RequestIntent` 和带用户原句的 `MemoryProposal[]`。代码提交已验证的解释产物后，分别推进 `EffectiveProfile` 编译和可选记忆提交；合法候选提交不以偏好编译或教学生成为前提。后台仅按候选执行状态更新，不再次调用模型提取或整理同一输入。关闭记忆读取、学习不影响本次要求的解释；结构化表单可直接产生同样的输入对象。

普通正文改为结构化 `AnswerDocument`，页面 Markdown 从同一产物生成；这是目标合同，当前 writer 仍输出 Markdown。各阶段合同见[文本回答设计](03-文本回答生成.md)和[动画设计](04-动画生成.md)，记忆生命周期见[个性化设计](05-长期记忆与个性化.md)。新增阶段名称不代表当前运行时配置已经支持同名角色。

## 一份准备好的请求

调用层先构建完整请求，再让预算、发送和审计共同消费这份请求。业务阶段只提供规则、明确输入、schema、需要的图片和阶段上限，不能另外拼一套近似提示词用于估算。

| 内容 | 责任与约束 |
|---|---|
| 阶段规则 | 对应业务阶段维护；公共不变量可复用，阶段职责不混入通用客户端 |
| 业务输入 | 来自冻结的任务要求、`EffectiveProfile` 和指定版本产物；按阶段显式投影 |
| 输出合同 | 使用版本化 schema；合同合法不等于数学内容正确 |
| 模型连接与参数 | 使用任务固定配置及显式阶段派生参数；能力在调用前检查 |
| 最终消息 | 包含实际规则、数据、schema 编码、图片和本次修复内容 |
| 预算与追踪 | 对同一最终消息计算、记录和发送；凭据不进入公开记录或内容指纹 |

使用规则放在受信任的指令层；材料、用户要求、记忆内容和失败候选作为有来源的数据传递。用户记忆不能获得修改系统规则、数学标准或输出合同的权限。

输入大小仍可采用保守估算，但方法和输出预留必须明确，不能把估算称为服务商实际 token 计数。图片等非文本输入需计入独立预算。超限在发送前报告；题设、必要证明和待修复候选不能被静默截断。

当前通用模型入口为 Chat Completions 兼容协议，目标改造不默认迁移协议。固定阶段的完整必要上下文仍随每次请求发送，不把本地差量记录当作服务端已保存的对话状态。稳定顺序有利于比较请求及前缀复用，但实际缓存收益须由服务商回报验证。

## 配置、能力与凭据

任务受理时固定配置及凭据引用；阶段派生的输出额度、上下文上限等应明确记录。缺少角色绑定、所需能力或凭据时，在调用前返回具体错误，不临时挑选另一个模型或厂商。

完整生成 URL、鉴权头、token 参数和厂商扩展必须显式配置。新增协议需独立定义消息编码、能力、错误及用量映射，不以地址推测协议，也不通过循环尝试参数掩盖不兼容。

MiMo TTS 保持独立适配器：输入是已经核对的旁白及语音参数，输出是音频和对应元数据；它不重写数学内容，不把音频字节包装成文本回答。当前操作边界见[MiMo 语音](../current/MiMo语音与验收.md)。

## 失败与有界修复

两类再次调用必须分开记录：

- 暂态网络重试：发送同一个准备好的请求，遵守允许的错误类型、次数和剩余预算。
- 内容或结构修复：保留原阶段输入、失败候选及具体错误，生成新候选版本，重新执行受影响的完整检查。

超时、鉴权、限流、输出截断、拒绝、意外工具调用、结构不合格和业务检查失败均保留明确状态。不得因返回了可解析 JSON 就发布成功，也不能省略必要检查来消除错误。工具调用不属于当前固定阶段协议；只有另行定义相应阶段合同后才能支持。

每次尝试消耗所属阶段和父任务预算，换角色、局部修复或切换适配器不能重置父 deadline。超限或不可修复时停止对应阶段。请求解释失败属于前置阶段失败；记忆事务提交失败独立报告，不把已生成的内容改判为失败，也不声称偏好已经保存。

## 调用身份与产物依赖

每次逻辑调用保存 `run / stage / call / attempt` 标识、适用场景、修复来源、实际模型配置摘要、规则/schema/能力版本及输入产物标识。已有请求正文只保存一份，图片记录必要的来源和内容指纹，密钥及鉴权头不公开。

成功提交的阶段产物绑定实际输入与检查凭据。生成模型和参数用于追溯；是否复用产物由当前内容、schema、能力和检查合同判断，不能仅因模型名称变化就认定产物失效。检查规则变化时，相应旧凭据必须重新验证。

## 验收

- 初次调用和修复调用的预算、审计与网络发送使用同一份消息；脱敏字段除外。
- 运行中修改配置或记忆，不改变已受理任务的输入；修订任务显式建立新版本。
- 超限、无能力、未绑定角色和无效参数在网络请求前被发现。
- 失败能够关联到具体阶段、候选、反馈和规则版本；有限重试保留全部尝试与用量。
- 新请求解释只产生一次语义解释，后台没有重复提取调用。
- 连接测试只证明指定请求可用，不替代各阶段的真实质量、费用和时延验收。
