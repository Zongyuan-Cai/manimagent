# LLM 接入与调用设计

更新：2026-11-06。本文维护调用层的决策与扩展边界；操作、配置字段和接口见[模型界面配置](../current/LLM界面配置.md)，当前能力见[能力与接口](../current/能力与接口.md)。

## 当前选择

当前通过 Chat Completions 兼容协议接入回答、内容检查、视频规划、场景生成和计划检查。每个角色引用服务端模型配置，业务请求不携带密钥。用户记忆提取复用回答模型连接并使用独立受限参数；MiMo 语音由专门的 TTS 适配器处理，不把语音字节包装成文本回答。

角色配置和用户界面共用 `Settings.model_id_for()`。显式绑定优先，计划检查继承内容检查，其他角色继承回答角色；没有可继承绑定时优先 `text`、其次第一个配置。配置为空时明确未配置，不能悄悄选择另一个厂商。

| 决策 | 理由与约束 |
|---|---|
| 普通回答输出 Markdown，结构化阶段输出 JSON | 正文不被场景结构限制；结构化结果按实际 schema 校验 |
| 配置在任务受理时冻结 | 队列中的任务不混用用户随后保存的新地址、模型或凭据 |
| 密钥与模型配置分开保存 | 公开接口和诊断只显示配置状态或凭据引用 |
| 允许完整生成 URL、自定义鉴权头和 token 参数 | 兼容差异显式配置，不用地址猜测协议 |
| thinking 仅在显式配置时发送 | 兼容服务未必支持该厂商扩展 |
| 所有请求继承阶段预算 | 格式重试、网络重试、检查与修复均计入用量，不能无限重试 |

## 失败与验证

调用层区分超时、网络失败、鉴权、限流、截断、拒绝、工具回合和结构不合格。调用成功不代表业务成功：正文还需内容与来源检查，计划还需覆盖和布局检查，语音还需音频验证。

结构错误重试可提供有界候选和字段错误，不能截断题设以容纳修复消息。必要检查不可用时不发布伪装通过的结果；可选记忆提取失败可带警告继续原有生成链路。

草稿连接测试不保存配置；成功只说明该请求格式与服务可用，不证明全部角色、题型或输出长度适配。当前文字与规划的真实厂商证据主要为 DeepSeek，MiMo 证据限于语音链路。真实评测入口与隔离测试职责见[代码架构](../current/代码架构与迁移.md)。

## 后续扩展

原生 Responses、Anthropic Messages、Gemini 协议，提供商原生文件上传、多模态输入、工具事件和跨厂商自动故障转移尚未实现。新增时应分别定义请求编码、能力限制、错误映射、用量统计和真实验证，不把 Chat 兼容地址配置当作新协议实现。

若未来拆分连接与模型绑定，必须保留现有任务配置快照、凭据引用和修订冲突语义。没有实际复用需求时不新增通用协议框架。

文件与模型输入的上游比较集中见[文件输入调研](../research/开源Agent文件上传与LLM输入调研.md)。
