# 分层用户记忆：生成、迁移与清理

更新：2026-11-06。本文定义用户记忆的设计与实现边界；操作和 HTTP 契约见[用户记忆与个性化](../current/用户记忆与个性化.md)。代码、测试与当前 API 是已实现行为的依据，研究设想见[研究方案](../research/个性化记忆与投稿研究方案.md)。

## 范围

本项目维护一套用户记忆。用户画像、视觉偏好、讲解偏好、知识背景等是条目的字段；短期与深层表示信息的稳定程度。核心是从交互生成什么记忆、何时跨层迁移、如何清理失效信息。首版不引入生成器修复经验，不生成跨任务经验总结，也不将所有条目合并成一段画像摘要。

实现采用本机单用户 SQLite 提交状态，并提供 Markdown 记忆目录用于查看、受控编辑与逐任务审计；不新增数据库服务、向量库或训练任务。记忆可选，不是原有材料、文字、视频及 TTS 链路的前置依赖。关闭时沿用原有生成路径。

使用已有记忆与学习新偏好分别控制。任务传 `memory` 且 `learn:false` 时只读取；`learn:true` 增加持久化后台沉淀任务，结果发布后再提取写入。省略 `memory` 时均不执行，当前没有只学习但不读取的任务模式；网页学习开关依赖读取开关。手动记忆管理是明确的独立操作，不受任务开关限制。

## 可读文件与提交边界

记忆内容应能直接打开阅读，并能追踪生成、晋升、纠正、清理和注入。当前组织为一个索引、每条记忆一个 Markdown、每个任务一份注入记录。字段与稳定程度保存在每条记录的元数据中，不因文件化而增加记忆类型、生成经验或合并画像。

SQLite 继续作为唯一提交依据：条目、会话支持、来源去重、后台任务状态与写入回执在事务内协调。Markdown 是可读导出和显式修改的输入格式。只读和调试不需要模型调用；编辑只有在导入校验通过后才改变有效记忆，直接覆盖文件或索引不触发后台自动学习。

导入只允许修改取值，并核对导出时的条目版本。修改按普通纠正创建新条目、保留层级与有效期，同时提升人工修订版本，阻断旧后台提取。ID、证据、独立支持数或层级不能成为用户通过改元数据伪造的状态。过期、被替代、已删除或版本发生变化的条目均不能被旧文件覆盖。

自动导出保留通过内容摘要识别到的未导入文件编辑，重启和重新同步继续核对这些状态。服务内部操作串行并在发布前复查文件，外部编辑器不参与同一锁协议，仍存在检查与写入之间的竞争窗口；不能将此机制描述成任意并发编辑无损合并。用户应完成一次本地保存再刷新和导入，或编辑下载副本后显式提交。

数据库提交与文件写入各自报告结果，后者失败时保留前者，文件可重试生成。删除数据库记录不通过残留文件恢复，仍由来源摘要阻止旧来源重放。该选择保留事务保护，并提供可比较的文本材料，不引入任意双向文件/数据库同步。

任务审计从实际记录的请求提取记忆片段，保留角色、尝试和状态，区分冻结的候选快照与该次调用真正构造的内容。没有请求证据时显示未知或未调用，不能把预期投影伪装成实际注入；也不能将请求构造或 HTTP 成功解释为模型已遵守。

## 一条记忆的生命周期

```text
用户明确表达
  → 有原句依据的候选条目
  → 短期记忆
  → 独立会话重复支持或用户确认 → 深层记忆
  → 新证据到来：保留、当前任务覆盖、确认替换或清理
```

层级迁移作用于可核对的条目，不要求另写抽象经验。每条记忆保留字段、取值、适用范围、层级、状态、时间和支持证据。模型推测的能力、人格或学习风格不能直接成为已确认事实。

| 环节 | 首版规则 | 所防止的问题 |
|---|---|---|
| 生成 | 只从用户提供的表达提取；候选必须带原文连续片段 | 从题目、教材、模型答案推断用户属性 |
| 入短期 | 普通候选先短期保存，有效期内可跨会话读取；临时表达限定原会话 | 将“近期”误作“仅这一轮”，或将“这次”扩大为“以后都这样” |
| 迁移 | 同范围、字段与规范化取值获得 3 个独立会话支持后晋升；非临时条目可手动确认 | 同一会话重试或反复提及造成虚假稳定性 |
| 冲突 | 当前会话的新短期要求可覆盖相应深层默认；跨会话积累或明确确认后才替换旧稳定值 | 单次例外抹除长期偏好，或旧偏好压过当前要求 |
| 纠正 | 普通修改保留层级、临时性和原到期时间；显式确认长期才进入深层 | 把改错字视作晋升，或通过编辑无限延长短期记忆 |
| 清理 | 到期短期条目、被替代条目及容量超限条目按规则处理 | 陈旧信息继续影响生成、记忆无限增长 |

默认短期有效期为 14 天，晋升需要 3 个独立会话；阈值通过 `Settings.memory_policy` 配置。非临时近期条目在有效期内跨会话可用；临时条目只用于原会话，不因重复自动晋升。开启新会话不会清除所有近期偏好。深层条目不因长期未检索而自动判错或到期。

## 生成的证据边界

自动提取只处理当前 `instruction`，不把上传材料视为用户自述；独立记忆入口只处理用户填写的 `text`。回答、旁白、系统复述、渲染成功和用户没有反对，都不构成独立支持。

提取模型沿用现有回答模型配置，以受限结构输出候选。候选的证据必须存在于本次输入中。原句核验只能证明出处存在，不能保证模型选择的字段、取值和时间范围一定正确，因此保留用户查看、确认、纠正和删除入口。

例如，“今天赶时间，讲快一点”只能支持临时节奏要求；“我以后都想先看图，再看公式”可以产生长期偏好的候选。字段和值的规范化仅处理格式差异；首版不做语义同义项归并，不声称能自动识别所有等价说法。

## 迁移与冲突

独立性按会话标识计数。同一会话内出现十次仍只有一份会话支持；同一个 `source_id` 重放不会再次累计证据。网页提供显式新会话入口，刷新或重新生成不应自动冒充独立交互。

范围是适用条件，不是额外记忆层级。全局条目可用于任意范围；指定范围的条目只进入相应范围的检索。当前会话的明确表达优先，其次比较适用范围、稳定程度与更新时间；当前请求中的明确要求始终优先于历史默认。

新候选与深层条目矛盾时，不直接全局覆盖。该候选可在当前会话优先使用；非临时近期条目在其他会话也可参与检索，但不会仅因更新较晚就压过同范围的深层默认。当新值满足独立支持条件或被用户明确确认后，旧稳定值才被替代。

普通纠正以新条目替代旧条目，并保留原层级、临时性和到期时间；旧取值的多个会话支持不移植为新取值的证据。PATCH 的 `confirm_long_term` 默认 `false`，只有显式 `true` 才将新值确认为深层并清除临时性及到期时间。非临时短期条目也可通过确认入口晋升。过期和已替代条目不再允许编辑。

首版采用确定性规则便于检查。证据可靠性学习、偏好变化点识别和可学习的迁移策略属于后续研究，不应从现有阈值规则推断这些能力已经具备。

## 清理与容量

默认最多保留 200 条记忆，每条支持证据有界；单次上下文最多 12 条、6000 字符。清理优先考虑过期短期和被替代记录，容量策略只驱逐短期信息；深层条目占满时拒绝新写入并提示用户管理，不静默驱逐已确认记忆。读取时也检查有效性，不能因为尚未手动清理而取出已过期条目。

来源去重账本默认最多 10000 个来源，只保存标识和内容摘要；达到容量后拒绝新来源写入，已有记忆仍可读取和管理。删除条目后保留来源摘要，避免重放同一输入使被删条目复活。该账本不保存额外原文，但也不属于可无限增长的日志。

清理需要区分信息失效与暂时没有用途。深层信息长期未用不等于错误，低检索频次不能单独证明应删除。用户主动删除和纠正有独立入口，不要求等待自动清理。

自动维护在启动时、写入时及后台约每 60 秒运行，网页也可手动清理。沉淀队列最多 100 个未完成任务，最多保留 200 个终态摘要。完成、取消、跳过及重试耗尽时清除队列原文；仍可重试的失败任务保留必要输入并受终态历史上限约束，不承诺按天过期。清理队列原文不等于清除既有主任务记录中的表达。

删除针对当前 SQLite 记忆库中的条目和附属证据。已经发布的 Answer、视频、任务诊断及其中冻结的历史快照不会自动改写或抹除。因此，本功能不是覆盖全部历史产物的数据擦除接口；导出、分享和备份这些历史产物时仍需注意其中可能包含旧快照。

## 接入生成流程

```text
本次 instruction + 可选 memory 参数
  → 受理时选择已存有效条目并冻结快照
  → 按角色生成稳定的模型输入投影
  → 当前 instruction 直接生效，生成并检查完整 Answer
  → Answer 保存同一快照
  → 动画规划读取 Answer 快照
  → 分镜、旁白、TTS、可信模板渲染

learn=true 的独立后台分支
  → 受理时登记 waiting
  → 父任务终态且已发布 Answer（包括 partial）
  → queued → 后台提取与原子写入 → 后续任务可读取
```

冻结时点是任务受理时，早于排队和后台沉淀。当前表达不先通过提取再成为本次上下文；它作为 `instruction` 直接生效，并优先于已有记忆。后台学习只改变后续任务的记忆库，不回填当前 Answer；人工正文修订继承原快照，后续单独视频与续跑也使用对应 Answer 的快照。

上下文是有长度预算的 JSON 数据，不能获得系统指令权限。文字阶段可据此调整解释深度和表达，视频阶段只在固定 Answer 的内容边界内调整教学规划。当前可信模板仍规定字体、布局与配色，不能承诺任意视觉偏好必然执行。

没有完整 Answer 的父任务取消沉淀。队列容量不足或登记失败保留主生成流程并给出提示；后台提取失败在独立任务状态中呈现，不将已完成结果改判失败。模型输出内容的正确性与记忆管理状态的正确性分别验证。

## 后台任务、恢复与写入边界

SQLite 队列保存 `waiting/queued/running/completed/failed/skipped/cancelled` 状态。单个后台 worker 领取前检查前台队列，优先让出前台任务；后台提取独立记账，默认每次最多 1 次调用、20 秒和 16000 token。`memory_learning_timeout` 不超过 20 秒，`memory_learning_max_tokens` 配置独立 token 预算；不做自动 provider 重试，失败仅允许手动重试，总尝试最多 3 次。已开始的后台请求不占据前台 worker，也不扣正文预算。

提交快照记录人工修改版本。提取完成后，写入事务再次检查该版本与任务取消状态；人工确认、纠正或删除不能被迟到的旧结果覆盖。取消和写入相互竞争时以事务结果为准，已提交的任务返回完成，不虚报撤回；对应的来源去重、效果记录和条目写入原子完成。

重启将 `waiting` 与父任务及 Answer 对账；`queued` 继续等待领取。`running` 若未原子提交则失败，需人工决定是否重试；若已提交则幂等恢复为完成，避免重复模型调用或重复证据。中断调用无法确认完整用量时保留未知标志。

GET `/memory` 返回条目、策略及 `learning` 状态汇总；单任务可读取 `/memory/learning/{job_id}`，重试和取消分别 POST `/retry`、`/cancel`。摘要返回服务端判定的 `can_retry/can_cancel`，避免前端仅凭状态臆断操作资格。后台 `usage` 按 `attempt_history` 累加，和主生成 `usage` 分开；缺少完整回报时使用 `usage_unknown`，不以零代替。

界面观察后台状态有次数和失败上限，不使前台等待沉淀结束；有活跃任务时更新任务列表，打开的条目编辑器保留输入。人工操作后只刷新当前记忆库，不覆盖已生成 Answer 展示的历史快照。

## 审计快照与稳定输入

完整 `memory_snapshot` 继续保留策略、会话、捕获时间、记忆 ID、层级和更新时间，用于解释及追溯历史结果。模型不直接接收整个审计对象，而是读取 `user_memory.deep` 与 `recent_user_memory`：两者仅保留字段、取值和范围，近期条目另保留 `temporary`。投影不重新解决冲突、不截断出另一个赢家、不生成摘要或做语义合并；它在已有快照选择之后按固定顺序输出。

投影按角色保守过滤：回答与内容检查不接收已知 `visual.*` 偏好，视频保留；未知自定义字段保留，视觉材料读取和记忆提取不注入历史偏好。界面展示完整回答快照，不能将其等同于每个阶段最终收到的全部提示词，也不能将“已传入”当作模型已遵守。

系统规则／schema 固定在前，用户数据的段落顺序为“深层 → 共享材料、固定正文或全局大纲 → 近期 → 本次 instruction、指定 scene 与修复反馈”。重点保留同角色、同 Answer 的场景共同前缀。仅在稳定段内部采用确定顺序，不做全局 JSON 键排序，以免把动态反馈移动到共享上下文之前。来源 ID 与引用校验继续保留，因此本轮不保证重新上传同内容后的跨任务复用。

服务商缓存统计独立于现有检查结果复用和场景续跑。`cached_input_tokens:null` 表示尚无有效回报，合法的 `0` 表示已知零命中；`cache_reported_calls` 表示回报覆盖次数，`cache_accounted_input_tokens` 仅累加这些调用的完整输入 token。比例使用后者作分母，部分回报必须注明覆盖范围，不能把未报告调用当作未命中。原输入预算仍包含缓存 token。

同字段冲突先于投影解决；临时要求替代深层默认时，前置深层段可能变化。本轮没有为缓存单独保留一份被覆盖的默认视图。容量筛选先确定字段赢家，再按稳定的语义优先级与字段顺序选取；增加同值支持证据不会无谓挤走其他字段。

测试可证明投影和共同前缀的稳定性，不能据此证明服务商缓存命中、成本或延迟收益。[本轮真实 MiMo 合成对照](../../testresult/memory-cache-20261106/cache-run/报告.md)保留全部 6 次尝试：仅 1 次报告有效缓存统计，其余未知，不据此承诺性能改善。

## 验收与后续

程序验收覆盖：原句准入、幂等重放、独立会话计数、临时信息不晋升、冲突替换、范围隔离、过期过滤、容量、重启持久化、并发一致性、用户纠正／删除，以及 Answer 与视频快照一致。既有证据见[记忆验收报告](../../testresult/memory-20261106/报告.md)；稳定投影、跨场景共同前缀与未知／零／部分缓存回报见[记忆与缓存修复报告](../../testresult/memory-cache-20261106/报告.md)。当前后台沉淀、独立预算、发布后激活、取消／人工修改竞争、重启恢复及页面状态的验收见[记忆沉淀报告](../../testresult/memory-consolidation-20261106/报告.md)。

可读文件的验收另检查自动同步不覆盖外部编辑、导入版本检查和完整回滚、旧文件不能恢复已删除条目、导出失败不伪装数据库失败，以及实际请求审计不泄漏无关材料或凭据。对应结果见[文件与审计验收](../../testresult/memory-files-20261106/报告.md)，不使用上一轮通过数字替代本轮验证。

受控流程验收使用固定模型响应检验接口和状态；真实模型验收另行测量提取错误及个性化要求是否被实际遵守。前者不能替代后者，也不能据此声称提高了真人学习效果。

下一阶段优先补足真实交互样例和可复现失败，再决定是否需要语义匹配、变化识别或学习型策略。两层结构足以启动，不以增加层数或字段数作为进展指标。
