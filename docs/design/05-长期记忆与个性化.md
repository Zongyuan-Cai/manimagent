# 用户记忆与个性化：设计与实现边界

更新：2026-11-13。状态：**核心记忆链路已实现，完整设计仍有待完成项**。一次请求解释、类型化偏好编译、独立读写、确定性后台提交、来源撤回及防复活围栏已经落地；使用方式与当前限制见[用户记忆说明](../current/用户记忆与个性化.md)。固定 pipeline、阶段输入及 EffectiveProfile 的总体合同见[架构设计](00-固定教学流水线架构.md)。

本页保留完整语义合同，不将全部设计视作已验收。当前 scope 仅校验格式及所选祖先关系，尚无课程目录；管理 API 尚无调用者提供的期望版本参数；生成表单尚无完整 RequestIntent 直传路径；旧数据目前统一导出隔离，尚无确定映射导入器。真实模型语义、实际表达遵循及完整成片评测尚未重跑，历史第 13 轮停止状态保持不变。

## 职责与范围

用户记忆保存跨任务可复用的明确解释/视觉偏好和用户自述背景。模型理解用户表达，程序决定哪些候选有效、如何归并、何时成为默认、如何执行和撤回。

本版不保存自动推断的掌握度、人格、能力或永久学习风格；不建立教学历史总摘要、生成器经验库或向量检索。用户说“我是大一”只能成为带观察日期的自述。系统提供了极限讲解、渲染成功或用户没有反对，都不证明用户已掌握极限。生成器失败经验通过离线评测改进提示词、模板和校验器，不进入用户库，也不允许后台记忆修改发布的系统规则。

三个对象严格区分：

| 对象 | 含义 | 消费方式 |
|---|---|---|
| 原句观察 | 谁在什么会话和范围中表达了什么、意图是什么 | 归并和状态更新的证据 |
| 有效记忆 | 受控字段、类型化取值、范围、状态和时效 | 后续受理任务的默认候选 |
| EffectiveProfile | 当前要求与受理时记忆编译后的参数 | 当前固定 pipeline 的明确输入 |

原句不再兼任记忆身份；EffectiveProfile 不回写为新的证据。

## 规范字段与原句证据

领域字段定义包含：字段名、类型、合法取值、适用范围、消费阶段、执行方式和时效策略。字段及值由实际产品能力限定；新增字段要同时补齐解释、编译、执行和验收合同。

当前字段合同由 `src/manimagent/personalization.py` 的 `FIELD_VALUES` 定义：

| 字段 | 当前规范取值 |
|---|---|
| `explanation.order` | `intuition_then_proof`、`proof_then_examples` |
| `explanation.detail` | `concise`、`detailed` |
| `explanation.examples` | `few`、`many` |
| `visual.palette` | `standard`、`blue_gold`、`high_contrast` |
| `visual.font_size` | `standard`、`large` |
| `visual.motion` | `standard`、`minimal` |
| `profile.background` | `first_year`、`second_year`、`third_year`、`fourth_year`、`graduate` |

解释字段不能减少必要推理；视觉字段必须进入渲染器支持的真实参数。背景自述标记 `self_reported`、保留受理日期，当前固定 365 天有效；重复不会自动晋升，明确确认也不取消其时效。字段类型与范围合同扩展后仍需补齐执行和验收。

规范化示例：“先讲直观，再证明”和“先理解直觉，再看严格推导”可以映射到同一个 `explanation.order=intuition_then_proof`。两条原句仍独立留证，不能为了匹配改写原句。

请求解释阶段产出的 `MemoryProposal` 至少包含：

| 字段 | 用途 |
|---|---|
| `field / value` | 来自领域合同的规范身份 |
| `scope` | 有效的 global、course 或 topic 标识 |
| `intent` | 普通观察、设为默认、纠正、忘记、明确恢复等受控意图 |
| `quote` 与服务端来源绑定 | 模型返回本次用户原文连续片段；source ID、session ID 和受理日期由程序绑定 |

source ID、session ID、受理序号、观察时间和并发围栏由程序绑定，不能由模型伪造。范围由用户选择或明确表达并通过目录/标识校验，模型不能凭空发明课程或扩大适用范围。

提取只读用户本次表达与允许的字段/能力，不读教材、答案、检查报告或旧记忆作为新证据。未知字段、非法取值、无原句依据或关键歧义必须明确报告。超出合同的表达可以保留为本次原始要求，但不声称已成为可执行的跨任务记忆；若它是本次必要硬要求且无法执行，则进入 needs_input。

模型的语义归类和意图识别仍可能出错。程序校验只能保证字段、原句、范围、提交和计数规则，不能证明同义判断正确；同义、反义、条件变化和引用人物需要真实语义评测。

## 当前要求与持久记忆分开

“这道题直接证明”“这次快一点”只进入 `RequestIntent` 和本次 EffectiveProfile，不写跨任务偏好库，不占近期容量，不参与支持计数。

“今天”“这一段学习会话”不能无声缩小为仅一个任务或扩大为永久默认。单任务产品应明确可执行期限；确需跨任务会话要求时，另行定义有结束条件的 session override，再接入相同编译合同。该扩展不属于本版已承诺能力。

读和学是独立控制：

| 读取已有记忆 | 学习新偏好 | 行为 |
|---|---|---|
| 关 | 关 | 本次只使用当前要求和产品默认，不提交候选 |
| 开 | 关 | 使用冻结记忆，不更新库 |
| 关 | 开 | 本次不用历史偏好；合法新候选可影响未来任务 |
| 开 | 开 | 使用旧快照，提交新候选供未来任务使用 |

关闭读取时，存储层仍可为已授权的写入取得必要版本围栏，但不能把旧偏好内容注入本次生成。结构化“设默认/纠正/忘记”是独立管理操作，可直接按合同提交，无需模型调用。

## 默认偏好的状态机

近期与稳定表示默认偏好的应用期限和稳定程度，不表示事实真实性等级。

| 事件 | 状态变化 |
|---|---|
| 普通、未限定仅本次的偏好陈述 | 新建或支持近期候选 |
| 同一规范值获得足够独立会话支持 | 晋升为稳定默认 |
| 明确“以后默认”“请记住”或 UI 确认 | 直接成为已确认默认 |
| 明确纠正已有默认 | 新值替换旧默认，以本次纠正作为依据 |
| 近期到期 | 不再参与后续编译，随后物理清理 |
| 用户忘记 | 移除有效值并建立防自动恢复标记 |
| 撤回来源 | 撤销该来源支持并重新计算相关状态 |

当前使用十四天支持窗口内三个独立会话、近期十四天作为默认产品参数；它们不是论文结论，也不适用于背景字段。背景自述按字段自身的有效期/复核策略处理，保留影响意义的时间限定。稳定偏好不因长期未被读取就自动判错。

同一 source 重放幂等；同一真实会话重复多次仍只提供一次独立支持。刷新、重试、重新生成不得自动创建新会话来凑支持。模型复述、系统读取和媒体成功均不增加支持。

明确纠正默认时，新值保持默认地位的依据是用户这次管理意图；旧值的会话支持不能复制给新值。普通近期变更与同范围稳定默认冲突时，记录新候选但不静默替换旧默认。本次明确要求仍由 RequestIntent 直接生效；跨任务替换要有明确确认或满足新支持条件。

同一个 `(scope, field)` 至多有一个有效稳定默认；不同规范值的候选保留各自证据。程序给用户请求和管理操作分配单调递增的受理序号，近期冲突、设默认、纠正、忘记和恢复都按该序号裁决，不依赖模型生成时间或后台完成顺序。较旧的默认设置即使晚完成，也不能覆盖已经生效的较新决定。

## 一次解释，两条执行支线

当前实现已取消“父任务终态且 Answer 已发布”的学习门槛：

1. 接受并持久化原始用户输入，冻结本次读取的记忆及内部提交围栏。
2. 固定请求解释同时产生 RequestIntent 与合法 MemoryProposal；表单输入可直接构造合同。
3. 提交已验证的解释产物后，分别推进本次 EffectiveProfile 编译与合法候选提交；两条支线互不以对方成功为条件。
4. 开启学习时，合法候选进入持久提交队列；后台只做代码归并和事务更新，不再次调用模型提取。生成链路使用由旧快照和当前要求编译的固定参数。
5. 新记忆只影响之后受理的任务，绝不回填本次 Answer 或当前场景。本次明确排除旧偏好通过 RequestIntent 生效，不等待数据库提交。

请求解释消耗前台预算并记录用量；后台提交仅记录处理状态与数据库结果，不虚构第二次模型用量。解释失败不能标记已学习，未提交不能显示“已经记住”。用户输入已可靠接受且候选合法后，数学、TTS 或渲染失败不否定用户原句的有效性。

解释产物可以明确报告某项生成要求不受支持，同时保留另一项合法记忆候选；后者可以独立提交。未通过原句、范围或语义确认的候选不能借此进入数据库。合法默认提交不依赖 VisualSpec 或后续产物成功。

生成与记忆保存分别报告：生成失败可以同时保存偏好成功，生成成功也可以保存失败。后台错误不得改写教学产物的质量状态。前台可获执行优先级，但记忆写入不再以媒体发布作为依赖。

取消生成和取消记忆保存是两个明确动作。取消生成不声称撤回已经提交的偏好；取消尚未提交的记忆任务必须在事务内阻止写入。若已提交，则返回实际结果并提供纠正/忘记入口。

## 编译与实际执行

先应用 RequestIntent 中明确的本轮记忆排除/重置，再按固定优先级编译：当前明确值 → 主题默认 → 课程默认 → 全局默认 → 产品默认；同范围稳定默认优先于近期候选。程序一次解决范围、时效和冲突，然后生成各阶段需要的字段。

“忘掉蓝金配色并生成视频”同时产生本轮排除和持久忘记候选；当前任务不能继续从冻结快照选中被明确撤销的值。“仅这次不用历史配色”只产生本轮排除，不写入忘记操作。排除作用于本轮投影，不原地改写审计快照；若持久提交失败，仍应独立报告未来默认未完成修改。

回答侧使用 TeachingSpec，视频规划使用教学参数和视频能力，渲染器直接消费 VisualSpec。材料读取不接受用户画像。数学检查标准不随偏好降低。

视觉主题通过语义颜色角色映射执行，不能仅靠 prompt 提醒模型使用某颜色。应用记录区分“请求了什么”“编译采用了什么”“实际执行了什么”；教学顺序等模型生成行为与颜色等可确定参数分别评价。无法支持的历史软偏好记录未采用原因，不能假装已经满足。

冻结候选依据与模型注入预算分开。由于字段和范围有界，按合同直接投影，不需要先选任意十二条再过滤角色，也不需要 LLM 总摘要。若未来引入派生缓存，必须绑定所有有效变化的 revision 或内容摘要，不能仅用人工修改计数。

## 存储与事务

SQLite 是唯一记忆事实源。当前存储 `schema_version=3`，记忆生命周期／快照 `policy_version=typed-user-memory-3`；编译合同另用 `personalization-2`，任务记录用 `pipeline_version=fixed-2`，这些不是同一个版本号。`revision` 记录全库有效变化，保留的 `manual_revision` 字段与它同值；`sequence` 是接受顺序，不能用 revision 或模型完成时间代替。

实际持久化包括接受记录、条目、完整观察、来源去重、自动晋升与显式决定围栏、规范值禁止自动恢复表及提交队列。显式围栏不会在 restore 后删除，旧观察不能越过 forget→restore 后重新加入支持；后台回执与条目变更原子提交。领域实体为：

| 实体 | 保存内容 |
|---|---|
| 记忆条目 | 规范字段、类型化值、scope、状态、稳定依据、有效期 |
| 支持观察 | source/session、原句、意图、观察顺序、支持哪个条目、是否撤回 |
| 提交任务 | 合法候选、状态、尝试、并发围栏、提交回执 |
| 撤销/版本信息 | 字段范围的代际、防自动恢复标记、schema/policy 与全库 revision |

同源去重、支持记录、独立会话计数、晋升/替换和回执在一个事务提交。所有有效变化更新全库 revision；字段/范围记录代际、最近显式决定的受理序号和撤销围栏。默认设置及替换也遵守该顺序，不只对删除做保护。

后台候选绑定持久化接受记录的受理序号；当前实现用字段围栏和禁止自动恢复表表达代际约束，不要求模型提供代际。提交时若状态变化，必须按当前围栏和用户受理顺序重新校验：早于后续纠正、忘记或新默认的旧结果不能覆盖较新决定；真正较晚受理的明确设置不能仅因较早请求晚提交而被误判成旧意图。禁止自动恢复的值还须符合显式恢复规则。重校验由代码完成，不重新猜测用户语义或无限重试。

每次任务保存实际使用的冻结事实和 EffectiveProfile；仅保存可变条目的 ID 不足以还原历史。后台写入采用唯一约束与回执恢复，重启不能因状态不确定重复增加支持。未提交任务只有在取消、代际和来源条件仍满足时才能重试。

条目、证据、队列和来源账本均有明确容量。过期候选和可清理诊断可按策略移除；容量不足时报告，不能静默丢弃用户确认的默认或为腾空间丢掉防重放依据。审计证据的展示上限不能破坏支持关系的真实计数。

Markdown 由数据库生成，用于查看、导出和调试。当前已移除文件导入路径，旧导入 API 明确拒绝；不运行双向自动学习。用户管理通过结构化入口提交；调用者显式携带期望版本的检查仍待实现，目前依赖当前条目状态、事务和接受顺序保证提交约束。

## 纠正、忘记与撤回来源

### 纠正默认

对明确的默认修改，先校验取值与能力，事务内建立新版本、使旧默认失效，并增加字段/范围代际。旧后台结果不能覆盖该操作。新值支持只来源于新的表达或管理确认，不继承旧值的重复次数。

### 忘记偏好

移除条目及其有效支持，留下不含原句的来源去重与必要的规范值防自动恢复标记。普通重放或旧文本换 source ID 不应恢复该值；用户明确“重新记住”或 UI 恢复可以解除限制。

被禁止保存的值仍可以作为用户当前明确要求仅用于本次执行，这不等于已经重新记住。标记按明确的字段、范围和必要取值约束，不无故禁止同字段其他合法偏好。

### 撤回来源

撤销某 source 对相关条目的支持，重新计算独立会话数和有效状态。仅靠自动支持晋升的条目，支持不足时按剩余证据和时效回到近期或失效；仍有有效明确确认的默认可保留。撤回来源不等于永久禁止以后学习整个字段。

未来没有独立总摘要，因此不会从旧摘要恢复结论；若新增派生视图，必须沿支持关系失效。现有冻结任务和已发布产物继续记录当时依据。要求立即停止在途使用时应显式取消受影响任务并创建新修订；彻底清除历史产物是另一种明示的擦除操作，不能用“忘记偏好”冒充已全量删除。

## 旧数据迁移

旧自由文本值、temporary 条目和发布后提取队列不直接等价于新模型。当前切换先取得目录独占租约，逐字导出 `memory-migration-v3.json`，然后清出旧有效条目并取消旧未完成／失败队列。持有旧服务租约或导出失败时停止迁移，保留旧数据。旧来源去重依据保留，用户需通过新入口重新确认默认；当前没有自动猜测转换或可直接导入报告的工具。

下列是完整迁移合同，其中确定映射转换及配套处理工具仍待实现：

- 可确定映射的字段/取值转换为规范值，并保留原始观察和来源；不能把模型猜测当无损迁移。
- 未知字段或无法可靠映射的内容保留可读导出并列为待处理，不注入新的有效默认。
- temporary 历史条目不自动变成跨任务近期偏好；历史运行快照保留旧语义。
- 明确人工确认可作为新稳定状态的依据，已有会话支持须保留真实来源；不能凭旧层级复制不明支持。
- 旧提取任务在切换前停止或按旧协议完成对账，不能与新类型化提交队列混写。
- 历史 Answer、视频和评测报告保持旧版本身份，不能补写不存在的新合同或执行证据。

## 验收矩阵

| 输入/事件 | 预期 |
|---|---|
| 同义表述 | 同一规范值，各自保留原句 |
| 反向或带不同条件的表述 | 不误并，不扩大 scope |
| 同源重放/同会话重复 | 不增加独立支持 |
| 本次例外 | 立即影响当前参数，不进入跨任务库 |
| 明确以后默认 | 直接建立可追溯的稳定默认 |
| 生成失败 | 合法、已授权的偏好仍可独立保存 |
| 读取关闭但学习开启 | 本次不使用历史内容，未来可以使用新偏好 |
| 记忆提交失败 | 独立报告未保存，不伪装成功 |
| 人工纠正/删除与后台竞态 | 较旧意图不能覆盖较新决定，撤销围栏阻止自动恢复 |
| 同次忘记旧偏好并生成 | 当前参数立即排除该值，持久提交独立报告 |
| 两次默认设置乱序完成 | 按受理序号保留较新决定，不按提交时间覆盖 |
| 合法默认与不支持的视频要求同次出现 | 合法候选可保存，生成明确报告不支持 |
| 删除后旧文本换 source ID | 不自动复活，明确恢复除外 |
| 撤回一个来源 | 正确重算支持，保留仍有依据的条目 |
| 蓝金主题等可执行偏好 | 检查实际渲染参数，不只检查 prompt |
| 没有学生作答证据 | 不创建掌握度结论 |

状态与事务使用确定性测试；自然语言映射、意图识别和用户实际表达遵循使用独立真实评测。旧首版实验以当时实现解释，不能将其结果当作本设计已通过验收。
