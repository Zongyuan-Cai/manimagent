# MVP 输入与验收样例

前四节用于检查[动画生成设计](../04-动画生成.md)中的 0.1.0 纯文本入口和结果规则，保留原有长度与字段限制。最后一节定义待实现的双输出主流程验收，不能将两套入口和状态混用。样例是拟使用的测试内容，目前没有实测结果。

## 当前文字链路验收

本轮代码见 `tests/test_text_pipeline.py`，验证记录见[文字链路实现与覆盖检查](../文字链路实现与覆盖检查.md)。以下为当前 `/api/v2` 的验收口径：

| 情形 | 必须满足 |
|---|---|
| 直接问题、粘贴材料、多个文件混合 | 一次提交返回文字 Generation；正文可独立阅读、下载、修订，不调用 Docker |
| 同名文件、PDF 页码、DOCX 表格 | ID 与来源不混淆，只处理指定页，段落和表格保持阅读顺序 |
| 扫描页、题图、公式对象 | 明确 needs_review，保留原件和候选记录，不发布缺失材料或答案 |
| 关键条件不足、来源非法、输出截断 | needs_input／needs_review，不发布完整 Answer |
| 上下文超限、解析超时、上游鉴权失败 | 明确错误，不截断、不伪造成功，不将凭据写到响应 |
| 修改问题或人工修改正文 | 前者复用完成材料重新回答；后者创建新 Answer，旧版继续可读 |
| 服务重启、队列满、下载 | 中断状态可查询；队列满不生成悬空任务；下载与持久化正文一致 |

## 用户输入示例（旧动画基线）

### 简短知识点

```text
请用动画解释二维向量加法，展示首尾相接和坐标相加的对应关系。
```

系统可以自行选一个标注清楚的演示例子，不要求用户先提供分镜。

### 完整题目与本次要求

```text
给定向量 a=(3,2)，b=(1,0)，求 a 在 b 方向上的投影。
请先画出两个向量，再画投影和垂线，最后说明投影系数与投影向量的区别。
```

题设和目标应保持不变。内容核对包括投影系数为 3、投影向量为 (3,0)，两者需正确区分。

### 公式与文字混合

```text
解释二维旋转矩阵 R(theta)=[[cos(theta),-sin(theta)],[sin(theta),cos(theta)]]。
用 theta=pi/2 演示单位向量 (1,0) 如何变成 (0,1)，坐标轴保持固定，展示旋转前后的向量。
```

重点检查矩阵、旋转方向、向量终点和公式标记是否一致。

## 输入规则验收

| 情形 | 输入或构造方式 | 预期行为 |
|---|---|---|
| 空输入 | 空字符串或只有空白 | 422，不创建任务 |
| 非字符串 | text 为数字、数组或对象 | 422，不创建任务 |
| 缺失或多余字段 | 无 text，或提交文件字段等未知字段 | 422，不创建任务 |
| 超长输入 | 去除首尾空白后 3001 个字符 | 422，提示长度限制，不截断 |
| 换行和符号 | 多行内容，包含向量符号和公式 | 保留内部换行与数学内容 |
| 缺少题设 | 求这个矩阵的特征值 | needs_input，提示提供矩阵 |
| 只有链接 | 仅提供一条网页链接 | needs_input，提示直接粘贴学习内容，不抓取网页 |
| 内容超出范围 | 要求生成整本教材的动画 | needs_input，提示选取一个知识点或片段 |

长度边界按 Unicode 码点测试，覆盖 1、3000 和 3001，以及中文、换行和补充字符。JSON 解析与未知字段校验应与契约一致。

## 生成回归样例

| 编号 | 固定输入文本 | 主要核对点 |
|---|---|---|
| G01 | 用动画解释 a=(2,1) 与 b=(1,2) 的向量加法，展示首尾相接和坐标相加。 | 终点为 (3,3)，图形与坐标一致 |
| G02 | 解释向量 a=(1,2) 分别乘以 2 和 -1 的几何意义，展示长度与方向变化。 | 结果为 (2,4) 与 (-1,-2) |
| G03 | 给定 a=(3,2)、b=(1,0)，演示 a 在 b 方向的投影，区分投影系数与投影向量。 | 系数为 3，向量为 (3,0) |
| G04 | 给定 a=(3,2)、b=(2,0)，演示 a 在 b 方向的投影，并说明为什么分母是 b 的长度平方。 | 系数为 1.5，向量为 (3,0) |
| G05 | 用矩阵 A=[[2,0],[0,1]] 解释平面缩放，展示两个单位基向量和向量 (1,1) 的变化。 | 向量 (1,1) 变为 (2,1) |
| G06 | 用 R=[[0,-1],[1,0]] 演示向量 (1,0) 逆时针旋转90度，坐标轴保持固定。 | 终点为 (0,1)，方向正确 |
| G07 | 用矩阵 A=[[1,1],[0,1]] 演示平面网格的错切，同时展示单位基向量的变化。 | 基向量变为 (1,0) 与 (1,1) |
| G08 | 用 A=[[2,0],[0,1]] 和 v=(1,0) 解释特征向量与特征值，展示 Av=2v。 | 向量保持同向，长度加倍 |
| G09 | 用 A=[[-2,0],[0,1]] 和 v=(1,0) 解释负特征值，展示 Av=-2v 及方向反转。 | 终点为 (-2,0)，不能误讲为始终同向 |
| G10 | 用两条直线解释方程组 x+y=3、x-y=1 的解，标出交点并代回验证。 | 交点为 (2,1)，两式均成立 |

以上字符串作为初始固定输入，开始基线实验时登记文档版本，不能临时改题后混算成功率。另留少量未用于提示词调整的完整输入，检查迁移表现。

## 运行与检查规则验收

构造语法错误、无效 LaTeX、超时、缺失字体、VLM 服务失败和无法解析的检查结果，检查对应分支，不依赖模型随机碰巧触发。

还需覆盖：早期候选合格而后续候选失败；评分很高但报告存在严重问题；预览通过但正式视频未通过；部分场景成功；队列满；服务重启后遗留任务。

预期分别验证预算计数、候选保留、状态准确、最终代码与视频绑定，以及未检查结果不能标为通过。对成功生成的完整视频进行人工观看，检查动态过程、数学内容、中文公式和场景连贯性。

记录输入版本、配置版本、最终状态、失败原因、修复次数、总耗时、调用次数和可获取的使用量。验收目标与实际结果分别记录。

## 双输出主流程验收（待实现）

统一输入、GenerationRequest、Generation 与 Job 的规则见 [总览](../index.md)。下列样例验证新的默认产品行为，不表示当前 `/api/jobs` 已接受这些请求。

| 编号 | 输入或构造方式 | 预期行为 |
|---|---|---|
| D01 | 一次提交 G03 的完整投影题及讲解要求 | 自动生成全文解答与动画，两者区分系数 3 与向量 (3,0)，只需一次主提交 |
| D02 | 完整文字已发布，阻塞视频阶段 | Job 为 running；Generation.answer_id 已可读取，Markdown 下载与网页正文一致 |
| D03 | 两种结果均完成 | Job 为 completed，result.type 为 generation，VideoResult.answer_id 与 Generation.answer_id 相同 |
| D04 | 回答可用，Docker、字体或视频模型依赖不可用 | 仍取得完整文字，整体 partial，错误关联视频阶段，video_id 不指向失败候选 |
| D05 | 回答截断或缺少关键条件 | 保留诊断候选，未发布完整 answer_id，不启动动画，不计入文字或双输出成功 |
| D06 | 视频失败后显式重试 | 新整体 Job 关联同一 Generation，复用原 answer_id，不重新调用回答模型；旧错误与耗时保留 |
| D07 | 两个客户端同时重试同一 partial 任务 | expected_job_id 原子检查，只接受一个，另一个返回 409，不重复排队或扣除调用预算 |
| D08 | 编辑答案后生成动画 | 新 answer_id 创建新 Generation；旧任务和旧视频继续对应旧正文 |
| D09 | 视频生成期间服务重启 | 若全文已发布则整体 partial、视频阶段 interrupted；全文可读且不自动重跑；其他情况按总览恢复规则处理 |
| D10 | 题目能完整回答但超出动画范围或场景预算 | 不删减文字求视频通过，保留全文并报告视频未完成，整体 partial |
| D11 | 引用已完成的 Answer 创建双输出任务 | 直接展示已有全文并生成对应动画，回答调用次数为零，不重读或重新推理材料，也不要求跳过阶段具备模型依赖 |
| D12 | 文字与视频分别成功但回答版本不同 | 不得整体 completed，不把不匹配的视频登记为本次 video_id |

分别登记 generation_id、各次 job_id、answer_id、video_id、文字首次可读与动画完成时间、阶段错误和已知用量。报告文字、动画与同版本双输出成功率，分开统计首次提交和显式重试。
