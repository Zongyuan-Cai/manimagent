# 开发计划

更新日期：2026年10月29日。本轮只整理方案、调研与验收，不修改代码、配置或历史动画项目。TTS 合成暂缓，旁白与音画契约现在就要建立；依据见[开源项目与论文调研](research/音画对齐开源项目与论文调研.md)。

## 当前阶段已经完成什么

当前 0.2.0 已实现“问题／文件 → 可追溯材料 → 完整 Markdown → 内容检查 → Answer”，包括网页阅读、下载、来源、人工修订和复用。真实文字链路测试与版本隔离证据见[测试报告](../testresult/测试报告.md)；当前接口与边界见[文字链路实现与覆盖检查](文字链路实现与覆盖检查.md)。不再把已实现的文件上传、正文保存和模型界面配置排成未来前置工作。

旧动画 0.1.0 已冻结在 [legacy_mvp](../legacy_mvp/README.md)，具备规划、Manim、执行纠错、VLM、渲染与合成的基础 Pipeline。它的短时长默认值、粗粒度采样和多轮串行开销需要重新设计，不能直接视作正式生产方案。历史结果见[MVP 验证记录](MVP验证记录.md)。

下一阶段目标是把确定版本的完整 Answer 派生为旁白与画面共享的语义计划，先接入无声预览，验证教学时长、事件契约和生产耗时；以后用真实音频边界解析同一时间线。默认双输出只在正式版接入后启用，当前文字服务继续按文字成功判定。

## 当前方案与调研修正

| 决策 | 具体约束 | 维护位置 |
|---|---|---|
| 内容先定版 | 分镜与页面使用同一 answer_id；视频不重新解题 | [总览](index.md)、[文本回答](03-文本回答生成.md) |
| 音画契约前置 | 现在形成 spoken_text、cue、对象与事件关系；当前估时不冒充实测，TTS 服务后接 | [音画对齐调研](research/音画对齐开源项目与论文调研.md) |
| 先分析教学工作量 | 受众、题型、推理依赖、新概念与阅读需要共同决定时长 | [动画 Pipeline](04-动画生成.md) |
| 正式交付 2～6 分钟 | 简短完整讲解 2～3 分钟，常规多步 3～6 分钟；过长先拆分 | 动画 Pipeline |
| 时长逐层核对 | 总计划、场景、节拍、代码执行与 MP4 实测贯通；禁止末尾凑时长 | 动画 Pipeline、[生产验收](动画时长与生产验收.md) |
| 无声也讲完整 | 方法选择、推理依据、公式含义与结论必须通过画面说明 | [Prompt 与检查](动画Prompt与检查规范.md) |
| 检查按证据分工 | 内容、规划、执行、画面、媒体；必需项未知不算通过 | Prompt 与检查 |
| 生产时间有界 | 常规视频阶段 P95 目标 ≤8 分钟，整体 ≤10 分钟；硬限分别 10／15 分钟 | 生产验收，均待实测 |
| 修复有限 | 合格即停止，优先局部修复，所有调用与重渲染累计预算 | 动画 Pipeline、生产验收 |
| 失败保留全文 | 双输出动画失败为 partial；显式重试只做视频 | 总览 |

这些是下一轮实现的起点，时长／性能数字需经过固定机器、真实模型和人工看片校准。本轮没有增加实现通过或性能测试结论。

## 下一阶段按这个顺序落地

| 阶段 | 工作 | 进入下一阶段的证据 |
|---|---|---|
| A 复盘与基线 | 固定代表性 Answer；记录旧规划时长、实际视频、调用数和分阶段耗时；不先追求更复杂画面 | 能区分短片来自规划、代码还是阅读节奏，慢在哪里有计时依据 |
| B 教学与音画规划 | 教学单元、受众分析、旁白／公式读法、cue／对象／事件关系、估计时间解析；规划检查 | 同一事件可在不同语速估计下重新排程；不混用估计与实测；漏讲、凑时长、错误指代可被拒绝 |
| C 最小动画模块 | 以 answer_id 为唯一内容入口，选择性迁移隔离渲染、日志纠错和候选绑定；先用稳定模板 | 首条真实 2～6 分钟无声视频可看懂；计划与实际时长、帧率、覆盖一致 |
| D 质量与资源闭环 | 按关键事件取证、检查交付规格；全局 deadline、调用／修复上限、超时终止与阶段计时 | 检查不可用不误放，预算不足及时停止；不靠跳过检查换速度 |
| E 双输出与版本 | 同页文字先展示，自动视频，VideoResult、partial、仅重试动画与答案修订 | 页面、API、产物版本一致；视频失败、重启、并发重试不会丢正文或错绑 |
| F 生产评测 | 支持范围内至少 10 题×3 次真实运行，另测错误输入／故障；人工完整看片 | 同时报告完成率、严重问题、时长与耗时分布、全部失败；未达标有收窄范围或优化证据 |

A～F 不要求分六个大 PR；可按可回归的增量提交。每个增量保持当前文字能力和发布包隔离。旧项目保留为独立历史基线，新功能只迁移所需能力，不混用依赖、目录和配置。

## 性能优化的实施优先级

先减少重复调用、重复渲染和无必要修订，再评估模板、静态停留、受控缓存与合成优化。常规场景优先一次交付规格渲染；只有复杂场景需要预览时才接受双重渲染成本。取得合格候选后不为美化再跑一轮。

基准先串行，记录冷／热启动、机器和峰值资源；至多两场景并发必须由实测证明改善 P95 与失败率。不要一开始同时迁移调度、上多模型、扩充三维和做视觉特效，导致无法定位时长与失败问题。

完整的 deadline 继承、阶段预算、质量门槛与指标分母由[生产验收](动画时长与生产验收.md)统一维护，不在多份配置表重复定义。

## 本阶段验收与交付

必须交付完整 Markdown、同版本合格 MP4、细粒度教学单元与时间映射、检查报告、耗时／调用记录、运行说明及固定回归样例。演示材料同时提供文字和完整视频，30 秒 smoke 或若干成功片段不能替代生产样例。

验证分三层：程序测试验证确定性规则和状态；真实模型／渲染验证质量与成本；人工完整看片核对推理、阅读与采样遗漏。历史测试数量、受控模型通过和真实文字测试不自动折算为新动画成功率。

发布判断同时看支持范围首次请求的双输出合格率、人工严重问题、文字可读时间、视频／整体 P95、超时与 partial、显式重试成本。不能只给成功视频的耗时，或把正确拒绝不支持输入算成视频完成。

## 暂不排入本阶段

真实 TTS 服务、强制对齐模型部署、字幕文件、长视频、多语言、三维复杂场景和跨任务自动缓存先不实施。旁白脚本、语义锚点、画面事件与时间解析契约现在就设计，不能把音画对齐整体后置。当前无声阶段验证语义和估计排程，真实同步误差须等音频接入后测量。局部场景修复属于当前闭环，更广泛的局部更新产品接口另行设计。

扫描件、复杂公式／图示识别、多协议和长材料读取继续按各自能力边界推进，不作为所有纯文本动画接入的共同前置。学习记忆与个性化继续[暂缓](05-长期记忆与个性化.md)。

长期目标保留原申报方向：带学习记忆的个性化视听讲解与反馈系统，以及 CCF B 类及以上国际学术会议论文投稿或中国发明专利申请。投稿／申请不等于录用／授权，不把暂缓模块变为近期依赖。
