## 已实现链路与代码

`FileAsset → MaterialIR → ContextBundle → Markdown writer → 内容 checker → Answer`。首轮主回答直接返回 Markdown 和 LaTeX，checker 返回独立 JSON 报告，不覆盖正文。

| 文件 | 职责 |
|---|---|
| `src/manimagent/schemas.py` | v2 公共契约；与旧动画 schemas 分开 |
| `content_store.py` | 生成资源 ID、原件与摘要、原子 JSON 存储、诊断资产 |
| `materials.py`、`parse_worker.py` | 本地文本／PDF／DOCX 解析、来源和覆盖、子进程超时终止 |
| `answers.py` | 全文上下文、逐调用预算、直接回答、内容检查、引用校验、版本修订 |
| `text_jobs.py` | 有界文字队列、固定配置、持久化状态、恢复中断记录、Generation 编排 |
| `text_api.py` | v2 HTTP 接口、上传接收上限 |
| `markdown_view.py`、`web/` | 安全 Markdown 展示、离线公式排版、来源、下载、复制、编辑和材料复用 |

当前角色配置沿用 `models/roles`，没有实现文档 01 中完整的 ProviderConnection／ModelBinding 控制面。只支持 Chat Completions；Responses、Messages、Gemini、原生文件上传和能力探测均不对外宣称可用。

## 可用接口与示例

| 方法与路径 | 行为 |
|---|---|
| GET `/api/v2/health` | 仅检查回答模型配置，并返回格式和主要限额；不发送模型请求 |
| POST `/api/v2/files` | 单个 multipart `file`，201 FileAsset；多文件分别上传 |
| GET `/api/v2/files/{id}`、`/{id}/content` | 元数据、下载原件或诊断；内容校验 SHA-256 |
| POST `/api/v2/materials/parse` | ParseRequest，202 Job；不需要模型 |
| GET `/api/v2/materials/{id}` | 已完成 MaterialIR |
| POST `/api/v2/answers` | AnswerRequest，202 Job；可复用完成材料 |
| GET `/api/v2/answers/{id}` | 不可变 Answer |
| GET `/api/v2/answers/{id}/markdown?download=true` | 原样正文及下载 |
| GET `/api/v2/answers/{id}/html` | 同一正文派生的安全展示；不将原始 HTML 当作页面执行 |
| POST `/api/v2/answers/revisions` | 完整替换 Markdown，201 新 Answer；保留旧版本 |
| POST `/api/v2/generations` | 一次提交，自动解析并生成完整文字，202 Job |
| GET `/api/v2/generations/{id}`、`/api/v2/jobs/{id}` | 阶段与已发布引用、状态、错误、用量、诊断 |

主请求示例（无需文件也可以提问）：

```json
{
  "output_mode": "text",
  "source": {
    "type": "inputs",
    "inputs": [{"type": "text", "text": "a=(3,2)，b=(1,0)"}],
    "instruction": "求 a 在 b 方向上的投影，并解释系数与向量的区别。"
  }
}
```

文件上传取得 `file_id` 后可追加 `{"type":"file","file_id":"file_..."}`；PDF 可加 `selection: {"kind":"pages","start":2,"end":4}`，从 1 开始、包含两端。其他格式当前不支持 selection。

复用完成材料使用 `source: {type:"materials", material_ids:[...], instruction:"新问题"}`；复用已有回答使用 `source: {type:"answer", answer_id:"answer_..."}`，后者不调用模型。三种来源互斥，拒绝额外字段。任务创建前验证引用、模型和队列；接受后错误写入 Job。默认配置 ID 为 `parser_default`、`answer_default`，可省略；尚未实现任意 profile 管理。

## 明确补齐的行为

- 材料在 user payload 内，应用规则在 system 内。链接只作为文字，不抓取 URL；不提供任意宿主文件读取或 shell 工具。
- 来源语法固定为 `[[material_id:block_id]]`。只能引用本次实际提供的块；缺失、伪造或不完整标记进入 `needs_review`。网页派生为编号链接，下载与编辑仍保留原标记。
- 首版索引使用单个完整正文步骤，`steps[0].content == markdown`，避免在公式、代码或表格中切断；不是已经实现精细的章节索引。正文没有标题时使用“文字解答”，不改正文。
- `answer_check: true` 默认开启；writer 与 checker 都得到完整材料，分别检查输入预算。checker 发现必要条件不足时 `needs_input`，关键错误或不确定时 `needs_review`；检查失败不发布 Answer。
- 人工编辑不调用模型，继承材料与原要求，重新校验来源并保存新 ID，增加“未重新内容检查”提示。修改问题需重新生成回答。
- 非空、结束原因与引用由程序检查；语义完整性依赖模型 checker，检查通过不等于形式化证明。
- `finish_reason=length`、拒答、未完成工具回合或没有可靠停止标志都不能发布完整文字。候选、逐次调用输入、结束原因和检查报告保存到诊断；上游鉴权错误体不会直接回显。
- 每次提交深拷贝模型、角色、参数和预算；凭据只保留环境变量名，发送前解析。任务记录不存密钥值。
- 服务端按所有材料聚合估算上下文，用 UTF-8 字节数加协议余量作保守 token 上界，另加输出预留；超过角色 context_window 与 answer_context_tokens 的较小值就停止，不截断或发起该次调用。可能保守拒绝部分实际可容纳材料。
- Job.usage 保留兼容旧模型的 token 汇总与 tokens_reported；缺失用量不能解释成零消耗，逐次诊断的 usage 为 null。总调用次数、时间和已报告 token 上限仍生效。
- 上传与解析失败不会删除原件；中断解析不发布 MaterialIR；失败／待检查的回答不发布 Answer。修改问题可显式复用 material_id，不做自动缓存或幂等。
- 文字任务有独立单 Worker 与有限等待槽位。只运行一个服务进程；不同 CLI／服务实例应使用不同 private_dir。重启时未完成任务 interrupted，不自动重跑；已登记完整回答的文字 Generation 可核对后完成。

## 支持范围与尚未实现的内容

| 输入 | 当前行为与边界 |
|---|---|
| 直接文本、TXT、Markdown | UTF-8，保留原件／请求与行号；拒绝无效编码、空材料、NUL 和超限 |
| PDF | pypdf 逐页提取，页码范围可对照；空文字页、扫描页、已检测绘图／图像或异常字形进入 needs_review；加密／损坏文件 needs_input |
| DOCX | python-docx 遍历正文段落与表格；段落序号、表格未知位置分别保留；检测到公式对象、图片、嵌入对象、特殊结构或页眉脚注等则 needs_review |
| 图片、PPTX、音视频、原生文件输入 | 尚未实现，明确拒绝 |

PDF 绘图检测采取保守策略：部分有装饰线条的文件也会要求核对。PDF 库不保证复杂版面、矩阵、上下标或公式语义准确；尚无 OCR、页图生成、图示提取、公式识别、人工确认候选后继续的接口。遇到这些情况需要用户上传文本版、粘贴完整条件或调整页码范围，不绕过缺失内容继续生成。

文件处理使用受控子进程限制时间；DOCX 限制条目和声明解压规模，PDF 限制页数、展开流及文字总量。当前没有操作系统级内存沙箱，不能将这些检查称为针对任意恶意文件的完全隔离。面向本地单用户，没有认证、租户隔离、跨用户共享、删除与自动清理 API，不应直接作为公网多用户服务。

实现依据参见 [pypdf 官方提取说明](https://github.com/py-pdf/pypdf/blob/main/docs/user/extract-text.md)与 [python-docx 阅读顺序接口](https://python-docx.readthedocs.io/en/latest/api/document.html#docx.document.Document.iter_inner_content)。本轮选择 pypdf 作为首版 PDF 解析器；PDFium 为后续候选，不声称已经使用。
