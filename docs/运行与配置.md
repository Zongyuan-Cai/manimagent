# MVP 运行与配置

本文对应 0.1.0 的纯文本 MVP。模型按角色配置，用户界面始终只有一个文本输入框。

## 环境与安装

宿主需要 Python 3.12、uv 和运行中的 Docker Engine。Windows 使用 Docker Desktop 的 Linux 容器模式。Manim、LaTeX、中文字体、FFmpeg 和 ffprobe 都安装在渲染镜像中，宿主无需另装这些渲染依赖。

在项目根目录执行：

```bash
uv sync --frozen --extra dev
docker build -f docker/renderer.Dockerfile -t manimagent-renderer:0.1.0 .
```

如果 uv 尚未安装，可按 [uv 官方说明](https://docs.astral.sh/uv/getting-started/installation/)安装。本地已有 .venv 时，Windows 可以直接使用 .venv/Scripts/uv.exe 和 .venv/Scripts/manimagent.exe，无需激活环境。

## 配置模型

复制 .env.example 为 .env，将文本与视觉模型各自的接口地址、模型名和密钥填入。base_url 填到服务的版本前缀，例如 https://服务地址/v1，不包含 /chat/completions。视觉模型必须支持图像输入。

PowerShell：

```powershell
Copy-Item .env.example .env
Copy-Item config.example.yaml config.yaml
```

Linux 或 macOS：

```bash
cp .env.example .env
cp config.example.yaml config.yaml
```

.env 与 config.yaml 均已忽略，不提交到 Git。修改配置后重启服务。密钥仅通过本地环境变量读取，渲染容器不会获得模型密钥。

默认 planner、plan_checker、coder、execution_repair 和 visual_reviser 使用 text；vision_checker 使用 vision。config.yaml 的 roles 可以引用 models 中另行声明的模型，以覆盖某个角色。

适配层使用兼容 Chat Completions 的 /chat/completions、消息列表、JSON 对象输出和图像 data URL。实现依据见[官方接口参考](https://developers.openai.com/api/reference/resources/chat/subresources/completions/methods/create)。并非所有兼容服务都实现相同参数：不支持 response_format 时设置 json_mode: false；需要 max_completion_tokens 时修改 token_parameter。即使关闭 JSON 模式，服务仍须返回可校验的 JSON。

若服务需要代理，在启动进程的环境中配置 HTTPS_PROXY 等标准代理变量。Docker 镜像拉取和构建的网络配置独立于模型请求；运行中的渲染容器禁网。

## 启动与生成

```bash
uv run manimagent doctor
uv run manimagent serve
```

访问 http://127.0.0.1:8000，填写纯文本并点击生成。doctor 只检查配置与 Docker 镜像可用性，不发起模型调用；它不验证密钥余额或接口权限。

Windows 当前环境也可直接执行：

```powershell
.\.venv\Scripts\manimagent.exe serve
```

命令行生成：

```bash
uv run manimagent generate --text "请用动画解释二维向量投影，使用 a=(3,2)、b=(1,0) 举例。"
```

需要其他配置文件时，把 --config 放在子命令前，例如 manimagent --config configs/local.yaml serve。runs_dir 的相对路径按配置文件目录解析。

## 无模型的渲染检查

```bash
uv run manimagent smoke
```

smoke 渲染一个手写的五秒向量投影场景，检查中文、MathTex、抽帧、正式规格和视频合成。输出中给出视频及抽帧路径。它不调用模型，也不是文本自动生成效果的演示。

## 测试

```bash
uv run ruff check src tests
uv run ruff format --check src tests
uv run pytest -q
```

默认测试使用受控模型与渲染响应，不需要密钥或 Docker。真实渲染集成测试需先构建镜像并显式启用：

```powershell
$env:MANIMAGENT_TEST_DOCKER = '1'
uv run pytest tests/test_docker_integration.py -q
```

```bash
MANIMAGENT_TEST_DOCKER=1 uv run pytest tests/test_docker_integration.py -q
```

集成测试使用受控模型响应与真实 Docker、Manim、FFmpeg，验证完整流程；不会将其结果作为真实模型质量结论。GitHub Actions 执行无需模型和 Docker 的检查与打包。

## 任务与产物

任务状态与接口遵循 [动画生成中的 MVP 基线](04-动画生成.md)。任务目录位于 runs/{job_id}/，包括原始输入、配置快照（不含密钥值）、规划、候选代码、渲染结果、检查报告和清单。只有所有正式场景与合成验证都通过，才登记 final.mp4。

needs_input 表示应补充题设；needs_review 表示有视频但检查未完成或存在问题；failed 表示没有取得可用结果。服务重启后，遗留的非终态任务标为 interrupted，不自动继续执行。

模型使用量只累加服务实际返回的 token 数据。服务不提供用量时，tokens_reported 为 false，不能把计数零解释为零消耗；调用次数与时间预算仍然生效。

本地单用户运行时只启动一个服务进程，不使用多 worker 或自动 reload。CLI 与网页不要同时操作同一个 runs_dir 的未完成任务；需要独立执行时使用不同的 runs_dir。
