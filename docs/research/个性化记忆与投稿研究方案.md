## 项目与已有工作的关系

[ManimAgent: Self-Evolving Multimodal Agents for Visual Education](https://arxiv.org/abs/2606.30296) 是项目作者本人的已有工作。早期文档将其误写为外部同名竞争工作、建议因重名另起题名，该建议撤回。后续论文应清楚说明与作者已有论文的增量，避免把已经发表的生成与修复记忆再次包装为新贡献。

作者当前选择两条独立路线：用户记忆的生成、跨层迁移和清理；数学讲解中的音画对齐。两条路线可以共用项目作为实验平台，但不要求先合成一个大型个性化学习系统，也不以大量真人数据采集为启动前提。

## 方向一：用户记忆生命周期

### 研究对象

研究对象是可跨任务复用的明确偏好与用户自述背景。稳定程度、持续时间与证据来源分别记录；普通偏好可经独立重复证据形成稳定默认，明确“以后默认／记住”可直接设为已确认默认。仅本次要求在目标架构中退出跨任务记忆库。核心仍是三个决策：什么进入记忆、何时改变适用状态、什么需要清理。

本方向不生成通用修复经验，不将历史交互持续合并为经验摘要，也不把字段划分本身作为论文贡献。当前工程首版的原句候选、独立会话计数、管理入口、过期及容量限制、固定生成快照可作为旧基线。目标的类型化字段、可执行视觉参数和记忆提交状态机需独立验证；它们本身也不是学习型策略或已证明优于已有方法的新算法。教学经历、自动掌握度、向量检索及全局自然语言记忆摘要均不属于本次工程目标。

### 需要对比的工作

| 原始工作 | 与本方向相关的已有能力 | 对研究设计的要求 |
|---|---|---|
| [MemoryOS，EMNLP 2025](https://aclanthology.org/2025.emnlp-main.1318/) | 短期、中期、长期个人记忆及动态更新 | 不能仅以增加层级或迁移流程作为新意 |
| [MemoryBank](https://arxiv.org/abs/2305.10250) | 根据时间与重要性强化、遗忘长期记忆 | 不能仅以时间衰减或遗忘曲线作为新意 |
| [Auto-Dreamer](https://arxiv.org/abs/2605.20616) | 将快速获取与跨会话离线巩固分开，学习巩固策略 | 快慢过程和巩固调度已有研究；本方向需明确用户信息状态判断的增量 |
| [Useful Memories Become Faulty When Continuously Updated by LLMs](https://arxiv.org/abs/2605.12978) | 在其评测环境中发现持续巩固可能降低记忆效用，保留原始经历具有竞争力 | 保留可核对依据，不能预设更深或更抽象一定更好 |
| [Memora](https://arxiv.org/abs/2604.20006) | 评估随用户情况变化的记忆，以及过时、无效记忆的误用 | 应使用外部评测补充自建案例，并明确清理对最终回答的影响 |
| [LongMemEval](https://arxiv.org/abs/2410.10813) | 信息抽取、多会话推理、时间推理、知识更新与拒答评测 | 不能只测静态检索命中率 |

以上是相关工作线索，尚未完成统一预算下的代码复现与完整新颖性审查。

### 候选核心假设

在相同存储和模型调用预算下，依据独立证据区分“临时要求、稳定属性、已经变化的信息”，联合控制生成、迁移和清理，可能比固定次数晋升、固定时间遗忘更少误记、更快适应真实变化。

这一假设需要实际机制和对照实验支持。可先分析同一会话重复、模型复述、自我强化、任务范围变化等错误来源，再决定是否需要概率模型、变化点判断或可学习策略；不为方法复杂度而提前添加训练和多智能体模块。

### 无需大量真人采集的首轮评测

预设隐藏的稳定偏好、临时例外、噪声、范围与变化时点，生成多会话表达；方法只看到用户表达，评分器持有独立的隐藏状态。划分应覆盖未见过的用户状态组合和表达方式，不能只更换同一模板中的词语。

| 评测环节 | 指标与对照 |
|---|---|
| 生成 | 错误写入率、遗漏率、原句依据正确性；检查题目内容是否被误认为用户事实 |
| 迁移 | 临时信息误晋升率、稳定信息识别率；固定同一来源重复十次与十个独立会话分别比较 |
| 更新与清理 | 用户变化后的修正延迟、过时记忆使用率、误删仍有效记忆的比例 |
| 下游生成 | 当前要求和有效偏好遵守率、数学内容正确性、实际成本；文字与视频分别评估 |
| 资源 | 活动条目、存储、上下文长度、全部提取及管理调用量；清理成本也计入 |

至少比较：无记忆、短期窗口、平坦记忆、频次晋升与时间清理、完整方法；逐项移除证据去重、迁移与清理。相同模型、上下文和调用预算下比较，所有失败保留。可用 Memora、LongMemEval 检验外部适用性，受控模拟只能支持记忆管理和个性化生成的结论，不能证明真人学习收益。

### 模拟真人的可执行评测设计

以下为待冻结并运行的 12 人物／144 输入协议。此前已经执行单个合成学生的 13 轮探索并修改生产提示词；该探索有题目、配置和提示词的同时变化，不是本协议的受控研究结果。`tests/support/memory.py` 主要以受控模型响应验证旧工程规则；`evals.narrated --memory-note` 在生成前提取并人工确认种子记忆，可验证使用链路，但不能单独证明自然跨会话晋升能力。

把模拟、被测系统、判定、优化分成四种职责。可以由同一助手组织执行，但模拟器与优化器应使用分离的上下文；结果判定优先采用独立预设真值与程序检查，语义判定再用盲评和人工抽查。

| 角色 | 可见信息 | 产物与限制 |
|---|---|---|
| 用户模拟器 | 隐藏人物设定、当轮事件、本人与产品的可见交互 | 自然用户表达；看不到数据库、预期标签、候选 prompt 或内部错误分析 |
| 被测 Agent | 本轮公开输入、正常提供的材料及自身记忆快照 | 正常完成生成与沉淀；看不到人物卡、未来事件或标准答案 |
| 判定器 | 冻结的事件真值、已公开证据、实际轨迹 | 分层错误与证据；不能要求系统记住用户从未透露的信息 |
| Prompt 优化器 | 训练轨迹的错误、相关 prompt 和允许修改范围 | 小幅候选修改；不得读取最终测试集、改标准答案或放宽程序契约 |

每个人物都有稳定偏好、临时例外、领域范围、表达风格及预设变化时点。稳定事实是否已经向系统透露单独记录，隐藏人物信息不自动成为应写入的记忆。表层语言包含口语、改写、否定、引文、题目中的虚构人物、含糊表达和无偏好轮次。

首轮可用 12 个人物 × 4 个会话 × 3 轮输入，共 144 条固定输入，按人物和场景家族划分为 6/3/3 个训练、验证、测试人物；这是诊断规模，不用于宣称统计上的普遍收益。先冻结事件与表达再比较候选 prompt。另设少量自适应交互，让模拟器根据可见回答自然追问，用于发现新失败；发现的样例进入下一版训练集，不能回流当前最终测试集。

| 轨迹片段 | 模拟表达／行为 | 应检查的结果 |
|---|---|---|
| 会话 1 | “我通常希望每一步先说清为什么。” | 提取有原句证据的近期偏好；目标版本校验规范字段／取值 |
| 同一会话再表达 | 同义改写或重复同一请求 | 不增加独立会话支持；来源重放幂等 |
| 会话 2、3 | 再次明确同一稳定偏好 | 相同偏好累计不同会话后按阈值形成稳定默认；分别报告旧精确匹配的碎片化与新规范值误归并 |
| 临时例外 | “只有这道题先给结论，平时仍讲过程。” | 当前要求立即优先；旧基线检查 temporary 不晋升，新目标检查本题例外不进入跨任务库 |
| 干扰轮次 | “题目中的小王喜欢红色。”／纯数学题 | 不把引文、虚构人物或题目内容写成用户事实 |
| 跨会话探针 | 只给新题，不重述任何偏好 | 核对记忆确实被选入、出现在实际请求中，并改变允许调整的回答行为 |
| 明确改变偏好 | 用户声明新的长期默认，或通过管理操作纠正／确认 | 当前要求立即优先；目标版本明确设默认直接生效，普通观察仍按证据策略处理；旧基线单独评分 |
| 删除／过期／只读 | 删除条目、推进测试时钟、关闭学习或禁用记忆 | 后续快照遵守新状态，既有 Answer 快照保持不变；未开学习时不产生新沉淀 |

实际驱动规则按被测合同绑定版本：

- 每个人物使用独立 `private_dir`／SQLite；当前产品是单用户，`session_id` 区分会话，不能隔离不同用户。一个会话内保持同一 ID，不能每一轮换 ID 凑晋升。
- 确认、纠正和删除通过真实记忆管理接口模拟用户操作；自然语言“忘掉这个”在旧实现中不保证触发删除。新版本只按实际实现的管理意图合同验收，不能预先算作已有能力。
- 旧基线本次要求放在生成请求的 `source.instruction`，目标版本由固定请求解释阶段生成当前要求及候选。两者只将用户原始表达作为个人信息证据；材料中的人物、模型答案和修复日志均作为污染负例。
- 旧基线正常顺序轨迹等待父任务终态及学习任务结果；目标版本独立等待记忆提交结果，不要求教学产物成功。另设并发轨迹，明确下一任务在提交前／后应读哪个版本，不能用任意 sleep 猜状态。
- 每轮保存输入、模型提取候选、数据库前后状态、冻结快照、真实请求中的角色投影、回答及独立学习用量。HTTP 成功、学习 completed、条目存在、请求已注入、回答遵守分别检查。
- Prompt 对比从相同空库或固定基线库重放整个人物轨迹；不让候选 B 继承候选 A 的学习结果。为最终候选重复独立运行，记录所有失败与实际调用数。
- 时间过期用可注入时钟的存储测试验证，不修改主机时间。旧 `memory/observe` 入口可隔离测试旧提取器；目标版本需分别验收固定请求解释和确定性提交。两者都不能以内部接口成功替代正常用户路径。

目标版本还需增加读关闭但学开启、生成失败但偏好保存成功、本次视觉参数实际执行、删除后迟到候选不能恢复，以及无需读取历史记忆也能立即执行当前要求的案例。这些是目标验收项，不回填旧 13 轮结果。

### 指标与失败归因

先区分三层：提取是否正确，记忆状态是否正确，回答是否正确使用。候选的引文逐字存在只是证据校验的一部分；还应独立判断引文是否支持该取值、临时性和范围。按人物及场景家族报告分母、错误率与不确定性，不用一个总体分数掩盖无记忆轮次上的误记。

| 层次 | 关键指标 |
|---|---|
| 提取 | 精确率、召回率、无事实轮次误记率、临时性错误率、语义证据支持率 |
| 状态 | 独立会话计数、误晋升率、语义重复条目率、更新延迟、过期／删除与取消后的残留写入 |
| 选取与注入 | 适用记忆召回、错误范围／过时记忆使用率、快照一致性、角色过滤与实际请求匹配 |
| 下游行为 | 未重述偏好时的遵守率、本次要求覆盖率、数学正确性、来源完整性 |
| 资源 | 所有模型调用与 token、提示词长度、延迟、记忆占用、失败和重试成本 |

同一公开输入分别运行无记忆、当前记忆方法、理想记忆对照。理想记忆只能包含截至当时已公开且仍有效的事实，不能偷用人物卡中未透露的设定。它用于区分“记错／没取到”和“正确注入仍不会用”。规则测试保持精确断言；主观回答由不知道候选身份的评审按冻结量表判断，抽查分歧和高影响错误。LongMemEval 的信息提取、跨会话、时间、更新与拒答维度可以补充场景覆盖，但不能直接等同于本项目的偏好遵守评测。[LongMemEval 原论文](https://arxiv.org/abs/2410.10813)

旧实现有一个需保留的基线边界：条目只做 Unicode／空白规范化，按 `scope + field + value` 精确匹配；提取器只拿到 `known_fields`，没有历史 value。“先画图”和“图像优先”可能形成两条，无法合并独立会话证据。13 轮探索已观察到同句改写导致分裂；随后 `value=evidence` 的小样本控制只验证固定原句，没有实现语义归并。目标版本改用类型化规范值与独立原句证据，需同时报告碎片率和错误归并率。不能让评分器替系统合并后宣称晋升成功，也不能把字段合同缺陷都归因于 sys prompt。

### 用文字梯度迭代 system prompt

对 API 中的离散提示词没有直接可用的数值梯度。可借鉴 ProTeGi：从一批失败样例生成自然语言错误反馈，再据此编辑 prompt 并搜索候选；TextGrad 则把文字反馈归因到复合系统中的不同组件。这里建议先用简单的单职责候选搜索，尚未选择或引入任何优化框架。[ProTeGi](https://aclanthology.org/2023.emnlp-main.494/)、[TextGrad](https://arxiv.org/abs/2406.07496)

旧基线的提取提示词位于 `memory/service.py::EXTRACTION_INSTRUCTION`，记忆使用说明为 `MEMORY_CONTEXT_INSTRUCTION`；13 轮探索已经修改其中部分规则。重写目标下，个人信息解释归固定请求解释阶段，后台提交不再有独立提取提示词。后续优化应选择一个已实现版本、一个明确职责进行，不能用旧文件位置约束新架构。对同一版本做 prompt 对照时，数据库规则、字段合同、晋升阈值、预算、取消围栏和正确性检查保持不变；架构／合同变化另立实验。检查回执必须随相关规则版本失效。

一次迭代的执行顺序：

1. 固定模型配置、案例版本、初始记忆和评判标准，运行当前 prompt，记录完整轨迹。
2. 从训练集抽取分层小批次，汇总“输入—预期—实际—错误层次—相关规则”。先判断问题来自提取、存储策略、选取、提示词注入还是回答执行；程序缺陷进入代码修复。
3. 生成文字梯度，例如：“把一句话里的本题例外和长期习惯当成一个事实，导致整条记忆标为临时。”反馈必须绑定证据，不能只写“提升准确率”。
4. 生成 2～3 个局部候选。将“学习率”理解为编辑幅度：一次只改一个职责段或少量规则；保留无修改的基线候选，限制提示词长度，避免累加每个失败样例的专用补丁。
5. 在相同冻结输入和独立重置的记忆库上比较候选。开发阶段用训练集诊断、验证集选优；维护案例家族指标和不变量门槛，不能为了提高召回而放宽证据规则。
6. 最优候选经过配对复跑，确认误记、误晋升、当前要求优先、数学正确性等关键指标不倒退，才成为下一轮基线。无可靠改进就保留旧版本；预设调用／token／轮数上限，连续无提升时停止。
7. 选定方案后才运行锁定的最终测试集。测试结果不再用于这一轮改写；需要继续优化时明确启动新实验并更换独立留出集。

可用加权错误率作为搜索目标，例如 `L(P) = w1×误记率 + w2×漏记率 + w3×临时性错误率 + w4×错误使用率 + λ×调用成本`。权重和计分分母在实验前固定；写入取消、证据伪造、快照越界等硬约束单独判定。建议先限制误记和临时性错误，再改善召回，而不是一开始追求记忆条目最多。梯度下降只是迭代方式的类比，不保证损失单调下降或全局收敛。

例如针对“这道题只要结论，平时还是解释每一步”，候选修改可要求“按原句中的事实分别判定限定范围；本题限制只作用于对应事实”。配套反例必须覆盖“我平时也只要结论”和没有任何稳定偏好的表达，防止该修正一律提取出“喜欢详细解释”。

### 研究评测接入顺序

1. 保留现有 `evals.memory_visual`、`evals.memory_assessment`、`evals.visual_review` 及 13 轮原始证据；已存在的 runner 不再列为待从零创建的功能。它们当前服务旧合同，适配新架构需另行验收。
2. 冻结人物、事件账本、支持字段与评分标准，为旧基线和新目标分别定义状态预期。旧精确字符串匹配与新类型化规范值不共用隐式判定。
3. 目标实现完成后，先验证请求解释、偏好编译、状态提交及无偏好重述的文字探针，再选代表性视频检查实际渲染参数；搜索期间不为每个候选生成完整配音视频。
4. 有可信基线后再运行候选 prompt 文件、批次反馈、版本选择与回滚。候选保存在独立实验目录，选优后审阅差异再修改发布的提示词；记忆后台任务不自行优化系统提示词。

每次实验保存案例／prompt／源码摘要、模型及参数、人物和会话划分、逐轮状态、评分依据、全部用量和失败分母。首轮受控模拟支持工程与提示词改进判断；真人自然程度和实际学习收益仍需独立验证。

## 方向二：数学对象状态感知的音画对齐

### 工程基础与边界

当前 MiMo TTS 已提供真实音频，按实测旁白时长安排节拍；节拍内高亮位置仍按文本比例估计。词级强制对齐、字幕及语义状态对齐尚未实现。现有真实有声链路成功是工程基础，不能直接作为精确音画对齐的研究结果。

[Manim Voiceover](https://voiceover.manim.community/en/stable/quickstart.html) 已支持音频时长和词语书签同步；[Data Player](https://virtual.ieeevis.org/year/2023/paper_v-full-1049.html) 已研究旁白与视觉对象的语义关联及同步约束。因此，接 TTS、使用时间戳或添加统一时间线不足以单独构成贡献。

### 候选研究问题

同一个符号或向量会在推导过程中移动、变形、分解或消失。即使语词时间戳正确，讲解也可能指向错误版本的对象。候选方向是绑定“旁白片段—数学对象—当前状态”，验证对象在对应讲解窗口是否存在、动作是否完成，并在语速或局部推导变化后修复受影响事件。

这仍是待验证的新颖性假设。需要进一步和语义关联、约束调度及可执行动画生成方法对比，不能仅因场景换成数学就认为是新方法。

### 数据与评测

以可执行数学或算法轨迹构建状态真值，例如向量变换、代数步骤或排序过程。真值生成器与被测方法分离，按任务和模板家族划分；语音分句拼接只能提供句段级时间真值，不能声称自然连续语音的逐词真值。

对照当前比例估时、强制对齐加自动书签、直接 LLM 时间线、语义关联加调度，以及理想对象绑定上界。指标包括对象／状态绑定、允许时间窗口内的事件比例、状态和顺序违规、可见性覆盖、语速／停顿／改写扰动后的稳健性、修复范围与成本。

可以增加少量独立核查的自然旁白样例提高外部有效性；不要求先开展大规模学生实验。也不能由相同对齐器生成真值并给自己评分。

## 工程版本与投稿判断

工程重写顺序统一由[目标架构](../design/00-固定教学流水线架构.md)和[开发计划](../current/开发计划.md)维护，本文不另设一份产品实施计划。历史 TTS 与记忆基础分别见 [TTS 报告](../../testresult/tts-20261105/报告.md)、[记忆报告](../../testresult/memory-20261106/报告.md)；最新探索及未通过事项见[13 轮报告](../../testresult/memory-visual-20261111/报告.md)。这些结果不会因新设计文档发布而升级为新版本验收。

之后每条研究路线各自完成问题定义、最接近工作复现、失败集、方法及独立评测，再选择主投方向。音画对齐可按多媒体／可视化方法论文组织；用户记忆可按 AI／NLP 的持续交互记忆方法组织。CCF B 及以上是目标，不是当前功能组合自然满足的门槛。

会议级别、征稿主题与截止日期应在实际投稿决策时重新核对官方页面，不沿用旧目录或已经过期的时间表。现阶段不把真人学习效果、跨设备画像或生成器经验积累加入工程必需范围。
