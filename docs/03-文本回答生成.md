# 文本回答生成

更新日期：2026年10月24日

状态：独立回答模块、Answer 资源和本节 `/api/v2` 尚未实现。当前 MVP 的 Agents.plan(text) 直接生成动画所用的 LessonPlan，不能当作独立 Answer。公共版本、引用、任务和错误规则见 [文档总览](index.md)。

## 1 职责与边界

根据已完成的 MaterialIR 和本次要求，生成可独立阅读、保存和修订的回答。模块负责选取相关材料、保留题设与定义、组织推理或讲解步骤，并检查内容和来源。

回答使用 Markdown 与 LaTeX 表达正文，不包含 Manim 类名、场景布局或渲染参数。用户可以只获取回答，也可以将确定版本交给 [动画生成](04-动画生成.md)。模型连接和参数由 [LLM 接入与调用](01-LLM接入与调用.md) 提供，不写入内容结果。

近期只使用材料和本次要求。长期记忆与个性化暂缓，不为当前请求新增学习历史依赖。

## 2 处理流程

```text
校验材料 ID、完成状态和用户要求
  → 选择相关内容，保留题设、定义及必要依赖
  → 生成标题、回答步骤与来源引用
  → 检查内容、条件、来源和结构
  → 从结构化步骤派生 Markdown
  → 保存完整 Answer，或返回待补充、待核对问题
```

材料不足时提示补充，不编造题设。概念解释可以选取明确标注的演示例子，具体题目的数据和条件必须保留。长材料的选取不能丢掉结论所依赖的定义或条件。

结构和引用用确定性规则校验；内容一致性按回答配置组织模型检查。关键公式、题设或结论无法确定时，保留来源并返回问题。合法 JSON 不能代替内容检查。

## 3 输入输出

```text
generate_answer(request: AnswerRequest) -> Answer
save_answer_revision(request: AnswerRevisionRequest) -> Answer
```

### Answer

Answer 是可独立使用的回答，与动画类名、画面布局、渲染分辨率等实现细节无关。

| 字段 | 类型 | 规则 |
|---|---|---|
| schema_version | string | 必填，`"1.0"` |
| answer_id | string | 必填，不可变回答标识 |
| material_ids | string[] | 必填，至少一个来源材料标识 |
| derived_from_answer_id | string \| null | 必填；编辑或修订时引用旧回答，首次生成为 `null` |
| title | string | 必填，回答标题 |
| instruction | string | 必填，本次用户要求 |
| steps | AnswerStep[] | 必填，至少一个，按讲解顺序排列 |
| markdown | string | 必填，由 title 和 steps 的内容按确定规则生成 |
| warnings | AnswerNotice[] | 必填，保留回答中仍需注意的限制 |
| created_at | string | 必填，结果创建时间 |

AnswerStep 为 `{step_id, title, content, source_refs, example_notes}`：`step_id` 在回答内唯一；`content` 为可含 LaTeX 的 Markdown；`source_refs` 为 `{material_id, block_id}` 数组；`example_notes` 为字符串数组，说明系统自行选择的演示例子。没有来源的演示内容允许空引用，并需明确说明其性质。

AnswerNotice 为 `{code, message, step_ids, source_refs}`，使用带 material_id 的来源引用避免多材料中的 block_id 混淆；无定位的数组为 `[]`。

`steps` 是回答正文的唯一事实来源。`markdown` 按“一级标题为 title；每个步骤依次生成二级标题、正文及非空的演示例子说明”派生，避免完整回答与结构化步骤各自维护后发生冲突。来源索引根据 source_refs 单独展示。

用户编辑回答时提交结构化步骤，服务端校验引用并重新生成 markdown，以新 answer_id 保存。视频始终引用某个确定的 answer_id，已有视频不随回答编辑而改变。

### AnswerRequest 与回答修订

| 字段 | 类型 | 规则 |
|---|---|---|
| material_ids | string[] | 必填，至少一个，只能引用完成的解析结果 |
| instruction | string | 必填，非空，本次讲解要求 |
| answer_profile_id | string \| null | 可选，默认 `null`，使用应用默认回答配置 |

材料的选取、必要上下文补充和教学内容规划属于回答模块。长材料先选取与要求有关的内容，同时保留定义、题设和依赖条件；材料不足时返回明确提示。

AnswerRevisionRequest 为 `{base_answer_id, title, instruction, steps, warnings}`。用户提交完整替换内容而非局部补丁，服务端继承原 material_ids 并设置 derived_from_answer_id。引用仍需属于这些材料。修改材料集合或要求模型重新推理时，重新提交 AnswerRequest。

长期记忆与个性化的输入扩展待该能力重新启动时设计，近期不增加相应字段。

### 后续 HTTP 接口

以下端点均待实现。Job 与 Error 使用 [总览中的公共规则](index.md)。

| 方法与路径 | 请求 | 成功响应 |
|---|---|---|
| POST /api/v2/answers | AnswerRequest JSON | 202，Job |
| GET /api/v2/answers/{answer_id} | 无 | 200，Answer |
| POST /api/v2/answers/revisions | AnswerRevisionRequest JSON | 201，新 Answer |

示例中的材料 ID 指向已完成的解析结果：

```json
{
  "material_ids": ["material_demo"],
  "instruction": "解释特征向量的几何意义，保留材料中的矩阵和向量。",
  "answer_profile_id": "answer_default"
}
```

完成后的 Job 返回 `result: {"type": "answer", "id": "answer_demo"}`。页面可展示回答及来源索引，只有需要动画时才提交视频请求。

## 4 实现方案

### 内容与版本

AnswerStep 使用稳定 step_id，将讲解顺序和来源引用保存在结构化结果中；正文 Markdown 按确定规则派生。编辑时保存完整替换内容并校验来源，产生新的 answer_id；旧 Answer 和引用它的视频继续可读。

材料提取质量问题返回材料模块处理；回答组织或推理问题由本模块修订；动画中的布局、节奏和渲染问题由动画模块处理。动画模块发现原回答内容问题时，返回 answer_id 和 step_id，由上层显式发起修订。

### 调用与依赖

answer_writer 和 answer_checker 可以共用同一模型绑定，使用固定配置快照与有界预算。只依赖材料仓储和本阶段模型能力，不因渲染、字体或语音服务不可用而拒绝生成。

当前 Agents.plan 和 PlanChecker 中关于事实保留、演示例子和内容覆盖的检查可在拆分时复用；动画的场景数、布局和可执行性检查继续留在视频规划中。拆分后显式生成 Answer，不将现有 LessonPlan 直接改名。

## 5 当前状态与待办

先从纯文本 MaterialIR 贯通独立回答生成、保存和读取，再加入人工修订与页面展示。实现顺序见 [开发计划](开发计划.md)。

验收重点：

- 回答可以独立获取，未配置 Docker 或 TTS 时可正常工作。
- 更换问题或回答模型复用已有 MaterialIR，保留输入、配置与实际调用记录。
- 题设、定义、公式含义和结论完整，演示例子与来源事实区分清楚。
- 多材料引用有效；不存在的 material_id、block_id 和未完成材料被拒绝。
- 编辑后创建新版本，steps 与 Markdown 始终一致，旧视频仍指向旧回答。
- 缺少关键条件、输出截断或检查未完成时，不提交伪装完整的成功结果。
