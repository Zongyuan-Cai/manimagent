# 开发计划

更新：2026-11-13。本页分别记录当前可运行基线、尚未实现的目标重写和待完成验收。目标架构以[固定教学流水线架构](../design/00-固定教学流水线架构.md)为准；本次文档更新没有改变运行代码，也没有完成该设计中的新增能力。

## 当前实现与验证边界

当前开发工作树以 0.3.1 为基础，已具备材料解析、完整文字、分块动画、可选 MiMo 旁白和用户记忆首版。功能可运行不等于各类题目均已达到生产质量。

| 能力 | 当前完成边界 | 使用与维护入口 |
|---|---|---|
| 输入与文字 | 按当前支持范围解析材料，保留来源；生成、检查、下载和人工修订完整正文 | [能力与接口](能力与接口.md)、[运行与配置](运行与配置.md) |
| 动画 | 固定 Answer → 教学单元 → 大纲 → 分块 → 时间解析与内容／排版检查 → 可信 Manim → 全片解码 | [动画实现](动画实现与本地运行.md) |
| TTS | MiMo 逐节拍旁白、实测时长、WAV、有声 MP4；失败保留已发布正文 | [语音说明](MiMo语音与验收.md) |
| 用户记忆 | 原句候选、短期／深层、独立会话晋升、人工确认／纠正／删除、自动清理及持久后台任务 | [用户记忆](用户记忆与个性化.md) |
| 上下文与状态 | 受理时冻结配置和记忆，文字与视频共享快照，实际模型请求可审计 | [当前代码架构](代码架构与迁移.md) |

当前仍在父任务结束且 Answer 已发布后，由后台模型从原始 instruction 提取记忆；记忆使用自由字段／文本取值，临时信息可存为条目，学习开关依赖读取。这些是待替换的实现，不是新架构的要求。固定请求解释、类型化偏好、独立读写开关、仅由代码执行的后台候选提交，以及渲染器直接执行的视觉参数，均尚未落地。

最新一轮大一数学分析模拟按用户要求在第 13 轮结束后停止，原计划第 14–20 轮未执行。主轨迹为 1 轮完整成片、9 轮仅正文、3 轮正文被阻断；自然晋升与配色遵循未整体通过。独立固定原句提取、清退和场景控制实验必须单列，不能替代主轨迹结果。完整证据见[本轮报告](../../testresult/memory-visual-20261111/报告.md)及[记忆验证](../../testresult/memory-visual-20261111/记忆验证.md)。这次设计不代表恢复或完成剩余轮次。

先前的[结构清理](../../testresult/cleanup-20261111/报告.md)、[早期复审](../../testresult/review-20261103/报告.md)、[动画复测](../../testresult/review-animation-20261103/报告.md)和[后台沉淀验收](../../testresult/memory-consolidation-20261106/报告.md)保留各自版本与样本边界。历史通过数字不自动沿用到新架构。

## 目标重写与实施顺序

目标是固定编排器、类型化阶段合同、不可变领域产物、有效偏好编译和小型记忆状态机。实施允许整体替换内部模块，不以保留现有函数或最小改动为约束；阶段划分用于管理依赖与验收，不代表各阶段分别新增服务或通用框架。

| 顺序 | 待实现工作 | 完成证据 |
|---|---|---|
| 1 | 定义阶段合同与领域产物：SourceBundle、RequestIntent、AnswerDocument、VerifiedAnswer、VideoOutline、ScenePlan；明确输入、放行条件与产物依赖 | 各阶段只消费声明输入；教学单元、正文、来源及依赖保持同源；未通过检查的候选不能进入下游 |
| 2 | 固定请求解释一次产生 RequestIntent 与带原句的 MemoryProposal；编译 EffectiveProfile 中的 TeachingSpec／VisualSpec | 当前自然语言要求立即进入本次参数；材料与模型输出不成为用户证据；未知字段、能力不支持和歧义有明确结果 |
| 3 | 重写记忆存储与状态规则：受控字段和取值、范围、证据、完整版本、独立读写开关；后台只提交已解释候选，不重复调用模型 | 临时要求只影响当前任务；明确默认可直接确认；普通近期偏好按独立会话支持迁移；失败视频仍可保存合法偏好，当前任务不受写入影响 |
| 4 | 将视觉要求编译为渲染合同：语义色角色、主题映射、类型化数学图形，以及统一的能力定义 | 配色在实际对象参数中生效；离散点不误连线；曲线、割线、切线有对应语义约束；不支持的表达明确拒绝 |
| 5 | 统一最终请求的预算、发送与追踪；按依赖绑定候选、规则、能力和检查版本；建立阶段恢复 | 可追踪每次修复实际使用的输入；预算不足不能删条件继续；颜色、声音、正文变化只复算其受影响阶段，失效凭据不能复用 |
| 6 | 补齐来源撤回、删除防复活、迟到提交围栏、旧数据迁移及界面状态 | 人工纠正不能被旧任务覆盖；撤回来源可重算支持；删除不会从旧候选恢复；生成与记忆保存分别报告；旧历史产物不会被新语义冒充 |
| 7 | 对固定版本开展真实教学、记忆与音画验收 | 保存全部首次成功／失败、显式修复和成本；区分输入合规、状态正确、实际表达遵循及成片内容合格 |

目标架构、阶段职责与恢复规则由[架构设计](../design/00-固定教学流水线架构.md)维护；字段、证据、状态和撤回语义由[记忆设计](../design/05-长期记忆与个性化.md)维护。Prompt 与参数合同见[Prompt 规范](../design/动画Prompt与检查规范.md)。运行文档只有在对应代码与验证落地后才更新为新行为。

## 重写必须保持的产品约束

- 原始材料和用户要求可追溯，解析结果不能改写原题或制造用户属性。
- 检查通过的 Answer 是视频教学事实源；视频阶段不能重新解题或丢弃必要推理。
- 当前明确要求优先于历史默认；个性化不改变数学正确性、原始题设和发布标准。
- 一次任务使用固定的配置、记忆依据和已编译参数；后台更新只影响后续受理的任务。
- 读和学在目标设计中独立；记忆候选来自用户输入，提交结果与文字／视频结果分别报告。
- 文字已发布而视频失败可以交付部分完成；请求有声视频时，TTS 失败不能自动改交静音成功。
- 可信渲染器不执行模型生成的任意 Python；不支持的硬要求应尽早明确报告。
- 修复受父 deadline、调用与资源预算限制；失败候选及检查证据保留，不能放宽标准获得通过。
- 字段类型校验不等于语义理解正确；同义归并、歧义和范围选择仍需真实模型评测。
- 用户记忆与生成器改进资料分开；系统讲解过、渲染成功、反复读取记忆均不证明学生掌握或形成新支持。

## 待完成的质量验证

停止第 13 轮时，仍有 MathText 命令兼容、配色实际执行、图形和旁白约束遵循、检查器误报与漏报等问题。新方案通过受控字段和渲染合同改变解决位置；这些问题只有在新实现及对应回归通过后才能关闭，不能因为写入设计文档而标记已修复。

旧问题追踪中的修复与生产验收要分开。最终配置的 10 题 × 3 次真实生成、全部失败成本、完整人工看片、跨场景符号与颜色约定验收尚未完成。已有单次有声结果、记忆控制实验和确定性测试不能替代这些工作；不再用旧 issue 的关闭状态推断质量达标。

目标成片为 120～360 秒、1280×720、30 fps。常规视频阶段 P95 ≤8 分钟、整体 ≤10 分钟仍是待验证目标，测量口径见[生产验收](../design/动画时长与生产验收.md)。实际预算以所测版本和配置记录为准，配置了硬限并不等于达到性能目标。

生产评测要求支持范围内至少 10 题 × 3 次真实运行，并补充错误输入及故障情况。报告首次文字／视频合格率、人工严重问题、阅读时间、TTS 发音、视频／整体 P95、超时／partial 和显式重试成本。正确拒绝不支持输入不能算视频完成，不能只统计成功样例耗时。

验证分三层：程序测试验证合同、状态和恢复；真实模型及渲染验证理解、执行和成本；人工完整看片核对自动检查与关键帧采样可能遗漏的问题。基准先串行并记录冷／热启动、机器和资源；并发、缓存等优化须证明质量没有退步。

## 本版范围之外

本次目标不需要通用对话型 agent 内核、动态工具发现、会话树、历史压缩、向量检索、LLM 总摘要或自主记忆整理 agent。教学经历与掌握度跟踪、连续课程、诊断测验应在产品需要且具备学生作答证据时另行设计。

词级强制对齐、字幕、多语言长视频、三维、任意视觉风格、多租户和跨设备同步不作为本次目标重写的前置。OCR、材料覆盖和模型协议继续按各自边界维护。

生成器经验进入离线失败案例、校验器／模板／提示词修改和固定回归，不写入学生记忆，也不允许记忆提交过程改写发布的系统提示词。删除有效记忆影响未来任务；彻底擦除历史 Answer、视频及诊断快照是独立操作。

## 研究与投稿

用户记忆生命周期和音画对齐保留为两条独立研究路线，共用工程平台并分别定义方法、对照和指标。作者已有 ManimAgent 论文是前作，后续贡献必须说明与前作的区别。

CCF B 及以上会议仍是研究目标，投稿不等于录用。先完成可复现工程和方法对照，再核对具体会议的最新要求。模拟学生与固定控制实验不能解释为真人学习收益；具体方案见[研究方案](../research/个性化记忆与投稿研究方案.md)。
