0.3.1 开发工作树已实现“多种输入 → 可追溯材料 → 完整文字 → 整体规划 → 分块生成 → 可配音视频”，并提供可选的用户记忆。当前是单用户、单机、可信模板版本。已实现功能不等于生产验收通过；早期修复见 [0.3.1 复审报告](../../testresult/review-20261103/报告.md)，有声与记忆增量分别见 [TTS 报告](../../testresult/tts-20261105/报告.md)、[记忆报告](../../testresult/memory-20261106/报告.md)。

后续[动画修复与复测](../../testresult/review-animation-20261103/报告.md)补充符号矩阵、方程组、文案行宽、有界修复和检查配置绑定；区分快速模式媒体完成数、人工发现的内容错误与推理模式复测结果。

记忆通过有界上下文影响当前回答和视频规划；首版不加入生成器经验。开启语音后，节拍旁白边界来自真实 WAV 时长，节拍内高亮仍是比例估计；不能称为逐词或对象状态的精确同步。

## 当前双输出请求与资源

`POST /api/v2/generations` 接受 `output_mode: "text" | "both"`，省略时为 `text`。当前没有 `text_video` 值。请求形式：

```json
{
  "output_mode": "both",
  "video_profile_id": "auto",
  "source": {
    "type": "inputs",
    "inputs": [{"type": "text", "text": "给定 a=(3,2)、b=(2,0)，解释并计算正交投影。"}],
    "instruction": "完整推导，解释投影系数与投影向量的区别，并验证残差正交。"
  }
}
```

source 是互斥联合：`inputs` 提供输入与 instruction；`materials` 提供已保存的 material_ids 与 instruction；`answer` 提供 answer_id。复用 Answer 不调用 writer；未经内容检查的修订版在视频阶段补做检查。模型参数和密钥不放入业务请求。

`video_profile_id` 可为 `auto`（跟随已保存语音默认值）、`standard_narrated` 或 `standard_silent`；仅文字输出不调用 TTS。网页在开始前展示核心、语音与视觉配置状态，格式、大小或页码范围错误不会清掉已有回答。

顶层可选 `memory: {session_id, scope: "global", learn: true}` 开启本次用户记忆；省略则不启用。接收任务时冻结已有记忆，`learn:true` 另外登记持久化沉淀任务，等待本次输出结束且已发布完整 Answer 后才提取 instruction 中的新偏好；`learn:false` 只读取。复用 Answer 的视频沿用该 Answer 的快照，不读取最新记忆替换它，也不重复学习。后台状态、独立用量、重试与取消见[用户记忆与个性化](用户记忆与个性化.md)。

记忆文件接口位于 `/api/v2/memory/documents`，提供状态、读取／下载、重新同步和受控导入；只允许修改取值，导入后按人工纠正规则创建新条目。任务 `/api/v2/jobs/{job_id}/memory-context` 返回冻结快照及实际请求中的分角色记忆，`?download=true` 下载 Markdown。请求记录只证明构造了哪些内容，不证明服务端使用或遵守了偏好；详细字段与错误边界见[记忆 HTTP 入口](用户记忆与个性化.md#http-入口)。

| 资源 | 作用 |
|---|---|
| FileAsset | 原件、派生素材、诊断及成片，通过不透明 ID 访问 |
| MaterialIR | 规范文本／表格、来源位置与覆盖检查 |
| Answer | 独立完整正文、来源及可选 memory_snapshot；人工修订产生新 ID 并继承快照 |
| VideoPlan | 绑定 Answer ID/hash 的大纲、原文单元、场景和时间线 |
| VideoResult | 同版正文引用、媒体资产、逐单元时间映射和逐节拍关键帧 |
| Generation | 一次请求的材料、回答、视频引用和阶段状态 |
| Job | 队列、进度、错误、用量与诊断；独立 video job 从排队时携带 answer_id |

所有公共资源可序列化，内容 ID 不含本地路径或凭据；Answer/VideoResult 不原地修改。Job/Generation 是可更新的编排记录。入口与字段的最终依据为当前 `/openapi.json`、`schemas.py` 和 `video/models.py`。

视觉解析生成的材料带未人工核验的来源标记和警告；模型报告不确定时进入待核对。图片上传成功、模型声明支持视觉、文本连接测试通过，都不能替代对实际图像内容的核查。

## 执行、部分完成与续跑

材料 → 完整正文及检查 → 原子保存 Answer → 规划与分块 → 排版和计划检查 → 渲染与媒体验证 → 保存 VideoResult。正文就绪后立即可读，不等待视频。

| 结果 | 状态与行为 |
|---|---|
| 仅文字完成 | completed，读取完整 Answer |
| 双输出的文字已完成、动画运行中 | running，正文仍可阅读、下载与修订 |
| 双输出都完成 | completed，Generation 引用同版正文和视频 |
| 双输出的动画失败／待核对／预算耗尽 | partial，保留全文与阶段错误 |
| 材料或文字缺条件／不可靠／失败 | needs_input、needs_review 或 failed，不发布完整答案 |

只生成或重试视频使用 `POST /api/v2/videos`，传 `{answer_id, resume_job_id?}`。也可通过 `source.type=answer` 新建双输出 Generation。当前没有 `/generations/{id}/video-retries` 端点。

resume 只复用同 Answer ID、正文摘要和兼容 prompt 版本的分块；随后重新计算时间、检查和渲染。不会把续跑成功计作第一次成功，也不跨任务自动复用成片。编辑正文生成新 Answer 后，页面清理旧视频并忽略旧请求返回；播放前再次核对 Answer ID 与 hash。

每个私有目录只能由一个服务或 CLI 持有写入权。桌面重复启动回到已验证的现有服务。进程退出释放操作系统锁；重启恢复已有结果，并将未完成任务标记为 interrupted 或保留正文的 partial，不自动花费模型用量续跑。

## 动画与时间边界

当前模板支持公式、二维向量／点／线段／虚线／多边形／圆、最多 4×4 数值或符号矩阵。公式内矩阵由有限行列解析器和固定模板绘制，表达边界见[实现说明](动画实现与本地运行.md)。模型输出声明式数据，原生进程执行仓库内模板，不执行模型生成的 Python。无 Docker 依赖，也不宣称具有容器隔离。

整体规划为 3～8 场景、每场景 3～7 节拍、全片最多 42 节拍。程序根据屏幕阅读量、旁白稿和动作窗口解析时间；成片硬限 120～360 秒。短片修复只能展开正文已有依据，不能以重复内容或空等凑时长。矩阵保留数值区别；布局不可读时停止，不静默舍入或无限缩小。

当前硬限：受理起整体 900 秒、排队 120 秒、视频阶段 600 秒、单模型等待 60 秒、单场景渲染 90 秒、视频最多 24 次模型调用、全阶段一次额外模型重试与最多两次共享局部修复。性能目标和固定测量口径见[生产验收](../design/动画时长与生产验收.md)；限额存在不代表 P95 或合格率已达标。

交付规格为 1280×720、30 fps、H.264/yuv420p；开启 MiMo 时附带 AAC 音轨与独立 WAV，关闭时仍可生成无声视频。所有已发布成片完整解码并核验事件、媒体与版本；这不替代逐帧语义检查或人工完整看片。

## 实现与维护

当前使用 Python 3.12、uv、Pydantic、FastAPI、本地文件存储、用户记忆 SQLite、一个前台任务 Worker 和一个有界后台记忆 Worker；动画 extra 增加 Manim、Matplotlib、PyAV 和 FFmpeg。主入口为 `api/app.py`、`cli.py`；`materials/`、`answers/`、`memory/`、`video/` 维护业务，`jobs/` 负责队列、执行与状态恢复；详见[代码架构](代码架构与迁移.md)。

旧 LangGraph／Docker MVP 与过时文档已从当前树移除，复现入口为[固定历史版本](https://github.com/Zongyuan-Cai/manimagent/tree/3e1605c120cd31269406b146b22a6aec85075dbc)。当前发布包只包含正在维护的服务。

主维护者可直接推送 main，推送后执行 Windows／Linux 回归、原生渲染、JS 行为测试和隔离包安装验证。生产使用仍需完成固定版本真实评测与人工看片；本次真实失败不得用历史成功样例覆盖。
