# 用户记忆与个性化

更新：2026-11-13。本页说明当前工作树已实现的固定请求解释、类型化偏好、确定性记忆提交和只读 Markdown 导出。整体职责见[固定教学流水线架构](../design/00-固定教学流水线架构.md)，完整语义与尚未完成的边界见[记忆设计](../design/05-长期记忆与个性化.md)。

当前已经替换“Answer 发布后再调用模型提取”的旧路径。请求解释一次产生本次要求和记忆候选；合法候选独立提交，正文、视频或配音失败不会否定这次明确表达的偏好。程序测试验证状态与事务规则，尚未重新开展真实模型的同义理解、配色遵循及真人学习效果评测。

## 使用方式

1. 按[运行与配置](运行与配置.md)启动服务并配置回答模型。问题表单中的“使用已有记忆”和“记住新的偏好”可独立选择；新浏览器默认均关闭。
2. 本次要求始终经过请求解释。例如“这次直接证明”只影响当前任务；“以后默认用蓝金配色”还可以产生跨任务默认。关闭记忆不会关闭对当前要求的理解。
3. “我的偏好”可添加自然语言表达、查看规范值和原句、确认默认、从受支持选项中更正或删除。自然语言添加需要模型解释；确认、更正、删除由代码执行，不调用模型。更正表示确认新默认，不继承旧取值的会话支持。
4. 同一次交流沿用 `session_id`。刷新和重复提交不会创造独立支持；只有真正开始另一轮独立交流时才使用“开始新会话”。
5. 查看结果的历史快照和“本次使用的记忆”，核对 `EffectiveProfile` 的采用记录；在运行详情中查看逐次请求审计。后台新写入不会改写这个任务已经冻结的依据。
6. 在偏好更新记录中查看提交、失败、取消和允许的重试。生成状态、记忆保存状态、Markdown 导出状态分别报告，不能从“视频完成”推断已经保存偏好。

| 读取 `read` | 学习 `learn` | 行为 |
|---|---|---|
| `false` | `false` | 使用当前要求和产品默认，不提交新候选 |
| `true` | `false` | 使用受理时快照，不更新记忆 |
| `false` | `true` | 不把历史偏好送入生成，合法新候选可供未来任务使用 |
| `true` | `true` | 使用旧快照，同时独立提交本次候选 |

网页目前提交 `global` 范围。API 支持 `course.<id>` 和 `topic.<course>.<id>`，仅允许所选范围及其祖先范围；系统校验标识格式与范围关系，目前没有课程目录实体或网页范围选择器。CLI 尚无新增的记忆管理命令。

## 支持的字段与状态

| 字段 | 规范取值 |
|---|---|
| `explanation.order` | `intuition_then_proof`、`proof_then_examples` |
| `explanation.detail` | `concise`、`detailed` |
| `explanation.examples` | `few`、`many` |
| `visual.palette` | `standard`、`blue_gold`、`high_contrast` |
| `visual.font_size` | `standard`、`large` |
| `visual.motion` | `standard`、`minimal` |
| `profile.background` | `first_year`、`second_year`、`third_year`、`fourth_year`、`graduate` |

规范值与原句分开保存。“先理解直觉，再看严格推导”可以由模型映射为 `intuition_then_proof`，原句仍独立留证。取值校验通过不代表语义映射一定正确；模型不能从教材、解答或渲染成功推断学生掌握度。

普通偏好先进入 `short_term`，以用户输入的受理日期计算默认 14 天有效期。一个 14 天支持窗口内有 3 个独立会话支持同一规范值，才可自动成为 `deep`；同一会话重复表达只算一个独立支持。晋升后不因长期未读取而自动过期。明确“以后默认”、确认或更正可以直接建立默认。

背景字段始终标记 `self_reported=true`，证据保留受理日期。重复自述不自动晋升；即使明确确认，当前实现也按最新有效自述的受理日期设置 365 天期限，不将“大一”永久化。

编译先应用本次明确排除，再逐字段采用：当前明确值 → 主题 → 课程 → 全局 → 产品默认。同范围稳定值优先于近期值；近期冲突不会静默覆盖稳定默认。所有适用候选先被冻结，再由代码选用，后续阶段只消费已编译的 `TeachingSpec`／`VisualSpec`。

“忘记蓝金偏好并生成视频”会在本轮编译中立即排除蓝金，同时独立提交持久忘记操作。删除有效条目会清除其支持原句并留下不含原句的去重、规范值禁止自动恢复及接受顺序围栏；旧来源重放、换新来源 ID 或迟到提交均不能自动复活。需要恢复时通过自然语言明确“重新记住”，解释为 `restore`。来源撤回只移除该来源的支持并重算状态，不等于永久禁止整个字段。

## 保存、恢复与容量

受理时在 SQLite 事务中分配 `sequence` 并保存记忆快照；不读取历史时快照为 `null`，仍保留合法写入需要的来源绑定。解释只读取当前用户要求、有限字段及能力合同，不将历史记忆当作新证据。

解释产物先持久化，再分别进行偏好编译与候选排队。队列直接进入 `queued`，没有等待 Answer 发布的 `waiting` 阶段。后台执行 `queued → running → completed / failed / skipped`，取消为 `cancelled`；只做原句、来源、范围、受理顺序和状态检查，不再调用 LLM。

来源去重、支持记录、晋升或替换、全库修订和提交回执在同一事务内写入。并发默认以受理顺序决定先后，不以模型完成时间决定；较新的合法操作不会仅因旧操作先提交而被误拒。显式默认、更正、忘记和恢复的围栏持续有效；忘记后重新恢复，也不能重新吸收此前尚未提交的旧原句。

服务重启会恢复已持久化解释与排队之间的 `pending` 状态，不重新解释。`queued` 可继续处理；`running` 若已有提交回执则恢复完成，否则变为失败供显式重试。重试保留原受理顺序，最多 3 次；取消与提交竞争以事务结果为准，已提交时如实返回完成。停止生成不等于撤销已保存的记忆。

| 默认限制 | 当前含义 |
|---|---|
| 200 个条目 | 清理过期、已替代及必要的近期条目；不能静默驱逐已确认默认 |
| 每条显示 20 份证据 | 完整支持关系另存于观察表，显示限制不影响会话计数和来源撤回 |
| 200 个快照候选、100000 字符 | 保留全部适用候选；超限明确拒绝，不丢弃赢家后退回其他默认 |
| 10000 个来源 | 接受记录与去重依据有界；满额拒绝新来源，不删除防重放依据腾空间 |
| 100 个未完成提交任务 | 超限明确报告排队失败，教学链路可继续 |
| 200 个终态摘要 | 超限按历史顺序清理；来源去重独立保留 |

条目策略由 `Settings.memory_policy` 配置。近期与背景有效期从受理日期计算，迟到的普通候选不能通过提交时间续命。读取、模型复述及媒体成功不增加支持。后台队列的 `usage={}` 表示没有第二次模型调用；请求解释成本计入前台生成用量，手动添加偏好的解释成本随该管理请求返回。

## HTTP 入口

路径均以 `/api/v2` 为前缀，最终字段以 `/openapi.json` 为准。

| 方法与路径 | 作用 |
|---|---|
| `GET /memory` | 返回活动条目、策略、规范字段选项和近期提交任务 |
| `POST /memory/observations` | 用 `text/session_id/source_id/scope` 提交自然语言偏好；同步解释并事务提交 |
| `POST /memory/{memory_id}/confirm` | 明确确认默认；背景仍保留 365 天期限 |
| `PATCH /memory/{memory_id}` | `{"value":"规范新值"}` 更正确认默认；不支持的值返回 `invalid_memory`，422 |
| `DELETE /memory/{memory_id}` | 忘记该条目并建立防自动恢复依据 |
| `DELETE /memory/sources/{source_id}` | 撤回该来源支持并重算受影响条目 |
| `POST /memory/cleanup` | 清理失效条目并返回统计 |
| `GET /memory/learning/{job_id}` | 查看确定性提交状态、计数、跳过原因与允许的操作 |
| `POST /memory/learning/{job_id}/retry` | 显式重试允许重试的失败提交，保持原受理顺序 |
| `POST /memory/learning/{job_id}/cancel` | 取消未提交任务；已经原子提交则返回实际完成状态 |
| `GET /memory/documents`、`POST /memory/documents/sync` | 查看或刷新只读导出和文件状态 |
| `GET /memory/documents/{memory_id}` | 查看 Markdown；`?download=true` 下载 |
| `POST /memory/documents/{memory_id}/import` | 旧入口明确返回 `memory_document_read_only`，409，不再导入文件 |
| `GET /jobs/{job_id}/memory-context` | 查看冻结快照、编译采用记录及实际请求审计；支持下载 Markdown |

自然语言添加示例：

```json
{
  "text": "以后数学分析的视频默认使用蓝金配色。",
  "session_id": "analysis-lesson-1",
  "source_id": "preference-1",
  "scope": "course.analysis"
}
```

同一次用户表达的重试沿用 `source_id`，不能换 ID 来制造支持，也不能将同一 ID 改绑不同文本。生成请求中的可选配置为 `"memory":{"session_id":"analysis-lesson-1","scope":"course.analysis","read":false,"learn":true}`。省略整个 `memory` 不读写记忆；显式提供对象时 `read` 和 `learn` 的 API 默认值均为 `true`，建议客户端完整声明。

复用已有 Answer 生成视频时，不接受新的 `memory` 参数，保留该 Answer 的冻结参数。记忆管理只影响未来受理任务，不重写旧 Answer、视频、任务快照或本地导出副本。当前是本机单用户系统，`session_id` 不是账号隔离机制。

## 只读文件与迁移

SQLite 是唯一有效记忆源。默认数据库为 `runs/current/private/memory.sqlite3`；配置 `private_dir` 后随其移动。`memory/MEMORY.md` 是索引，`memory/entries/memory_<id>.md` 是条目导出，`memory/snapshots/job_<id>.md` 是冻结快照与实际请求审计。

文件只能查看、下载和调试。编辑或删除 Markdown 不会修改数据库，也不会被后台学习；修改默认使用结构化管理入口。导出失败独立显示，不撤销已经提交的数据库操作。

| 文件状态 | 当前含义 |
|---|---|
| `current` | 与数据库导出一致 |
| `edited` | 检测到本地编辑，保留副本，不导入 |
| `stale` | 本地副本有编辑，原条目也已变化，不覆盖副本 |
| `deleted` | 原条目已清理，但用户编辑的副本仍保留；不能借文件恢复记忆 |

| 标识 | 当前值与用途 |
|---|---|
| SQLite `schema_version` | `3`，表示条目、接受记录、完整支持、围栏和提交队列的存储合同 |
| 记忆 `policy_version` | `typed-user-memory-3`，标识生命周期和快照规则 |
| `EffectiveProfile.policy_version` | `personalization-2`，标识字段编译合同，不是数据库版本 |
| 任务 `pipeline_version` | `fixed-2`，标识流水线记录；历史任务保留原身份 |
| `revision` | 全库有效变化计数；`manual_revision` 是保留的同值字段名，不再只计人工修改 |
| `sequence / accepted_sequence` | 单调受理顺序，用于来源绑定、候选排序和显式决定围栏，不等于 revision 或时间戳 |

升级旧库前先停止旧服务并保留私有目录备份。初始化检测到旧库时必须先取得目录独占租约；旧服务仍运行则返回 `instance_busy`，不更改旧条目。迁移先逐字导出 `memory-migration-v3.json`，包含旧条目、来源、会话及后台任务，导出失败即停止且保留数据库原状。

当前迁移**不自动猜测任何旧自由文本的规范值**：旧条目退出有效库，旧未完成／失败的提取任务取消，来源去重依据保留；迁移完成后释放临时租约。用户根据导出报告，通过新的偏好管理重新明确需要的默认。尚无自动确定映射导入器，不能用导出文件直接恢复有效偏好。旧任务快照和评测报告不补写新合同或新验证凭据。

## 验证边界

程序回归覆盖同源幂等、会话支持窗口、时效、来源撤回、接受顺序、取消与提交竞争、回执恢复、迁移独占及只读导出。它们不证明模型必然识别正确的同义、反义、条件或引用人物，也不替代实际渲染和完整人工看片。

尚待完成的设计包括管理请求的显式期望版本检查、课程目录校验、生成表单直接提交完整类型化要求、迁移映射工具，以及新的真实语义与成片评测；具体计划见[开发计划](开发计划.md)。
