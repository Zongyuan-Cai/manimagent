# 正式动画阶段：实现与本地运行

更新：2026-11-06。当前 0.3.1 开发工作树已接入 MiMo，可输出有声 MP4/WAV；旁白边界实测、高亮位置仍为估计。具体配置、字段及失败行为见[MiMo语音与验收](MiMo语音与验收.md)。视频规划沿用 Answer 的可选[用户记忆快照](用户记忆与个性化.md)，不在规划中实时读取可变记忆库。

实现依据为[动画 Pipeline](../design/04-动画生成.md)、[Prompt 与检查规范](../design/动画Prompt与检查规范.md)和[时长与生产验收](../design/动画时长与生产验收.md)。本版采用可信的本地 Manim 模板，模型只生成受约束的 JSON，不依赖 Docker。禁止将该本地进程执行方式直接用于任意模型生成的 Python。

## 实际链路

1. 固定已有 Answer 与 SHA-256。有效内容检查回执必须同时匹配正文摘要、检查策略和检查模型配置摘要；关闭过内容检查、人工修订或更换检查模型／thinking 配置后都会补检。
2. 按正文 Unicode 码点半开区间建立 TeachingUnit，不切开围栏代码和独立公式。各单元保留原文与摘要；不修改正文。
3. `video_planner` 一次规划整体场景、受众假设、难度与时长理由、每场景承接单元。支持 3～8 个自包含场景，全片最多 42 个节拍。
4. `scene_generator` 按大纲逐块输出：屏幕解释、短公式、完整图形状态、旁白稿、语义 cue 和阅读理由。每块独立保存，可在后续请求中复用已验证版本的分块。
5. 服务器先估算旁白与阅读时间，解析事件顺序；初始计划总长必须在 120～360 秒，单个估计节拍不超过 24 秒。重复内容、覆盖缺失、越界对象和不存在的 cue 对象均被拒绝。时长不合格时，在共享的两次修复额度内局部重新生成，不加空等、不整体降速。
6. `plan_checker` 对照完整正文与所有分块逐单元核验覆盖、数学含义、图形参数和无声解释。任何必需项 fail／unknown 均阻止发布；不能拿平均分抵消。
7. 开启语音时逐节拍合成 MiMo WAV，以实际音频长度和已检查阅读窗口重排时间，并按 30 fps 对齐帧；单拍超过 30 秒或全片超过 360 秒即停止，不截断或加速语音。
8. 可信渲染子进程执行项目自带的固定 Manim 程序；公式由 MathText 转 SVG，不调用外部 LaTeX。逐节拍记录实际出现、稳定阅读与结束区间，抽取原尺寸关键帧，核验场景实测时长。
9. 按场景顺序拼接 H.264 视频；有声模式再封装 AAC 音轨，保留独立 WAV。完整解码 1280×720／30 fps 成片，检查对应模式的音轨、时长、帧数、时间戳与连接点，再保存不可变 VideoResult。

`both` 请求先发布正文，再继续动画。动画失败时 Generation 和 Job 为 `partial`，原 Answer 保留；`POST /videos` 只重新生成视频，不调用 writer。独立视频任务失败会返回自身错误，而不会改变原答案。

## 当前表达范围

模板提供公式逐步推导、二维向量／点／线段／虚线／多边形／圆、至多 4×4 的数值或符号矩阵。坐标图采用相同横纵单位比例，图例避让；无图节拍使用完整宽度的公式区域和中文解释。所有内容带安全边距，文字过密时失败，不无限缩小字体。

暂不支持任意 Python、任意外部素材、三维、复杂 LaTeX 环境或公式程序求值。超出模板的必要表达应返回范围问题，不能为了适应模板删去问题。MathText 使用 ASCII 数学语法（如 `\frac`、`\mathbf`、`\cdot`），中文放普通文本。

数值矩阵可用 `diagram.matrix`；公式内允许 `pmatrix/bmatrix/vmatrix/matrix` 四种有限矩阵环境，以及最多 4 行、2 列的 `cases` 方程组／分段式。程序解析行列后用固定模板布局，单元仍由 MathText 渲染，不交给 TeX 编译器。每行公式最多两个环境，每个矩阵最多 4×4，每单元最多 60 字符；拒绝嵌套、宏、不等宽行和重复转义的环境。支持矩阵后的单字符或花括号上标，如转置、逆矩阵。独立坐标等式和连续等号推导过宽时可按语义边界换行；字号仍不得小于初始值的 78%。

屏幕文案的校验与渲染共用每行 32 列、最多两行的规则，中文按 1 列、ASCII 按 0.53 列估算。混排文本不再被统一的 64 字符上限误拒；实际像素仍由原生布局检查约束。公式中显式换行按原顺序拆为公式行，仍受每拍最多三行的数据限制。图文半屏放不下的代数推导可在局部修复时改用整屏公式拍，必要几何解释须保留，并由统一语义检查复核。

本版不接入视觉模型。公开结果明确保存 `visual_model_review: not_run`，检查模式为 `trusted_template_geometry_and_layout`。模型检查针对计划语义，固定模板的几何、文字边界与媒体由程序核验，关键帧供人工复核；这些证据不能扩称为任意视频的完整视觉检查。

## 无 Docker 安装

```powershell
uv sync --frozen --extra dev --extra animation
uv run manimagent doctor --animation
uv run manimagent serve
```

需要 Python 3.12；Windows 使用 Microsoft YaHei／SimHei，Linux 可安装 Noto Sans CJK SC，或配置 `video_font`。渲染依赖作为 `animation` 可选项，纯文字安装继续可用。Manim 固定 0.20.1、PyAV 固定 15.1.0，FFmpeg 使用 imageio-ffmpeg 自带程序，不依赖系统 PATH 中的 FFmpeg、Docker 或 LaTeX。安装机制参考 [Manim 官方本地安装说明](https://docs.manim.community/en/stable/installation/windows.html)和 [PyAV 官方安装说明](https://github.com/PyAV-Org/PyAV/blob/master/docs/overview/installation.rst)。

渲染依赖版本按锁文件安装；升级 Manim、PyAV 或 FFmpeg 时需重新运行原生渲染与安装包回归，不沿用旧版本通过结论。

桌面交付目录可双击 `start.cmd`，在本地浏览器中使用。首次安装后的其他机器需要自行填写 LLM 配置；源码压缩包不含任何凭据或运行数据库。

```powershell
uv run manimagent lesson --question "给定 a=(3,2)、b=(2,0)，解释并计算正交投影，验证残差正交" --output lesson.mp4
uv run manimagent video --answer-id answer_<已有ID> --output lesson.mp4
```

`lesson` 同时保存同名 Markdown；视频失败时已生成的 Markdown 仍保存。模型配置仍通过原 LLM 配置界面管理，增加规划、分块生成、计划检查三项角色；未显式绑定时分别继承回答／检查角色。

对已验证支持 DeepSeek `thinking` 参数的连接，可在高级设置选择 `disabled`，避免结构化检查把输出额度全部用在推理 token 上。默认配置不发送该厂商扩展，不假定每种 Chat 兼容服务都支持。

## API 与复用

```json
{"output_mode":"both","source":{"type":"inputs","instruction":"完整解释题目","inputs":[{"type":"text","text":"题目内容"}]}}
```

以上提交到 `POST /api/v2/generations`。默认未填写 output_mode 的旧客户端仍生成文字。另有：

| 操作 | 路径 |
|---|---|
| 只生成视频 | `POST /api/v2/videos`，`{answer_id, video_profile_id?: "auto"或"standard_silent"或"standard_narrated", resume_job_id?}` |
| 任务／进度 | `GET /api/v2/jobs/{job_id}` |
| 结果／计划 | `GET /api/v2/videos/{video_id}`、`/{video_id}/plan` |
| 播放／下载 | `GET /api/v2/videos/{video_id}/content`，支持 Range；`?download=true` 下载 |
| 逐节拍证据 | `GET /api/v2/videos/{video_id}/frames/{index}` |

`resume_job_id` 复用相同 answer_id、正文摘要和兼容提示词版本的整体大纲／分块；重新计算时间、重新检查计划并重新渲染。新回答版本不能引用旧分块。当前没有跨候选复用媒体缓存，也不复用旧像素检查报告。分块在任务记录中按场景保存，未完成结果不会伪造为正式 VideoResult。

## 预算与执行边界

动画请求从受理计整体 900 秒硬限，排队 120 秒，视频阶段 600 秒；单模型等待至多 60 秒，单场景渲染 90 秒，全视频最多 24 次模型调用。额外模型重试全阶段最多一次，局部生成修复最多两次；所有成本计入父预算。串行渲染，不在未测量前启用多场景并发。

两次生成修复在大纲、排版、时长和语义之间共享；同一场景可用剩余额度再次修复，每次都要重新预检，最终版本必须重新通过统一内容检查。结构校验重试在上下文允许时携带上次候选和字段错误；候选放不下时仅发送有界反馈，不截断题目。更新后的内容检查会拒绝“错误等式仍留在前文、后文自我更正”的正文，旧检查回执因策略摘要变化而需要补检。

原生渲染进程使用环境变量白名单，不接收模型密钥、代理凭据或 `.env`。只读取服务器生成的 JSON 和自身创建的素材；宿主监测内存、deadline 与停机事件，超限终止进程树。它是受约束本地执行，并非操作系统容器隔离；任意代码后端仍需独立安全执行边界。

无声路径使用 `time_source=estimated`；MiMo 路径使用 `time_source=audio_measured`，表示旁白节拍边界实测。节拍内 `cue_time_source=estimated`，仍无词级强制对齐或 SRT 字幕。两种模式均保持 Answer、教学单元、旁白与事件的版本关系，不能将实测总时长扩称为逐词精确同步。

## 必须保持的回归约束

- 一个私有数据目录只允许一个服务或 CLI 写入任务。操作系统持有锁，进程崩溃后自动释放；重复打开桌面入口复用已确认属于该目录的服务。CLI 与服务同时使用同一目录时返回明确错误。
- 场景 ID 忽略大小写后唯一，拒绝 Windows 保留名称。缓存提示词版本更新，旧版本分块不可直接混用。
- 数值矩阵使用可往返的浮点文本，按实际字形宽度排列行列；过密时拒绝并局部修复，不静默舍入或缩到不可读。
- 公式按字体 em 保持字形尺度，再对整组公式限制可读缩放下限；求和上下限不会因统一总高度而挤小主体。排不下时拒绝并请求局部修复，渲染证据记录 em 和行边界。
- 原生渲染在短临时目录执行，保留输入、结果、日志、关键帧和成片，自动回收中间 SVG 与分段缓存。共享字体缓存避免每场重新扫描；排版预检只做几何构建，实际渲染仍核对事件时序。
- 页面按分享链接、已保存任务、已保存回答／视频的顺序恢复。视频须与正文 ID 和内容哈希一致；编辑或新任务会隔离旧轮询响应。仅视频任务在排队时也记录源回答 ID。
- 低于 120 秒时，有限修复请求补足已有推理的解释；超长时精简冗余。两种情况都不能添加空等，仍受原有调用和总时限约束。

真实评测运行：`python -m evals.video_benchmark --output runs/acceptance --secret-file <本机DPAPI文件>`。默认 DeepSeek Flash、`thinking=enabled`、10 题各 3 次、串行；可用 `--thinking disabled` 对照快速模式，也可用 `--workers 2` 做并发压力评测，但其耗时不能直接当作单任务性能基线。配置与源代码摘要均随结果保存，所有失败都计入首次请求分母，续跑应另列。

模块已按规划、检查、时间线与渲染分开，模块职责与评测入口见[代码架构](代码架构与迁移.md)。
