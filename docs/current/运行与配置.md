# 运行与配置

更新：2026-11-06。MiMo 配置与实测时间边界见[MiMo语音与验收](MiMo语音与验收.md)；可选记忆入口见[用户记忆与个性化](用户记忆与个性化.md)。

适用于当前 0.3.1 开发工作树的文字、可配音动画与用户记忆服务。既有 CLI 命令与资源路径仍可使用；语音和记忆在原链路上提供可选能力。

## 安装与启动

需要 Python 3.12 和 uv；当前模板渲染不依赖 Docker：

```powershell
uv sync --frozen --extra dev --extra animation
uv run manimagent serve
```

访问 http://127.0.0.1:8000，打开顶部“设置”中的“核心模型”，填入服务、模型和密钥，点击“使用此模型”，测试后保存；需要配音时，在同一设置窗口中切换到“语音配音”，独立配置并试听。关闭设置后回到问题输入、输出选择和结果区域；记忆管理从顶部“我的偏好”进入。只需文字时使用 `uv sync --frozen --extra dev`，不安装 animation extra。渲染依赖、中文字体与表达范围见[动画实现](动画实现与本地运行.md)。

桌面源码交付目录可双击 `start.cmd`。同一私有目录已有服务时，启动器验证服务身份后打开已有页面；新服务在 8000～8010 选择并保留可用端口。不能对同一 `private_dir` 同时运行服务和写入型 CLI。

## 模型配置

网页“设置”集中提供核心 API 和语音两个配置入口，两者仍分别保存。核心 API 支持 Chat Completions 兼容服务，提供 DeepSeek、MiMo 和自定义连接入口。先用一个核心模型即可生成文字与动画，也可在高级角色中分别绑定回答、内容检查、视频规划、场景生成和计划检查。截图与扫描页读取可以单独绑定声明 `supports_vision: true` 的视觉模型，未指定 `material_reader` 时跟随回答模型；普通文字不要求视觉能力。保存用于随后接收的新任务，已接收任务使用原配置和凭据引用。详细步骤见[核心模型配置](LLM界面配置.md)。

MiMo TTS 是独立的语音配置；网页可填写密钥、音色与朗读要求，试听草稿后保存。默认配音开关与本次任务的有声／无声选择分开，不需要配音时不必配置。更改网页配置立即生效，手动修改 `.env`／YAML 则需要重启。接口和优先级见[语音配置](MiMo语音与验收.md)。

也可使用根目录 [config.example.yaml](../../config.example.yaml) 与 [.env.example](../../.env.example) 提供初始配置。环境变量包括 `MANIMAGENT_TEXT_BASE_URL`、`MANIMAGENT_TEXT_MODEL`、`MANIMAGENT_TEXT_API_KEY`；不要覆盖已有本机配置或凭据。`.env` 不覆盖已有进程环境变量，网页保存的设置覆盖对应初始值。

角色先使用显式绑定。未显式绑定时，计划检查继承内容检查，其他角色继承回答角色；没有可继承绑定时优先 `text`，其次第一个配置；配置为空仍为未配置。界面与执行使用同一规则。

普通回答不强制 JSON；结构化检查根据 `json_mode` 构造请求并校验返回。`token_parameter` 支持 `max_tokens`／`max_completion_tokens`。`generate_url` 是完整操作地址，否则在 `base_url` 后追加 `/chat/completions`。`thinking` 仅应在确认服务支持时设置；默认不发送该扩展。

多配置支持不等于所有协议已接入：当前不自动转换 Responses、Anthropic Messages 或 Gemini 原生协议。历史真实厂商验证以[验证证据索引](../README.md#验证证据与历史)为准，不能将同一厂商的多配置复测表述成多厂商验收。

## CLI

| 命令 | 行为 |
|---|---|
| `serve` | 启动本机 HTTP 服务与网页 |
| `doctor` | 检查模型配置；`--animation` 同时检查渲染依赖 |
| `answer` | 从问题与材料生成完整 Markdown |
| `lesson` | 生成 Markdown 与同版视频；是否配音由 TTS 配置决定 |
| `video` | 使用已有 Answer 生成或显式续跑视频 |

```powershell
uv run manimagent doctor --animation
uv run manimagent answer --question "求材料中的投影" --file notes.pdf --output answer.md
uv run manimagent lesson --question "给定 a=(3,2)、b=(2,0)，解释并计算正交投影" --output lesson.mp4
uv run manimagent video --answer-id answer_<已有ID> --output lesson.mp4
```

`--file` 可重复，`--text` 可提供补充材料。CLI 文件默认全文解析，PDF 范围通过网页或 API 指定。`--config` 放在子命令前；配置中的相对路径按配置文件目录解释。`lesson` 保存同名 Markdown，动画失败时正文仍保留。旧 `generate`、`smoke` 和 `--text-only` 不属于当前 CLI。

本轮未新增 CLI 记忆选项；新任务的用户记忆通过网页或 HTTP API 开启。CLI `video` 使用已有 Answer 时仍继承该 Answer 保存的快照，不重新读取当前记忆。

## 输入与结果

附件选择支持多次追加、移除单个文件、检查格式与大小；展开“支持的格式与限制”可查看服务实际支持的扩展名和限制。可直接输入问题，也可只上传材料并使用默认讲解指令。文件名、摘要与块位置保持可追溯；完整 Answer 保存为原始 Markdown，网页仅派生安全展示。

结果默认展示解答与动画。需要核对依据时，展开解答下的“来源与详情”→“材料与来源”；记忆快照和“高级 · 运行与检查记录”也位于此处。动画的分辨率、帧率、节拍与计划链接在“动画详情”中，下载与播放仍直接显示。

| 材料 | 当前读取方式与边界 |
|---|---|
| TXT、Markdown、代码、日志、LaTeX、配置文件 | UTF-8 文本读取；代码和命令只作为材料，不执行。Markdown 图片链接不等于图片已读取 |
| CSV、TSV、JSON、JSONL、NDJSON | 按行保留数据和来源；CSV 空列保留，JSON 类校验格式 |
| Jupyter IPYNB | 读取单元源码与文字输出，不运行单元；图像输出／附件仍需另存为图片读取 |
| PDF | 可选择起止页，页码从 1 开始且包含两端。正常文字页本地解析；扫描、题图、绘图或文字映射异常的页面栅格化后交给视觉读取模型；空白／无法核对的页面不会静默跳过 |
| DOCX | 段落、表格、可转写的基础公式与上下标；嵌入图片交视觉读取；无法可靠表达的特殊对象进入待核对 |
| XLSX | 按工作表和单元格定位，保留公式及文件内已存计算缓存；不会重算公式。缺少必要缓存、外链、图片或图表会提示核对，可另存 CSV／PDF／截图 |
| PPTX | 读取文字、表格与讲者备注，可选择幻灯片范围；图片可交视觉读取。图表、SmartArt、形状连线与完整布局需要另存 PDF 或截图 |
| PNG、JPEG、WEBP、静态 GIF、BMP、TIFF | 经解码、尺寸限制与归一化后发送给视觉模型；多帧图像拒绝，需先拆成静态文件 |

图片与视觉页会发送给所选核心 API 的 `material_reader`，需要服务支持 `image_url`，并明确勾选视觉能力；这不是本地离线 OCR。视觉识读存在误读，来源标记为未人工核验并带警告；模型报告不确定时保留诊断、要求核对，不发布完整回答。上传成功不等于文件全部内容已正确解析。

旧 `.doc/.ppt/.xls` 请另存现代格式，ZIP 请解压后选择文件，音视频请先提供转录文本。不运行笔记本、宏或源代码，不具备 Codex 所有本机应用／任意二进制操作能力。损坏、加密、空文件和必要条件缺失仍要求补充；超预算不截断，不把不完整候选发布成完整 Answer。

默认按问题、材料与本次指令生成；网页或 API 显式开启记忆后，使用有界的用户记忆上下文，当前要求优先。动画消费已保存的同版 Answer 及其记忆快照，不再次解题。MiMo 开启后用实测旁白长度安排节拍，但节拍内高亮仍是估计，尚未实现词级同步。

记忆在提交时固定。勾选“记住新的偏好”后，结果发布才进行后台提取，新偏好用于后续任务；后台单次最多调用模型一次，默认 20 秒和 16000 token 独立上限，失败不自动重试。`memory_learning_timeout`（不超过 20 秒）、`memory_learning_max_tokens` 与 `memory_policy` 可在 YAML 配置，示例见 `config.example.yaml`。策略默认 3 个独立会话支持后晋升、近期有效期 14 天。主任务 `usage` 不包含后台调用；后台任务保存累计用量与每次尝试，不应把两者混成同一份生成用量。

## 数据与限额

默认 `runs_dir=runs/current`、`private_dir=runs_dir/private`。原件、材料、回答、任务、视频、配置及 `memory.sqlite3` 保存在该私有目录。API Key 单独保存，Windows 使用当前用户 DPAPI；该目录不提交 Git、不进入发布包。

可读记忆目录为 `private_dir/memory/`：`MEMORY.md` 是索引，`entries/<memory_id>.md` 保存独立条目的内容和证据，`snapshots/<job_id>.md` 保存任务冻结快照及请求中的记忆投影。路径随 `private_dir` 变化，无需单独配置。SQLite 仍是生效状态的提交依据；直接编辑文件不会立即影响生成，需要在网页或 API 显式导入并通过版本校验。自动同步保留已检测到的未导入改动；外部编辑器不共享服务的锁，应保存完成后再刷新和导入，避免同时修改同一文件。

删除记忆不自动擦除历史生成产物、任务 Markdown 快照或已修改的本地文件。同步失败时数据库中已提交的操作仍有效，可在界面查看状态并重试同步。目录、操作和完整边界见[记忆文件与受控编辑](用户记忆与个性化.md#记忆文件与受控编辑)。

解析默认单文件 20 MiB、每次最多 20 个输入项（问题和补充文本也分别占一项）、PDF／PPTX 最多 100 页、XLSX 最多 100 个工作表、总文字 200000 字符。Office 压缩包展开默认 50 MiB／2000 条目；单次本地解析 60 秒。每任务最多 12 张视觉图片／页面，单图最多 2500 万像素，发送前长边缩放至最多 2000 像素；超限需选页或分批。服务实际限制由附件区域展示，不以扩展名判断内容必然可读。

回答上下文默认 24000 token（包含输出预留），与模型 `context_window` 取较小值。动画预算见[实现说明](动画实现与本地运行.md)，生产目标见[验收设计](../design/动画时长与生产验收.md)，两者不能混写为已达到的性能。

每个私有目录只允许一个服务进程持有写入权。重启不自动重跑付费任务；未完成任务标为 `interrupted`，已有文字的双输出保留为 `partial`，完整结果仍可读取。当前面向本机单用户，没有公开部署需要的认证和租户隔离。
