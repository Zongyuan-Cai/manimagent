# 第二阶段 完整视听讲解

状态：设计草案

本阶段在基础动画上加入学习材料解析与配音，使内容来源、讲解步骤、画面、语音和字幕保持对应。依赖第一阶段已经可用的场景生成与检查模块。

上传、解析、回答与视频按独立模块组织，公共契约和后续 API 以[模块解耦与接口设计](../模块解耦与接口设计.md)为准。该接口设计更新于2026年10月23日，尚未实现。

## 目标与边界

支持纯文本、文本型 PDF 与 DOCX 中的题目或学习内容，先形成可独立阅读的回答，按需转换为连贯的视听讲解。解析模块根据适配器能力选择原生文件输入或本地解析，统一输出带来源的 MaterialIR。优先处理可可靠解析的材料；扫描件和复杂手写内容按需要扩展。

教学规划仍依据当前材料和本次要求。学习者历史与个性化决策在第三、四阶段引入。

## 输入与输出

| 类型 | 内容 |
|---|---|
| 输入 | 学习材料、选定讲解范围、本次要求、语音配置 |
| 中间结果 | FileAsset、带来源的 MaterialIR、可独立保存的 Answer、视频内部规划、讲稿、音频片段、Timeline |
| 输出 | 可单独获取的回答，以及按需生成的配音字幕视频、来源索引、步骤与音画对应清单 |

## 核心流程

上传并保存原件 → 材料解析与来源定位 → 独立回答生成与保存 → 按需发起视频生成。视频模块内部完成场景规划、分步讲稿、TTS 与时长测量、动画事件安排、场景渲染与检查、音画合成。

每一步通过不可变结果 ID 引用上游。解析策略或回答模型可以独立更换，视频失败后复用原回答重试；用户也可以在获得回答后结束。

## 模块与关键设计

| 模块 | 职责 |
|---|---|
| FileStorage | 独立保存上传原件与元信息，不依赖模型和渲染环境 |
| MaterialParser | 封装原生文件与本地解析路径，提取文本、公式或相关图像，保留页码或段落位置 |
| AnswerGenerator | 根据材料和本次要求产出可独立阅读的 Answer，供直接展示或视频生成使用 |
| VideoGenerator | 消费确定版本的 Answer，封装场景规划、讲稿、渲染检查和合成 |
| NarrationPlanner | 根据讲解步骤生成与画面一致的讲稿 |
| SpeechProvider | 合成语音，返回实际时长与可用边界 |
| TimelineBuilder | 将步骤、音频范围、动画事件和字幕关联 |
| AVAssembler | 合成片段，并检查时长、顺序与字幕偏移 |

使用稳定的 step_id 关联视觉步骤、讲稿句子、音频和字幕。先获取实际音频时长，再安排动画节奏；动作过多时增加停顿或调整讲稿。

视频内部步骤保留对 Answer.step_id 的映射。可以调整视觉表达，但不能静默修改回答的题设和结论；发现内容问题时返回待核对信息，修订后的回答另存为新版本。

数学表达分别保存展示公式与朗读文本，并记录二者关系。解析不确定的公式保留来源位置或原图供检查，不能将低置信度识别结果直接视为正确内容。

VLM 继续负责画面检查，时间线规则负责音画对应。语音变化后，相关时间线与视频需重新验证。

## 技术与依赖

在第一阶段基础上引入文档解析、TTS 适配器和 Timeline 数据契约。解析和语音服务可以替换，业务流程不绑定单一厂商。产物仍可保存在本地，按内容与配置版本建立复用关系。

## 验收与交付

选择文本、PDF 和 DOCX 样例检查来源完整性、公式显示与朗读、讲稿覆盖和关键事件的音画对应。对无时间戳的语音服务，验证按句合成与时长测量的回退方案。

同时验证上传不依赖模型、回答不依赖渲染环境、不同解析路径符合相同契约，以及回答单独使用、回答编辑后再生成视频、视频重试复用回答和旧 MVP 接口兼容。

交付多材料输入、配音与字幕能力，以及时间线样例和视听测试记录。后续个性化规划继续产出相同的步骤结构，复用这一生成链路。
