# 第三阶段 长期学习记忆

状态：设计草案

本阶段建立学习者知识状态的跨会话保存、更新、检索与纠正机制，为下一阶段的个性化规划提供有依据的教学上下文。

## 目标与边界

管理知识点及关系、学习事件、掌握估计、历史错误和表达偏好。记忆需要区分观测事实与模型推断，保留来源，并表达不确定性。

可先使用模拟答题、追问和反馈驱动记忆模块，无需等待完整 Web。通用生成经验库属于可选优化，不能替代学习者长期记忆。

## 输入与输出

| 类型 | 内容 |
|---|---|
| 输入 | 学习者标识、答题或交互事件、知识点关联、已有状态、显式纠正 |
| 中间结果 | 候选学习证据、证据与概念关系、状态更新提案、变更记录 |
| 输出 | 当前知识状态、相关记忆摘要、记忆快照与证据引用 |

## 核心流程

学习事件 → 知识点对齐与候选证据提取 → 来源校验与去重 → 冲突处理 → 状态更新 → 检索相关记忆。

## 模块与关键设计

| 模块 | 职责 |
|---|---|
| ConceptRegistry | 管理有限领域的知识点、别名与先修关系 |
| EventStore | 记录交互、答题、反馈与纠正事件 |
| EvidenceExtractor | 从事件中提取候选证据，不直接决定最终状态 |
| StateUpdater | 依据有效证据更新估计、置信度和待核验状态 |
| MemoryRetriever | 返回当前内容及其先修知识相关的个人记忆 |
| RevisionManager | 撤销、更正或替代证据，重新计算相关状态 |

原始事件、有效证据和派生状态分开保存。一条提问不能直接判定未掌握，观看视频也不能直接判定掌握；偏好反馈只更新相应偏好。多个来源矛盾时保留待核验状态。

掌握估计与估计置信度分别记录。初期可用明确规则更新，待数据充分再评估知识追踪模型；未经校准的数值不称为真实掌握概率。

每次检索绑定学习者和状态版本，产出 MemorySnapshot。更新应能去重，纠正后应使旧证据失效，后续查询不再按旧结论规划。所有访问由服务端限定用户范围。

## 技术与依赖

在此阶段引入 PostgreSQL，使用关系表维护概念关系。有语义检索需求时再接入 pgvector 与多语言嵌入模型，记录模型版本和维度。API 与更新规则独立于生成模块。

## 验收与交付

使用连续模拟记录检查首次学习、多次答题、矛盾反馈、显式纠正、重复事件和跨会话恢复。重点验证证据追溯、状态变化、用户隔离与检索相关性。

交付数据模型、更新与检索接口、模拟学习历史和记忆正确性报告。此阶段可证明记忆机制工作，尚不证明个性化讲解或真实学习效果。
