# 第五阶段 交互集成与局部更新

状态：设计草案

本阶段将材料、生成、记忆和个性化规划联通成可持续使用的 Web 系统，并支持针对片段的补充、重讲和修改。

## 目标与边界

形成“材料输入 → 个性化讲解 → 用户交互 → 学习证据 → 记忆更新 → 后续讲解”的完整闭环。前期简单页面升级为材料、播放交互与学习记忆视图。

优先满足单个学习者连续使用和必要的数据隔离。复杂教学管理、实时协作等不属于申报书原型的必要目标。

## 输入与输出

| 类型 | 内容 |
|---|---|
| 输入 | 材料、任务要求、用户身份、关联步骤的追问、反馈、记忆纠正或局部修改请求 |
| 中间结果 | 任务事件、学习事件、状态版本、片段依赖与重建计划 |
| 输出 | 播放与交互页面、更新后的学习状态、新讲解或替换片段、完整运行记录 |

## 核心模块

| 模块 | 职责 |
|---|---|
| Web 与 API | 材料提交、状态查询、视频播放、追问、反馈和记忆查看 |
| TaskService | 管理任务状态、重试与取消，将长任务交给后台执行 |
| FeedbackRouter | 区分内容追问、呈现偏好、学习证据和记忆纠正 |
| MemoryIntegration | 校验并写入学习事件，为下一轮规划提供相关状态 |
| RevisionService | 确定需要修改的步骤与场景，协调片段重建和检查 |
| ArtifactStore | 保存不可变的候选版本、依赖关系和合成清单 |

## 交互与数据流

追问、反馈绑定 lesson_id、scene_id 或 step_id，说明它针对哪次讲解。交互分类后进入相应处理流程：布局或语速问题用于呈现调整，明确答题表现可形成学习证据，用户纠正触发证据修订。

用户可以查看与纠正知识状态的来源。后台校验状态更新，不能把所有反馈都转成掌握变化。事件去重，任务重试不能重复更新学习记忆。

任务状态由后端维护并通过 SSE 等方式推送。基本状态覆盖等待、规划、生成、检查、合成、完成、待检查、失败与取消。

## 局部更新

将场景作为主要重建单位，保留规划、讲稿、音频、时间线、代码和视频之间的依赖。修改讲稿需要重建对应音频和时间线；只改布局可复用音频，但仍要检查时长与画面。

优先设计自包含的场景边界。符号、教学目标或跨场景状态变化时，应扩大重建范围。新结果通过检查后再替换合成清单，保留旧版本用于回溯；缓存按学习者、内容与相关版本隔离。

## 技术与依赖

采用 FastAPI、React 与持久化任务记录，复用第三阶段数据库。初期可继续使用单 Worker；只有并发和恢复需求明确时，再引入专用队列服务。渲染仍在独立环境执行。

## 验收与交付

完整演示材料输入、播放、追问、反馈回写、跨会话再次生成与显式纠正。局部修改测试需同时确认新片段正确，以及其他片段确实复用。检查用户隔离、重复事件、任务取消和部分失败时的结果一致性。

交付可运行 Web 原型、部署与使用说明、接口说明、完整交互样例，以及局部修改的耗时与复用记录。
