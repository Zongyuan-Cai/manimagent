# 正式动画阶段：实现与本地运行

更新：2026-10-30。当前版本 0.3.0，接入已有文字链路；本阶段无声音合成。

实现依据为[动画 Pipeline](04-动画生成.md)、[Prompt 与检查规范](动画Prompt与检查规范.md)和[时长与生产验收](动画时长与生产验收.md)。原设计中的自由代码和容器执行没有启用。鉴于当前机器不能使用 Docker，本版采用可信的本地 Manim 模板，模型只生成受约束的 JSON。禁止将该本地进程执行方式直接用于任意模型生成的 Python。

## 实际链路

1. 固定已有 Answer 与 SHA-256。有效内容检查回执必须同时匹配正文摘要和检查策略；关闭过内容检查或人工修订的答案会补检。
2. 按正文 Unicode 码点半开区间建立 TeachingUnit，不切开围栏代码和独立公式。各单元保留原文与摘要；不修改正文。
3. `video_planner` 一次规划整体场景、受众假设、难度与时长理由、每场景承接单元。支持 3～8 个自包含场景，全片最多 42 个节拍。
4. `scene_generator` 按大纲逐块输出：屏幕解释、短公式、完整图形状态、旁白稿、语义 cue 和阅读理由。每块独立保存，可在后续请求中复用已验证版本的分块。
5. 服务器估算旁白与阅读时间，解析事件顺序；总长必须在 120～360 秒，单个节拍不超过 24 秒。重复内容、覆盖缺失、越界对象和不存在的 cue 对象均被拒绝。时长不合格时，在共享的两次修复额度内局部重新生成，不加空等、不整体降速。
6. `plan_checker` 对照完整正文与所有分块逐单元核验覆盖、数学含义、图形参数和无声解释。任何必需项 fail／unknown 均阻止发布；不能拿平均分抵消。
7. 可信渲染子进程执行项目自带的固定 Manim 程序；公式由 MathText 转 SVG，不调用外部 LaTeX。逐节拍记录实际出现、稳定阅读与结束区间，抽取原尺寸关键帧，核验场景实测时长。
8. 按场景顺序无重编码拼接，完整解码 H.264／yuv420p、1280×720／30 fps 成片；检查无音频、时长、帧数、时间戳与连接点，再保存不可变 VideoResult。

`both` 请求先发布正文，再继续动画。动画失败时 Generation 和 Job 为 `partial`，原 Answer 保留；`POST /videos` 只重新生成视频，不调用 writer。独立视频任务失败会返回自身错误，而不会改变原答案。

## 当前表达范围

模板提供公式逐步推导、二维向量／点／线段／虚线／多边形／圆、至多 4×4 的数值矩阵。坐标图采用相同横纵单位比例，图例避让；无图节拍使用完整宽度的公式区域和中文解释。所有内容带安全边距，文字过密时失败，不无限缩小字体。

暂不支持任意 Python、任意外部素材、三维、复杂 LaTeX 环境或公式程序求值。超出模板的必要表达应返回范围问题，不能为了适应模板删去问题。MathText 使用 ASCII 数学语法（如 `\frac`、`\mathbf`、`\cdot`），中文放普通文本；矩阵用专门数据结构。

本版不接入视觉模型。公开结果明确保存 `visual_model_review: not_run`，检查模式为 `trusted_template_geometry_and_layout`。模型检查针对计划语义，固定模板的几何、文字边界与媒体由程序核验，关键帧供人工复核；这些证据不能扩称为任意视频的完整视觉检查。

## 无 Docker 安装

```powershell
uv sync --frozen --extra dev --extra animation
uv run manimagent doctor --animation
uv run manimagent serve
```

需要 Python 3.12；Windows 使用 Microsoft YaHei／SimHei，Linux 可安装 Noto Sans CJK SC，或配置 `video_font`。渲染依赖作为 `animation` 可选项，纯文字安装继续可用。Manim 固定 0.20.1、PyAV 固定 15.1.0，FFmpeg 使用 imageio-ffmpeg 自带程序，不依赖系统 PATH 中的 FFmpeg、Docker 或 LaTeX。安装机制参考 [Manim 官方本地安装说明](https://docs.manim.community/en/stable/installation/windows.html)和 [PyAV 官方安装说明](https://github.com/PyAV-Org/PyAV/blob/master/docs/overview/installation.rst)。

当前机器的 PyAV 19 所带硬件相关 DLL 被系统应用控制阻止；15.1.0 的官方 wheel 与 Manim 要求兼容且实际导入／渲染通过。本项目没有修改系统应用控制策略或解锁被阻止的 DLL。

桌面交付目录可双击 `start.cmd`，在本地浏览器中使用。首次安装后的其他机器需要自行填写 LLM 配置；源码压缩包不含任何凭据或运行数据库。

```powershell
uv run manimagent lesson --question "给定 a=(3,2)、b=(2,0)，解释并计算正交投影，验证残差正交" --output lesson.mp4
uv run manimagent video --answer-id answer_<已有ID> --output lesson.mp4
```

`lesson` 同时保存同名 Markdown；视频失败时已生成的 Markdown 仍保存。模型配置仍通过原 LLM 配置界面管理，增加规划、分块生成、计划检查三项角色；未显式绑定时分别继承回答／检查角色。

对已验证支持 DeepSeek `thinking` 参数的连接，可在高级设置选择 `disabled`，避免结构化检查把输出额度全部用在推理 token 上。默认配置不发送该厂商扩展，不假定每种 Chat 兼容服务都支持。

## API 与复用

```json
{"output_mode":"both","source":{"type":"inputs","instruction":"完整解释题目","inputs":[{"type":"text","text":"题目内容"}]}}
```

以上提交到 `POST /api/v2/generations`。默认未填写 output_mode 的旧客户端仍生成文字。另有：

| 操作 | 路径 |
|---|---|
| 只生成视频 | `POST /api/v2/videos`，`{answer_id, video_profile_id?: "standard_silent", resume_job_id?}` |
| 任务／进度 | `GET /api/v2/jobs/{job_id}` |
| 结果／计划 | `GET /api/v2/videos/{video_id}`、`/{video_id}/plan` |
| 播放／下载 | `GET /api/v2/videos/{video_id}/content`，支持 Range；`?download=true` 下载 |
| 逐节拍证据 | `GET /api/v2/videos/{video_id}/frames/{index}` |

`resume_job_id` 复用相同 answer_id、正文摘要和兼容提示词版本的整体大纲／分块；重新计算时间、重新检查计划并重新渲染。新回答版本不能引用旧分块。当前没有跨候选复用媒体缓存，也不复用旧像素检查报告。分块在任务记录中按场景保存，未完成结果不会伪造为正式 VideoResult。

## 预算与执行边界

动画请求从受理计整体 900 秒硬限，排队 120 秒，视频阶段 600 秒；单模型等待至多 60 秒，单场景渲染 90 秒，全视频最多 24 次模型调用。额外模型重试全阶段最多一次，局部生成修复最多两次；所有成本计入父预算。串行渲染，不在未测量前启用多场景并发。

原生渲染进程使用环境变量白名单，不接收模型密钥、代理凭据或 `.env`。只读取服务器生成的 JSON 和自身创建的素材；宿主监测内存、deadline 与停机事件，超限终止进程树。它是受约束本地执行，并非操作系统容器隔离；任意代码后端仍需独立安全执行边界。

旁白稿、语义 cue、对象和事件现在就共同排程，但 `time_source` 始终为 `estimated`。无音频、无字幕文件，不宣称已验证实际音画同步。后续接入 TTS 时应替换时间解析层的边界来源，保持 Answer、单元、旁白和画面事件的版本关系。
