# 材料输入与解析

更新日期：2026年10月29日

状态：独立上传、材料解析及本节 `/api/v2` 尚未实现。当前 0.1.0 仅接收纯文本，输入校验基线见 [动画生成](04-动画生成.md)。公共版本、引用、任务和错误规则见 [文档总览](index.md)。

本文是文件上传与材料解析的正式设计，维护基本架构、公共契约、组件接口、存储、解析路由、质量检查和验收。回答时的材料选取与上下文组装由 [文本回答生成](03-文本回答生成.md) 维护。开源实现的逐项目比较保留在 [调研记录](research/开源Agent文件上传与LLM输入调研.md)，具体实现依据在本文对应细节旁引用。

## 1 职责与边界

本模块接收直接文本或用户文件，独立保存原件，选择解析路径并产出带来源的 MaterialIR。上传与解析可以分别执行、查看和重试。解析提取材料内容与结构，回答中的内容选取和教学组织由 [文本回答生成](03-文本回答生成.md) 负责。

| 操作 | 输入 | 输出 | 依赖 |
|---|---|---|---|
| 上传原件 | 文件字节、文件名和媒体类型 | FileAsset | 文件存储 |
| 解析文本 | 直接文本、解析配置 | MaterialIR | 文本规范化 |
| 解析文件 | FileAsset 引用、范围和解析配置 | MaterialIR | 选定解析器；模型读取路径按需依赖 LLM |

用户向本系统上传原件，与向模型提供商准备临时文件分别处理。模型连接、协议、鉴权、远端文件生命周期和能力证据由 [LLM 接入与调用](01-LLM接入与调用.md) 维护；本模块决定本次材料的解析路由和覆盖要求。替换解析器或提供商后，下游仍接收同一种 MaterialIR。

### 基本设计

以下三个决定分别维护，避免某种存储或解析方式限制后续回答：

| 决定 | 负责组件 | 本项目设计 |
|---|---|---|
| 原件存在哪里 | FileStore | 首版本地保存，存储键由服务端生成，外部只使用 file_id |
| 原件如何转换成材料 | MaterialService、ParserRegistry、LLM 适配层 | 选择应用解析器或原生文件输入，统一产出 MaterialIR |
| 模型回答时读取哪些内容 | 回答模块的 ContextAssembler | 近期完整注入指定材料，后续扩展内容块选取、检索和工具读取 |

首版面向直接文本、文本型 PDF 和 DOCX。纯文本、段落、表格、公式候选与图示分别保留；超出已实现解析能力时明确报告。扫描件、复杂公式识别、独立图片、PPTX 和音视频按后续阶段接入，不因开放上传入口就宣称已经支持解析。

本系统先保存可独立读取的 MaterialIR，再生成 Answer。原生文件输入同样承担材料提取职责，不能绕过材料保存直接把厂商会话作为后续回答的唯一来源。解析结果可以供多个问题与不同提供商复用。

这种职责划分参考 [Dify 的独立文件上传服务](https://github.com/langgenius/dify/blob/70975c1873aeab9e80ffcf5b2fec3796eda77059/api/services/file_service.py#L74-L168)和 [Document Extractor 的文本输出](https://docs.dify.ai/en/cloud/use-dify/nodes/doc-extractor)。本项目进一步保留内容块、页码与原图资产，以满足数学题设和来源追溯要求。

## 2 处理流程

连接、模型绑定、角色配置、能力证据及调用适配接口详见 [LLM 接入与调用](01-LLM接入与调用.md)。文件解析回退由本模块约束；调用重试与跨提供商切换分别在 LLM 接入层处理。

解析模块维护本地解析器注册表，通过 LLM 模块使用协议适配器与能力记录。能力判断依据服务地址或适配器、API 类型、模型、文件格式、大小与页数限制，以及是否需要识别图片或图表。能力规则由适配器配置维护，记录规则版本，不写死在上传接口或视频模块中。

| 模式 | 行为 |
|---|---|
| auto | 已确认满足本次读取要求时使用原生文件输入，否则选择可用的本地解析路径 |
| native | 强制原生文件输入；未知或不支持时明确返回能力问题 |
| local | 强制使用应用自行组织的解析器，OCR 等识别组件按解析配置选择 |

自定义服务地址能力未知时，auto 默认选择本地解析；用户可通过服务端解析配置声明并验证其能力。local 控制解析路径，具体 OCR 或其他识别服务的使用由 parser_profile_id 对应配置明确声明。

```text
上传路径：文件流 → FileStore → FileAsset

解析路径：ParseRequest
  → 校验引用与选择范围，固定解析配置快照
  → 建立输入清单与来源定位
  → 根据格式、内容要求和能力选择解析器
      → 应用解析器：文字、段落、表格、页图，按配置补充识别
      → 原生文件输入：LLM 适配器编码或准备远端引用，模型提取
  → 归一化 MaterialBlock，登记派生资产
  → 核对来源、处理范围与关键内容歧义
  → 原子保存 MaterialIR，Job 返回 material_id

回答路径：MaterialIR → ContextAssembler → Answer → 按需生成动画
```

原生路径可以要求模型输出结构化提取结果，但厂商返回的内容必须经过本系统校验和资产登记后才能成为 MaterialIR。不能只传出厂商 file_id 或依赖其会话继续存在。

auto 模式下，仅在适配器明确识别为当前文件输入能力不支持时回退。鉴权、配额和计费问题直接报告；超时与限流按固定预算重试；结构错误或内容不完整进入相应的校验失败或待核对状态。不得将所有 HTTP 400 或所有异常一律视为文件能力不支持。失败尝试、回退调用及模型使用量累计计入本阶段预算。

本地解析也必须满足本次读取要求。扫描件、图片或复杂公式需要 OCR 或其他识别能力时，通过可替换解析组件处理；缺少能力则给出提示。外部 OCR 或视觉模型调用需要由解析配置显式启用，原生与本地均失败时不提交缺失内容的成功结果。

解析与回答可以各自选择模型厂商。公开请求只携带 profile_id，厂商配置和密钥由服务端解析；所有厂商文件上传、格式转换与回退记录留在解析任务内部。

## 3 输入输出

```text
upload_file(stream, filename, media_type) -> FileAsset
parse_material(request: ParseRequest) -> MaterialIR
```

文件流只进入上传接口，解析请求使用结果 ID 或直接文本，不接受任意宿主路径。

直接文本的原文作为解析执行记录的一部分持久化，来源使用 input_index 和行号关联；不会为了取得来源而伪造 file_id。文件与直接文本均按 inputs 顺序生成内容块。

### FileAsset

FileAsset 同时用于上传原件和登记派生文件。文件上传成功仅表示原件已保存，不表示能够解析。

| 字段 | 类型 | 规则 |
|---|---|---|
| schema_version | string | 必填，`"1.0"` |
| file_id | string | 必填，资产标识 |
| filename | string | 必填，用于展示，不作为存储路径 |
| media_type | string | 必填，服务端确认的媒体类型 |
| size_bytes | integer | 必填，非负字节数 |
| sha256 | string | 必填，文件内容摘要，用于完整性与复用判断 |
| created_at | string | 必填，登记时间 |

下载使用 `GET /api/v2/files/{file_id}/content`，无需在结果中保存可能过期的外部链接。

### MaterialIR

本文统一使用 `MaterialIR` 表示解析结果，作为下游回答模块的统一输入。一个解析请求产出一个 MaterialIR；多个文件在其中分别保留来源。

| 字段 | 类型 | 规则 |
|---|---|---|
| schema_version | string | 必填，`"1.0"` |
| material_id | string | 必填，不可变解析结果标识 |
| source_file_ids | string[] | 必填；直接文本输入时为空 |
| blocks | MaterialBlock[] | 必填，按材料内阅读顺序组织，至少一个内容块 |
| warnings | Notice[] | 必填；记录缺失、不确定或未覆盖内容 |
| created_at | string | 必填，结果创建时间 |

MaterialBlock 的公共字段：

| 字段 | 类型 | 规则 |
|---|---|---|
| block_id | string | 必填，在 MaterialIR 内唯一 |
| kind | enum | `heading`、`text`、`formula`、`table`、`image` |
| content | string | 必填；标题或正文为文本，公式为 LaTeX，表格为 Markdown，图片为描述；无可靠识别内容时允许为空 |
| asset_ids | string[] | 必填；关联原图或裁剪图等本系统资产 |
| source | SourceLocation | 必填，定义见下文 |
| review_state | enum | `unverified`、`verified`、`needs_review`；默认 `unverified` |

SourceLocation 包含 `input_index`（对应 ParseRequest.inputs 中从 0 开始的位置）、`file_id`（直接文本输入为 `null`）、`locator` 和 `verification`。`locator` 为可空对象，可包含从 1 开始的 `page`、`slide`、`paragraph`、`line_start`、`line_end`，或非负的 `start_seconds`、`end_seconds`；只填写适用于该来源的字段。`verification` 为 `verified`、`unverified` 或 `unavailable`，区分可靠定位、模型给出的待核对定位和无法定位。

Notice 统一为 `{code, message, block_ids}`；无法关联到特定块时 `block_ids` 为 `[]`。`review_state` 记录内容核对情况，来源的 `verification` 仅记录位置可靠性，两者独立。模型成功返回 JSON 本身不能使内容变成 `verified`。

解析记录保留选择范围及覆盖情况。处理预算不足时不得静默截断；关键区域缺失或关键公式存在歧义时，任务进入 `needs_input` 或 `needs_review`，尚未完成的解析结果不作为成功结果供回答模块消费。

### ParseRequest

| 字段 | 类型 | 规则 |
|---|---|---|
| inputs | ParseInput[] | 必填，至少一个，数组顺序表示材料顺序 |
| parser_profile_id | string \| null | 可选，默认 `null`，使用应用默认解析配置 |
| input_mode | enum | 可选，默认 `auto`；支持 `auto`、`native`、`local` |

ParseInput 是带 type 的互斥联合：

- 文件：`{type: "file", file_id, selection}`；selection 可省略，默认全文。支持 `{kind: "pages", start, end}` 或 `{kind: "slides", start, end}`，范围从 1 开始且包含两端，必须与实际文件类型匹配。
- 文本：`{type: "text", text}`；text 必须非空，保存原始文本供来源核对，按同一 MaterialIR 输出。

首版未提供范围选择的格式按全文处理，超出预算时提示缩小材料。不得声称支持尚未实现的任意区域或时间段选择。

input_mode 只控制文件输入；直接文本输入始终走文本规范化，不因 native 或 local 模式被拒绝。

### 后续 HTTP 接口

以下端点均待实现。Job 与 Error 使用 [总览中的公共规则](index.md)。

| 方法与路径 | 请求 | 成功响应 |
|---|---|---|
| POST /api/v2/files | multipart/form-data，单个 file | 201，FileAsset |
| GET /api/v2/files/{file_id} | 无 | 200，FileAsset |
| GET /api/v2/files/{file_id}/content | 无 | 200，文件内容 |
| POST /api/v2/materials/parse | ParseRequest JSON | 202，Job |
| GET /api/v2/materials/{material_id} | 无 | 200，MaterialIR |

多文件分别上传取得 file_id，再放入同一个 ParseRequest。示例 ID 为占位值：

```json
{
  "inputs": [{"type": "file", "file_id": "file_demo", "selection": {"kind": "pages", "start": 12, "end": 14}}],
  "parser_profile_id": "parser_default",
  "input_mode": "auto"
}
```

完成后的 Job 返回 `result: {"type": "material", "id": "material_demo"}`，供读取或独立发起回答任务。

## 4 实现方案

### 组件和内部接口

| 组件 | 职责 | 主要输出 |
|---|---|---|
| FileStore | 保存、读取原件及派生资产，校验元数据与可访问性 | FileAsset、内部文件流 |
| MaterialService | 固定配置、校验请求、编排解析与提交结果 | MaterialIR、执行记录 |
| ParserRegistry | 按格式、实现版本与读取要求查找已注册解析器 | ParserDescriptor |
| MaterialParser | 执行特定格式的内容提取，报告范围和限制 | ParseCandidate |
| MaterialValidator | 检查结构、来源引用、覆盖范围和关键歧义 | 可提交结果或待处理问题 |
| MaterialRepository | 不可变保存与读取材料 | material_id 对应的 MaterialIR |

```text
FileStore.put(stream, upload_policy) -> FileAsset
FileStore.get(file_id, access_context) -> FileAsset
FileStore.open(file_id, access_context) -> BinaryStream

ParserRegistry.resolve(input_descriptor, requirements, profile_snapshot) -> MaterialParser
MaterialParser.parse(parse_context) -> ParseCandidate
MaterialValidator.validate(candidate, input_inventory) -> ValidationResult
MaterialRepository.save(material, parse_record) -> material_id
```

这些是内部逻辑接口，不接收客户端任意路径或可执行解析脚本。ParseCandidate 包含候选内容块、派生资产、逐输入处理范围、警告及使用量；它不是可供回答模块消费的成功结果。MaterialService 完成校验和持久化后才更新 Job.result。

ParserDescriptor 至少包含 parser_id、实现版本、支持格式、可保留的内容类型、可用的来源定位及依赖。选择依据包括本次材料是否要求图示、公式或扫描文字，不能只有扩展名匹配。格式分派参考 [Graphon 的文档解析入口](https://github.com/langgenius/graphon/blob/4fa22141774dff80e90e4dfa98ea3e6fbf0421bb/src/graphon/nodes/document_extractor/node.py#L759-L781)；本项目增加输出能力和覆盖校验。

建议在现有 Python 包中增加 `files.py`、`materials.py`、`parsers/`，Pydantic 契约在 `schemas.py` 中维护；回答模块的 `context.py` 消费 MaterialIR。API 依赖具体阶段服务，上传接口不调用当前动画引擎的完整 readiness 检查。

### 上传和原件存储

首版使用可配置的私有存储根目录，默认组织在 `data/private/` 下：

```text
files/<file_id>/content            原件或派生文件
files/<file_id>/metadata.json      FileAsset 与内部存储元数据
materials/<material_id>.json       不可变 MaterialIR
parse-runs/<job_id>/record.json    配置快照、输入清单、覆盖和尝试记录
```

FileAsset 只公开第 3 节字段；内部记录另保存存储键、来源资产关系和访问作用域。使用 file_id 生成目录，filename 只用于展示和下载。相同显示名允许对应不同资产，内容摘要相同也不能跳过访问检查。

上传按以下顺序执行：

1. 检查请求媒体类型、文件数量和接收上限；单请求只接收一个文件。
2. 流式写入受控临时文件，累计实际字节数和 SHA-256；超过上限立即停止，清理本次临时数据并返回 413，不依赖客户端 Content-Length。
3. 结合格式特征与容器结构确认媒体类型；后缀和浏览器 MIME 仅作线索。无法归入已接受类型时返回 415；已接受容器损坏则在解析时报告格式问题。
4. 完成文件写入并保存元数据，以临时文件和原子替换提交；文件和元数据均可读后返回 201。文件落盘后元数据提交失败时，清理本次未发布资产；中断遗留的临时资产通过受控维护任务回收。

首版上传白名单与已声明的材料格式一致，派生页图通过内部登记接口保存。上传成功仅表示原件持久化，不调用模型，也不要求 Docker。大文件读取采用分段或文件流，避免无条件将所有附件读入内存。

生成存储键与原名分离参考 [Dify 的 UUID 存储及文件记录](https://github.com/langgenius/dify/blob/70975c1873aeab9e80ffcf5b2fec3796eda77059/api/services/file_service.py#L100-L168)。流式限额、SHA-256 和本地原子提交是本项目选择；Dify 该段实现接收 bytes，使用 SHA3-256，不能将其等同于本项目的上传实现。

### 解析配置

parser_profile_id 指向服务端 ParseProfile，任务接受时保存 revision 与完整快照。首版配置包含：

| 配置组 | 内容 | 行为 |
|---|---|---|
| 解析器 | 启用的 parser_id 与版本、逐格式选择顺序 | 只允许注册过的实现 |
| 处理上限 | 单文件字节、页数、解析时长、解压后大小与容器条目上限 | 每项有有限值，按服务端发布配置执行 |
| 识别扩展 | OCR、视觉识别是否启用及服务引用 | 默认关闭；启用外部服务时明确目标连接 |
| 原图保留 | 页图、内嵌图和裁剪图的范围及数量、像素预算 | 按来源关联资产，不能无限展开 |
| 质量要求 | 必需内容类型、覆盖要求、关键歧义处理 | 不能通过放宽配置伪造 verified 状态 |
| 原生解析 | parser 角色绑定、输出 schema、调用预算 | 与 LLM 能力记录共同决定是否可用 |

不在本设计固定通用文件大小或页数数字；部署配置必须给出实际上限，并以边界样例验证。DOCX 等压缩容器还检查展开规模和条目路径，解析不执行宏、嵌入脚本或外部链接。

### 格式和来源保留

| 输入 | 首版处理 | 来源规则和限制 |
|---|---|---|
| 直接文本、TXT、Markdown | 保留原文与换行，按标题或段落生成块；编码失败或无可靠解码时报告问题 | 行号从 1 开始；文本原貌与规范化结果分别保留 |
| 文本型 PDF | 逐页提取文字与内容块，记录页数、空文字页和识别限制；按配置保存页图 | page 从 1 开始，不能把所有页先拼成字符串再推测页码 |
| DOCX | 按文档阅读顺序遍历段落与表格，登记内嵌图；识别到不支持的公式或对象时发出警告 | 使用段落序号；表格、图片无法映射到现有定位字段时 locator 为 null，不能补造 Word 页码 |
| 扫描页、复杂公式和图示 | 由显式启用的 OCR 或视觉解析扩展处理 | 未提供相应能力时报告缺失，关键内容不完整则停止提交 |
| PPTX、独立图片、音视频 | 后续另加解析器与验收 | 未实现前明确拒绝相关解析请求 |

PDF 首批实现评估 `pypdfium2`，允许以 `pypdf` 作为文字提取补充；DOCX 采用 `python-docx` 遍历内容。依赖只在具体解析器实现并验收时加入锁文件。选择参考 [Graphon 的 PDF 提取](https://github.com/langgenius/graphon/blob/4fa22141774dff80e90e4dfa98ea3e6fbf0421bb/src/graphon/nodes/document_extractor/node.py#L508-L542)与 [DOCX 阅读顺序遍历](https://github.com/langgenius/graphon/blob/4fa22141774dff80e90e4dfa98ea3e6fbf0421bb/src/graphon/nodes/document_extractor/node.py#L648-L666)。其 PDF 输出会合并页文本，本项目在页级包装中保留位置。上述库名不构成公式或扫描件识别能力承诺。

公式从文本提取或模型识别得到 LaTeX 候选时，保留原文或页图供核对；不得因字符串可编译就将内容标为 verified。图示描述无法可靠表达标注、几何关系或坐标时保留原图并标出问题。来源位置的 verification 与内容的 review_state 分别检查。

### 原生文件解析

原生路径仍使用同一输入清单、选择范围和 MaterialIR schema。执行顺序为能力检查、准备文件或编码字节、等待可读取、结构化提取、登记派生资产、范围及内容校验。需要上传远端文件时调用 `prepare_file`；支持直接字节或内容块的端点由适配器编码，不强求所有提供商都有 Files API。

提供商内容块有不同字段，具体转换封装在适配层，参考 [LibreChat 的文档编码器](https://github.com/LibreChat-AI/LibreChat/blob/8d3da9bbb220a0a96be9330a2e1cbd385fb786d5/packages/api/src/files/encode/document.ts#L125-L235)。该源码展示了按协议构造内容块，本项目仍需对目标地址、模型和格式做实测，不能以协议兼容声明代替能力判断。

页码范围必须在请求实际执行时得到保证。提供商不能强制选择范围时，先生成并登记仅包含选定页的派生文件，内部保存“派生第几页到原件第几页”的映射；预算不足或当前转换未实现则返回问题。不能只在提示词中写“只读第 12 至 14 页”就声称其他页未发送。

模型报告的位置默认 unverified；只有与原件或派生映射匹配并完成核对后才提高位置可靠性。不能核对的定位保留 null 或 unverified。远端引用失效时可在剩余预算内从原件重新准备；鉴权、配额和内容缺失仍按各自原因处理。

### 覆盖记录与提交条件

内部 ParseRecord 保存 job_id、原始直接文本或文件引用、profile 快照、实现与规则版本、选择范围、各次尝试、实际路径、派生关系、使用量以及逐输入覆盖记录。覆盖记录包含：

| 字段 | 规则 |
|---|---|
| input_index | 指向 ParseRequest.inputs 中的位置 |
| requested_scope | 全文或请求指定的 pages、slides 范围 |
| unit_kind / total_units | 检查单位及总数；页、段落等按实际格式表达，未知总数为 null |
| processed_ranges / missing_ranges | 已处理和未处理单位的闭区间；范围从 1 开始，排序且不重叠 |
| state | complete、incomplete 或 unknown，说明请求范围的处理情况 |
| warnings | 未识别内容、空文字页、定位限制与需核对的块 |

覆盖完整只表示请求单位已实际处理，不证明每个公式都正确。原生解析的输入页数、发送范围与输出映射尽量通过文件清单和原图独立核对；只收到模型自报“已读全部”不能将 unknown 改成 complete。无法证明范围已处理时进入 needs_review。

提交成功 MaterialIR 前检查：所有输入范围已处理；所有 block 和 asset 引用有效；块顺序与来源映射一致；关键题设、公式和图示没有未解决歧义。允许存在已说明的非关键限制和 unverified 内容，但不能把未解决的关键缺失包装成成功。用户通过 diagnostic_asset_ids 查看覆盖记录和候选材料，修正后创建新任务。

后台处理与可查询状态参考 [Open WebUI 的上传处理入口](https://github.com/open-webui/open-webui/blob/33c1978d5bad52a31df75ea55143025dfad18d16/backend/open_webui/routers/files.py#L404-L452)。ManimAgent 将处理状态放在 Job，不让同一原件的多次解析争用一个可变的“文件已解析”状态。

### 故障与重试

| 情况 | 结果与动作 |
|---|---|
| 输入不满足当前解析器格式、范围或已知能力 | 接受前按请求或依赖错误返回；执行中发现则写入 Job.error |
| 模型鉴权、配额、限流、超时 | 沿用 LLM 分类与共同预算；不统一触发本地解析回退 |
| auto 路径确认文件能力不支持 | 保留失败尝试，改走满足本次要求的应用解析器 |
| 原件损坏或加密且无法处理，必要条件缺失 | needs_input，返回用户可执行的补充动作 |
| 关键公式、图示或覆盖无法确认 | needs_review，保存候选块、原图和覆盖记录 |
| 中断、存储失败或预算耗尽 | interrupted 或 failed；原件保留，不发布半份成功材料 |
| 远端临时文件清理失败 | 单独记录并允许维护重试，不撤销已保存材料 |

解析阶段内的有限修复创建独立尝试，共用阶段预算；终态后的重试提交新 Job。恢复能力实现前，重启后未完成任务标为 interrupted。每个阶段结束都明确哪些资产已经发布、哪些只是临时数据。

### 复用与生命周期

原件、派生资产和 MaterialIR 分别保存。修改解析配置、选择范围或解析器时新建 material_id；改变问题只复用已有材料。首版通过结果 ID 显式复用，不承诺自动缓存或请求幂等。

后续解析缓存键至少包含文件摘要、输入顺序与范围、契约版本、解析器与配置版本、实际处理路径；原生解析还包含相关模型绑定与适配器版本。查缓存前执行访问检查；不能因不同用户上传相同摘要而直接共享材料。

依赖原件的 MaterialIR 和 Answer 继续有效期间，原件与引用的派生资产持续可读。删除和跨用户共享接口另行设计，先维护引用关系与临时资产清理；远端临时引用按独立生命周期回收。

### 工作区和按需读取的扩展边界

[OpenHands 将普通附件上传到工作区](https://github.com/OpenHands/OpenHands/blob/72886b6ea5bff39e795cc3b79bc2f444cb9669d6/src/api/conversation-file-upload.api.ts#L70-L175)，并在 [用户消息中列出成功文件名](https://github.com/OpenHands/OpenHands/blob/72886b6ea5bff39e795cc3b79bc2f444cb9669d6/src/utils/send-message-with-attachments.ts#L38-L85)；这类文件需要运行环境和工具取得内容。ManimAgent 首版先完成统一材料解析，通用 shell 与代码工作区不作为上传前置依赖。

后续可提供受控的材料块读取、搜索和原图查看工具，输入使用 material_id、block_id 或 asset_id，受当前请求材料范围和预算约束。分页读取参考 [Deep Agents 的 BackendProtocol](https://github.com/langchain-ai/deepagents/blob/98773a73843421f85a2113e6c3b0262f53d9bcd6/libs/deepagents/deepagents/backends/protocol.py#L454-L507)，路径隔离参考 [Talon 的附件暂存](https://github.com/langchain-ai/deepagents/blob/98773a73843421f85a2113e6c3b0262f53d9bcd6/libs/talon/deepagents_talon/attachments.py#L31-L115)。这些是扩展依据，首版接口仍明确拒绝尚未实现的工具要求。

## 5 当前状态与待办

当前代码没有独立 FileAsset、MaterialIR、解析器注册表或上传端点。以下是待实施工作，整体顺序与 [开发计划](开发计划.md) 协调。

| 阶段 | 交付 | 完成条件 |
|---|---|---|
| 1 | 契约、FileStore 与纯文本解析 | 无模型和 Docker 时可上传、读取原件元信息，并生成纯文本 MaterialIR |
| 2 | PDF、DOCX 解析器与覆盖记录 | 页码、阅读顺序、表格及不支持内容有明确结果，关键缺失不发布成功材料 |
| 3 | 与独立回答及 v2 页面联通 | 只解析、只回答、换问题复用材料及独立重试均可执行 |
| 4 | 图示与公式识别、原生解析适配 | 按格式与提供商分别验证，保留原图、能力证据与共同预算 |
| 5 | 长材料检索和受控读取 | 来源、读取范围、依赖补齐与超预算行为通过独立验收 |

验收样例与判定：

| 样例 | 必须满足 |
|---|---|
| 无模型或 Docker | 上传和文本规范化可用，不触发动画引擎依赖检查 |
| 同名多文件、混合文本与文件 | input_index、file_id、块顺序及引用对应正确 |
| 上传超限、断开连接、存储失败 | 不返回伪成功资产，临时数据可清理，原有资产不受影响 |
| PDF 的负号、矩阵、上下标和跨页定义 | 可对照原件核验；无法可靠识别的关键内容进入待核对 |
| 扫描页、空文字页和混合 PDF | 不因其他页有文字就忽略无文字页；按实际情况标记缺失或已处理 |
| DOCX 的段落、表格、内嵌图片和公式对象 | 阅读顺序正确；无法处理对象有警告，不补造 Word 页码 |
| 页码范围与原生输入 | 实际发送范围可核对，派生页码映射回原件；模型自报位置不自动 verified |
| 文件能力不支持与鉴权、配额失败 | 只有已识别的能力问题触发 auto 回退，其余按各自分类处理 |
| 超时、结构错误、预算耗尽和服务重启 | 尝试共用预算，保留诊断，未完成结果不可用于回答 |
| 重复提问、换解析器、远端引用过期 | 已有材料可复用，新解析产生新 ID，远端失效不丢失本系统原件 |
