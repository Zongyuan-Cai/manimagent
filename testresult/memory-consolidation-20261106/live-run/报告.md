# 首次真实验收：验收器响应转发失败

2026-11-06，合成数学任务，实际发生 **1 次 MiMo writer HTTP 调用**。本轮在首个失败后停止，未执行第 2、3 轮，未调用 checker、后台提取、视频或 TTS。

请求固定为“请讲解 x=1 时 x+x 的值。我希望以后讲解时每一步都说明依据。”，模型 `mimo-v2.6-flash`，官方 `/v1/chat/completions`，`api-key` 鉴权、关闭 thinking、输出上限 2048、模型等待上限 20 秒。密钥只从指定本机 `.env` 读取到内存，并通过临时环境变量交给 credentials resolver；未修改既有设置，退出已恢复环境变量。

## 观察与原因

MiMo 返回 **HTTP 200**、`finish_reason=stop`，提供完整文字响应；服务商报告输入 **681**、输出 **665** token，其中缓存输入 **256**。HTTP 调用观测耗时约 **17.953 秒**，整轮约 **18.359 秒**。完整请求与响应正文保存在 [calls.json](calls.json)，未记录请求鉴权头。

失败发生在验收器：`aread()` 已将传输压缩解码为正文，随后脚本仍保留 `Content-Encoding` 等传输头重建 `httpx.Response`，触发第二次解码的 `DecodingError`。应用将 HTTPX 异常统一标记为 `provider_timeout`，因此该错误码**不能用于证明本次 MiMo 实际超时**，更不能用作后台沉淀质量失败的证据。

主任务没有发布 Answer，状态为 `failed`；关联后台任务为 `cancelled`、`attempts=0`。主任务记录 `model_calls=1`、`tokens_reported=false`、token 计数 0，因为响应没成功交还应用；服务商返回的实际用量仍如上所示，不能据应用中的 0 计数认定没有费用。
