## 审查与修改

| 发现 | 修改 | 保持的行为 |
|---|---|---|
| 三个文件仅承担单个薄封装，定位逻辑需要额外跳转 | `api/materials.py` 的支持范围路由并入 `api/resources.py`；`materials/text.py` 的简单文本读取并入 `materials/parsers.py`；`llm/context.py` 的上下文组装并入 `memory/projection.py` | 路由地址、文本来源信息、按角色投影及提示词顺序不变 |
| 材料错误反复包装、视觉预算重复预检 | 统一每个附件的 `ContentError` 注释；视觉调用预算由 `read_visual` 统一检查 | 文件名、输入序号、重试属性保留；当前批次预算不足时，在首次视觉调用前失败，并保留回答所需预算 |
| 执行阶段在旧记录缺失快照时读取当前记忆，会混淆历史 | 删除 `prepare_memory` 及其调用 | 新任务在接收时冻结；视频继承 Answer 快照；旧任务缺失的信息保持未知 |
| 学习用量已经是内部 `Usage`，仍先转字典再兼容任意类型；文件同步缓存了无人读取的状态 | `finish` 直接接收 `Usage`，错误输入限定为现有字典契约；删除 `last_status` 与相应转发 | 外部供应商用量仍先归一化；旧尝试记录累加、错误白名单及文件同步错误返回不变 |
| 回答上下文加入 instruction 后，调用方又复制字典删除；视频规划有纯转发函数与重复初始化 | 材料上下文只负责材料，当前要求由提示词组装处添加；直接调用规划函数并只初始化一次状态 | 正文要求、材料顺序、分块与规划预算不变 |
| 前端遗留了旧面板转发、重复按钮锁定、重复编辑状态和无用 CSS | 删除无效 `.open` 转发、测试专用回调和无调用的 DOM 工具；编辑状态合并为一个 Map；移除旧 CSS 选择器 | 多条目草稿隔离、请求归属、修订锁与迟到响应保护保留；完成后的刷新异常记录到控制台，不改变已完成结果 |

内部必填字段改用直接访问，删除只为不完整测试替身存在的防御分支，测试替身按真实调用方式构造。外部输入校验、文件／网络错误、事务版本检查、取消围栏、进程隔离和 worker 终态处理仍保留。

没有继续合并共享的容器校验、材料块约束、后台沉淀、文件导入、注入审计或前端独立视图。这些模块有实际共享调用或不同状态生命周期；本轮不以单纯减少文件数为目标。
